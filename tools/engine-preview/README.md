# horde ENGINE PREVIEW

A throwaway plug-in that lets the human play the clean-room engine in Live (B624, ADR-366). It tests sound and CPU, and since B628 it also carries GUI 3 on the engine. It isn't the horde 2 shell (B398), it plays no part in the cutover decision, and it's deleted when that shell exists. Its bridge is planned as that shell's first slice (`docs/proposals/gui-on-engine.md`).

**What it has:** all 83 bank presets, levelled as the rendered previews are, with their blade-envelope routes played. **Every engine row is a host parameter** (B632, ADR-370): the 317 non-reserved rows plus Preset, 318 in all, each under the engine's own id and key, so every setting automates in Live. Above 64 parameters Live's panel opens empty and fills as controls in the plug-in's window are touched: a touch on the page reaches the host as one gesture (begin, value, end). **Polyphony is the one voice control** (the human, 2026-11-05: "One control: Polyphony"): the engine's own `voice.polyphony`, set from the page or the fallback window, with no separate Voices limit. **The plug-in's own safety rule:** a preset that loads asking for more than 8 voices, by the page, the host's Preset, a saved state or as the default, plays 8, set through the engine's Param path before the load completes, so the page shows 8. On engine `1ad270a` every bank preset asks for 16. A polyphony set by hand, at any value, stands, and a saved state keeps it.

**Its window is GUI 3's page** (B628), in a fixed 980 × 720 web view, talking to the engine through the bridge the plan's section 3 signs: the page sends `hordeNativeSend(JSON)`, and a 30 fps timer pushes `window.hordeNativeSnapshot(snapshot)`. The page's `hello` and `preset` are LOADs: the bridge answers each with one frame that acknowledges it and carries every engine row, and for a preset only once the new engine is playing, so the page never adopts the old preset's values. Host automation reaches the page as ordinary changed rows. With `want.summed` the page also gets the plug-in's own output for its scope (GN-4): `observe.summed = {rate, samples}`, the newest 2048 samples of (L + R) / 2, every 16th (128 points at 2756.25 per second at 44.1 kHz). The default page is a stand-in (`standin_page.html`): the presets, Polyphony, a few rows by key and one phase picture. `HORDE_PREVIEW_PAGE=<file>` builds another page in, such as the one `tools/gui3_inline.py` writes. `HORDE_PREVIEW_WEBVIEW=OFF` builds the old AppKit window instead (preset menu, Polyphony, every row and a CPU readout), the fallback until the page has been tried in Live.

**Pitch bend and the bank's glide** (B632), a stand-in for the pitch system (RC-3) until B504 rules it: MIDI pitch bend (in CLAP's MIDI dialect, as Live and the wrapper send it) at a fixed ±2 semitones, and each preset's `glide` and `glideAlways` from B.1 played exactly as SPEC-ENGINE 10.3 states them for the phrases: exponential in log frequency, 95 % in the glide time, from the most recently started note, a chord's notes each from the one before. A note's pitch goes to the engine only once it glides or is bent, from its first sample, and while it moves through IF-2's audio-rate input (float32), so a glide costs no extra engine segments. No travel law, quantizer or setting beyond these: they are B504's.

**The morph** (B636; ADR-370, ADR-373, ADR-376, ADR-377). The plug-in hosts the morph system (RC-11.1): four corners (each a full set of the manifest's values and both `ratios` texts), the pad's position, D.2's settings and each key's mode and count. It feeds them to the clean room's own resolver (`make_morph_resolver()`, IF-12), one per engine, prepared beside it so the two clocks run in lockstep (MO-3). On the audio thread the resolver's events reach the engine in the same span, whatever kind it emits: `Param` events, `Ratios` texts (through `set_ratios`, the span cut at the text's sample) and, from today's resolver, `SettingSet`s; `fx/` sets are dropped, as there is no rack. Nothing in the bridge knows which kinds the resolver emits, so the 1.0 resolver of round 61 / ADR-377 is a rebuild, not a rewrite. While the morph moves, spans are cut at each control interval, as for a routed preset; a still morph lets a silent engine be skipped as before.
- **The page's messages** (section 3's names, plus two the bridge adds): `morph {settings: {key: v}}` (D.2's thirteen settings by key, in v), `position {x, y}`, `modes {modes, counts}` (the whole menu: a key it leaves out is Follow at As the morph), `corner {index, values}` (values written into one corner) and `save {index}` (MO-25's Save current sound: what the engine holds now, Device keys excepted, and its texts). Each is acknowledged like any message. `want {morph: true}` adds the snapshot's `morph` member: the position and the refused-edit count every frame; D.2's settings, the modes, each corner's changed rows, the corners' texts, what the engine holds (`heard`) and its texts only when they change; and IF-10's heard setting set of each group for the lowest sounding voice.
- **Morph off is the plug-in as it was.** Corners B to D and the position are frozen; an edit (from the host, the page or the window) lands in the engine and in the audible corner, which is the sound. Turning the morph off, or choosing another audible corner while it is off, hands the sound over to that corner (MO-20), and the host is asked to rescan its values.
- **Morph on: the resolver is the only source of every key it resolves** (IF-12). An edit of such a key (from the host, the page or the window) is refused and counted in `morph.dropped`; Device keys still take edits. IF-12 routes those edits to the corners by ADR-109, but how one splits across the corners isn't in the spec, so this plug-in doesn't guess. Corner edits arrive as `corner` messages.
- **The position's seam.** Round 61 (#1431) makes `morph.x` and `morph.y` D.2 rows and host parameters; until it merges the position comes only from the page's `position` message. Every position goes through `set_position()` in `preview_plugin.cpp`, where their host events will call it.
- **No morph host parameters yet.** IF-11 appends the morph's host parameters from a morph manifest in the lockfile, and none is committed, so D.2's rows are transcribed from the spec in `morph_core.cpp` and reach the resolver only through the page.
- **A preset load puts the preset into all four corners**, as GUI 3's page does on a load; the settings, modes and position stay.

**What it lacks, because the engine lacks it:** filters, effects and the modulation matrix. Changing preset builds a new engine, which cuts off anything sounding. **No standalone app:** clap-wrapper's standalone format needs RtAudio and RtMidi, which it downloads, and neither is in this repo, so it would add two dependencies (a human gate).

**Every build is labelled** with the engine commit and a build number that only counts up. The label shows in the page (the snapshot's `plugin.build`), in the plug-in's description and in the log's first line, so a test build in Live is never a guess.

**What it saves:** the preset and every engine row that differs from what that preset loads ("current settings only", the human's ruling). A chunk holding only a preset's own values is about 30 bytes. Since B636 the morph saves with it, each piece only where it differs from what a load rebuilds by itself: D.2's settings that aren't their defaults, the position when it isn't corner A, each corner's rows and texts that differ from the preset's (not the audible corner while the morph is off: it is the sound, which the rows hold), and each key's mode and count that isn't the default. That is version 3 of the chunk; a patch that never touched the morph still writes version 2, byte for byte. A four-corner patch with three keys apart per corner is about 0.5 KB; 40 keys apart in each of four corners about 6 KB. Older chunks still load (the morph at its defaults), and a `voices` line in them is ignored.

**Silence costs next to nothing.** While the engine reports itself silent (OU-4) and no event or edit arrives, the shell skips it. On 1ad270a a silent `process()` cost 7 to 13 % of a core per instance; `skip()` costs about 0.1 to 0.4 %.

**Its session log.** Each instance writes `~/Library/Logs/horde-engine-preview/session-*.tsv`: for every preset played, the blocks that had sound, their mean and worst share of the block's time, and how many overran. Idle blocks don't count, so the figures say what a note costs. These figures are from a real session, not PF-3, and they don't replace it.

## Build

```bash
HORDE_LIBS_DIR=<a full checkout>/libs HORDE_SDK_CACHE=<a full checkout>/build-release/_deps tools/engine-preview/build.sh <engine commit> --install
```

The engine comes from `git archive` of the named commit, never the builder's working tree. Everything builds outside the repo. `--install` copies the VST3, AU and CLAP into `~/Library/Audio/Plug-Ins` and runs `auval`. Run it outside Claude Code's sandbox, or the install lands in an overlay Live can't see.

## The oracles

None is in `./verify`, because the engine isn't in this repo or in CI (B568). `build.sh` runs them all, and each has a control that must fail.

- `bridge_test.cpp`: the bridge's pure half (`bridge_core.h`, `morph_core.h`), headless. The morph's messages parse to what the morph system acts on (a key D.2 lacks, a mode the menu lacks and a reserved row are each reported); D.2's defaults as v are the page's and decode to D.2's units; the morph member carries a changed corner in its place and a heard set's settings; a chunk with no morph is version 2 byte for byte, and a version-3 chunk round-trips the corners, position, settings, texts and modes exactly (a chunk missing a corner line reads back without it). Every message type is acknowledged; a key the manifest lacks is reported and never sent; rack and midi keys and gestures never become Params; the manifest hash matches a value Python computed, and one changed row reads as a mismatch; a frame carries members only when `want` asks; the saved state round-trips and stays small; the polyphony cap takes 16 to 8 and leaves 8 or fewer alone.
- `smoke.cpp`: drives the built CLAP through its own interface and holds the output against the engine's own `horde_offline_render`, bit for bit, on five presets at blocks of 128 and at uneven blocks; that render shares no code with this shell, and its phrase carries the chord's glide, written in the test from item 15b's generator. A full pitch bend reaches a note's pitch input at +2 semitones exactly (a plant that drops bends must fail); a note glides by 10.3's law sample for sample from the most recently started note, and a chord glides note by note (a linear law and a glide from the wrong note must read as different). Every host parameter set by a host event reads back in the engine, the host and the frame (an event sent to the next id must fail). The scope's window equals the output the host received (a frozen tap and a tap of silence must fail). Through the bridge's extension (`bridge_ext.h`), a `set` on a row the host never sees reaches the engine and its seq comes back as `ack`; `hello` and `preset` are answered only in the frame that completes them, with every row (a preset only after the engine swap); a frame during silence claims no sound, and one during a chord does. A preset above 8 voices loads at 8; a held 12-note chord at polyphony 12 sounds 12 voices (the plant with the old Voices limit of 4 sounds 4). The mapping audit sets every engine row through the bridge and reads its exact v back from the engine and the next frame (a plant with the key map one row off must fail it). The morph (B636): with the morph off and corners B to D edited and the pad at D, the output is corner A's as plain edits, bit for bit (the morph on at D must differ); at each exact corner, under Quantum and under Blend, the output is that corner played with the morph off, bit for bit (A's render must differ from B's); under Blend a Morphable key holds MO-9's blend at the pad's weights (the transposed position's blend must differ, and a plant that drops position messages must stay at corner A); mid-pad under Blend the frame's heard sets show osc 1's kernel sounding several settings (one at an exact corner); each morph message is acknowledged only after a block and comes back in the frame; while the morph is on an edit of a key it resolves is refused and counted (a Device key still applies); Save current sound writes what the engine holds into its corner; morph off hands over to the audible corner; and the state round-trips a four-corner patch through another preset (a plant whose chunk forgets the morph must not). It also reports, never gates, what a still morph costs against morph off.
- `gui_shot.mm`: opens the plug-in's real window as a host does. For the page, it sends from inside the page as GUI 3 does and checks the host and the page both hear of it, a touch as one gesture, and the morph's messages acknowledged with the engine's new value heard back in the page; for the AppKit window, it moves real controls. It saves a picture.
- `frames_dump.cpp`: records the frames GUI 3's `ReplayTransport` plays, to `tools/labharness/fixtures/gui3-replay.json`, with `gui3-display.json` beside it (the engine's x, unit and option name for five values of every row). `build.sh` holds a fresh dump against the committed pair, byte for byte. **Re-recording them is a human gate.**

Last verified 2026-11-06 against engine `4f4afd4` (B636; the morph needs its resolver, which `1ad270a` lacks): bridge test, smoke and window GREEN with the stand-in page and with GUI 3's page from main. The committed recorded frames are from `1ad270a`, so `build.sh` only writes fresh ones; on `4f4afd4` they are byte-identical to the ones main's own build dumps, so the morph changes no frame the page records.
