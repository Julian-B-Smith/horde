# horde ENGINE PREVIEW

A throwaway plug-in that lets the human play the clean-room engine in Live (B624, ADR-366). It tests sound and CPU, and since B628 it also carries GUI 3 on the engine. It isn't the horde 2 shell (B398), it plays no part in the cutover decision, and it's deleted when that shell exists. Its bridge is planned as that shell's first slice (`docs/proposals/gui-on-engine.md`).

**What it has:** all 83 bank presets, levelled as the rendered previews are, with their blade-envelope routes played. **Every engine row is a host parameter** (B632, ADR-370): the 317 non-reserved rows plus Preset, 318 in all, each under the engine's own id and key, so every setting automates in Live. Above 64 parameters Live's panel opens empty and fills as controls in the plug-in's window are touched: a touch on the page reaches the host as one gesture (begin, value, end). **Polyphony is the one voice control** (the human, 2026-11-05: "One control: Polyphony"): the engine's own `voice.polyphony`, set from the page or the fallback window, with no separate Voices limit. **The plug-in's own safety rule:** a preset that loads asking for more than 8 voices, by the page, the host's Preset, a saved state or as the default, plays 8, set through the engine's Param path before the load completes, so the page shows 8. On engine `1ad270a` every bank preset asks for 16. A polyphony set by hand, at any value, stands, and a saved state keeps it.

**Its window is GUI 3's page** (B628), in a fixed 980 × 720 web view, talking to the engine through the bridge the plan's section 3 signs: the page sends `hordeNativeSend(JSON)`, and a 30 fps timer pushes `window.hordeNativeSnapshot(snapshot)`. The page's `hello` and `preset` are LOADs: the bridge answers each with one frame that acknowledges it and carries every engine row, and for a preset only once the new engine is playing, so the page never adopts the old preset's values. Host automation reaches the page as ordinary changed rows. With `want.summed` the page also gets the plug-in's own output for its scope (GN-4): `observe.summed = {rate, samples}`, the newest 2048 samples of (L + R) / 2, every 16th (128 points at 2756.25 per second at 44.1 kHz). The default page is a stand-in (`standin_page.html`): the presets, Polyphony, a few rows by key and one phase picture. `HORDE_PREVIEW_PAGE=<file>` builds another page in, such as the one `tools/gui3_inline.py` writes. `HORDE_PREVIEW_WEBVIEW=OFF` builds the old AppKit window instead (preset menu, Polyphony, every row and a CPU readout), the fallback until the page has been tried in Live.

**Pitch bend and the bank's glide** (B632), a stand-in for the pitch system (RC-3) until B504 rules it: MIDI pitch bend (in CLAP's MIDI dialect, as Live and the wrapper send it) at a fixed ±2 semitones, and each preset's `glide` and `glideAlways` from B.1 played exactly as SPEC-ENGINE 10.3 states them for the phrases: exponential in log frequency, 95 % in the glide time, from the most recently started note, a chord's notes each from the one before. A note's pitch goes to the engine only once it glides or is bent, from its first sample, and while it moves through IF-2's audio-rate input (float32), so a glide costs no extra engine segments. No travel law, quantizer or setting beyond these: they are B504's.

**The morph** (B636, B639 on round 61's 1.0 resolver; ADR-370, ADR-373, ADR-376, ADR-377). The plug-in hosts the morph system (RC-11.1): four corners (each a full set of the manifest's values and both `ratios` texts), the pad's position, D.2's settings, each key's mode and count, each key's waypoints with the patch's waypoint law and clamp (MO-21), and each key's region lock (MO-24). It feeds them to the clean room's own resolver (`make_morph_resolver()`, IF-12), one per engine, prepared beside it so the two clocks run in lockstep (MO-3). On the audio thread the resolver's events reach the engine in the same span, whatever kind it emits: `Param` events (a landing passed on in `Event::landing`, MO-26 (4)), MO-26's source levels as `EventType::MorphLevel`, `Ratios` texts (through `set_ratios`, the span cut at the text's sample) and `SettingSet`s, which a 1.0 resolver no longer sends (ADR-377); `fx/` sets are dropped, as there is no rack, and a kind this build doesn't know is counted in `morph.unknown`. While the morph moves, spans are cut at each control interval, as for a routed preset; a still morph lets a silent engine be skipped as before.
- **The page's messages** (section 3's names, plus the bridge's own): `morph {settings: {key: v}}` (D.2's thirteen settings by key, in v), `position {x, y}`, `modes {modes, counts}` (the whole menu: a key it leaves out is Follow at As the morph), `corner {index, values}` (values written into one corner), `save {index}` (MO-25's Save current sound) and, since B639, MO-21 and MO-24's three (below). Each is acknowledged like any message. `want {morph: true}` adds the snapshot's `morph` member: every frame, the position, the refused-edit count (`dropped`), the unknown-event count, each source's heard morph level (`levels: [osc1, osc2, sub, noise]`, IF-10's, so the page can draw fades) and the resolver's counters (`counters: {refusedWaypoints, refusedLocks, droppedInputs, droppedEvents}`); only when they change, D.2's settings, the modes, the waypoints, the law and the locks (whole), each corner's changed rows, the corners' texts, and what the engine holds (`heard`) and its texts; and IF-10's heard setting sets, empty under a 1.0 resolver.
- **MO-21 and MO-24's messages** (B639; page choices, never host parameters). The bridge forwards each to the resolver, which judges it and counts what it refuses (`morph.counters`); the morph state keeps what was sent, and the state saves it.
  - `waypoints {seq, key, points: [{x, y, v}, ...]}`: one Morphable key's whole list, in stored order, replacing its previous list; `points: []` clears it. Positions and values are in [0, 1] (the resolver clamps them). MO-21 refuses a list whole when it has more than 8 points, a point nearer than 0.04 to a corner or another point, a key that can't hold waypoints (a circular, Structural or Device key, a ratios text), or would bring the patch above 64; then nothing changes and `refusedWaypoints` counts it. A point missing x, y or v, or not a finite number, makes the message unreadable: it is acknowledged, named in `refused.types`, and nothing acts.
  - `waypointLaw {seq, law: "tps" | "tin", clamp: true | false}`: the patch's waypoint law (TPS·Δ by default) and its Clamp to set values (on by default).
  - `lock {seq, key, offsets: [dB, dC, dD] | null}`: a key's region lock, its three offsets (d[A] is 0), or `null` for none. A non-finite offset or one past 1e6 in magnitude is refused and counted in `refusedLocks`. A lock "as is" takes the offsets IF-12's `lock_as_is` gives; the bridge has no message for that read yet.
  - Keys are named as in `modes`, `osc1.ratios` and `osc2.ratios` included.
- **Morph off is the plug-in as it was.** Corners B to D and the position are frozen; an edit (from the host, the page or the window) lands in the engine and in the audible corner, which is the sound. Turning the morph off, or choosing another audible corner while it is off, hands the sound over to that corner (MO-20), and the host is asked to rescan its values.
- **Morph on: the resolver is the only source of every key it resolves** (IF-12). An edit of such a key (from the host, the page or the window) is refused and counted in `morph.dropped`; Device keys still take edits. IF-12 routes those edits to the corners by ADR-109, but how one splits across the corners isn't in the spec, so this plug-in doesn't guess. Corner edits arrive as `corner` messages.
- **The position is two host parameters** (B639, IF-11): `morph.x` and `morph.y` (round 61's D.2 rows: 0 to 1, lin, default 0), the last two parameters, after every engine row. Host automation moves the pad, and the page's `position` message sets both as a touch: each reaches the host as begin, value, end, unless the page holds a gesture open. Every position goes through `set_position()` in `preview_plugin.cpp`, at its event's sample.
- **No other morph host parameters.** IF-11 lists twelve morph host parameters (the position's two, and on, law, count, temperature, cohesion, step rate, sync, division, triplet, dotted and glide; never seed or audible), from a morph manifest committed as a lockfile with explicit ids. None is committed, so only the position's two are host parameters here, under the plug-in's own ids (0xA00001, 0xA00002), and D.2's other rows are transcribed from the spec in `morph_core.cpp` and reach the resolver only through the page.
- **Save current sound** (MO-25) uses the resolver's own reads: each key's `resolved_value`, each oscillator's `resolved_ratios`, and for a source fading the `level_sent` g, baked into its level key (`mix.osc1` and the like) as the v whose dB gain is the heard gain times g, or, below the law's −60 dB, the source stored off with its level key at the heard gain (ADR-377 A2).
- **A preset load puts the preset into all four corners**, as GUI 3's page does on a load; the settings, modes and position stay.
- **The demo bank** (B645): after the 83 factory presets, a small section named `Demo (morph): …`, each a four-corner patch that uses what the engine exposes today (both oscillators, both blades, the sub, the noise and its stages, the four envelopes, the voice). The data is one committed file, `demo_bank.json` (its rules in `demo_bank.h`): per preset a base (a factory preset or the engine's defaults), the rows every corner shares and each corner's own, in each row's unit, D.2's settings, any key's mode and B.1's blade-envelope routes (ENV 2 or 3 to a blade's cut, cutHz or width), which the plug-in plays as it plays the factory bank's. `gen_bank` turns each corner into the engine's own state text and embeds it after the factory bank, whose entries it writes exactly as before. **Loading a demo** (from the page, the host's Preset or a state) puts its four corners into the morph, sets D.2's settings to the demo's (the morph on, every setting it doesn't name at D.2's default), its keys' modes, and clears waypoints and locks; the position stays. Corner A is the preset's own state, so a saved chunk stores corners B to D as differences, as for any four-corner patch (a demo's chunk is a few KB). A factory preset loaded after a demo leaves the demo's settings and modes, like any load; its four equal corners make them inaudible. Before modulation and the FX: no waypoints, and the routes are B.1's stand-in. Pass 2 (the human's first listen): away from the supersaw, many Morphable rows travelling together between corners. Each demo's corners are levelled by measurement to the factory bank's median loudness with a peak of at most −1 dBFS (`demo_render`, below).

**What it lacks, because the engine lacks it:** the modulation matrix, and effects of its own (its FX are the rack's, below). Changing preset builds a new engine, which cuts off anything sounding. **No standalone app:** clap-wrapper's standalone format needs RtAudio and RtMidi, which it downloads, and neither is in this repo, so it would add two dependencies (a human gate).

**The rack** (B714, ADR-410 r4, ADR-411, ADR-412): the generic module slot, `tools/rack`, after the engine's output. Every module `tools/rack/modules.json` hands the default build (today Weir's SVF 12 filter as fx/1, Scape's reverb as fx/2) sits on one serial chain, engine → fx/1 → fx/2 → out. Nothing in `preview_plugin.cpp` or `bridge_core.*` names a module (`tools/module_neutral_check.py` holds them to it): a module is hosted from its pin, its manifest, its state-budget row, horde's interim law and mod overlay (`tools/rack/law/`, until FOUNDATIONS names the fields) and an adapter (`tools/admission/*_adapter.cpp`). The test configuration (`preview-testmods`) adds a do-nothing module by data alone, with no change to either file.
- **Host parameters:** each slot's switch and keys, after the morph's two, in ascending id order, from the ledger `host_ids.lock.json` (append-only, `tools/host_id_ledger_check.py`). The pre-B714 numbers stand: Weir's on at `0xA00010` and its mode, cutoff, resonance, Ring and mix at `0xA00011-15`; Scape's on at `0xA00016` and Scape's manifest id k at `0xA00017` + k; new keys from `0xA00036` (Weir's slot-supplied I/O gains took `0xA00034-35`). A key's host value is its v by its law (a stepped key's option index), as an engine row's (ADR-412 r2): Weir's ids keep the form they had, and Scape's continuous ids changed from Scape's own units to v. A flip key with fewer than two values (Weir's type) is a constant, never a parameter.
- **Off is a true bypass:** a slot switched off touches nothing, not its module and not its I/O gains, so every preset is bit-identical to the build with no rack module at all (`preview-plant-norack`), before and after each slot has run.
- **I/O gains:** a module that declares `io.inGain` and `io.outGain` (Scape) owns them; for any other (Weir) the slot supplies the pair, ±24 dB, gliding 20 ms (RS-4.6, RS-4.7).
- **Switching on** sends every value, then resets the module: it starts cleared, nothing ramps in. While on, the module's own smoothing is the only smoothing.
- **Idle:** with zeros in, a slot runs while the time since its input last sounded is under its DECLARED tail (re-queried each block), then it is skipped, its output exact zero; the same rule on the idle engine's skip and while the engine sounds. Any slot that ran on the idle path makes the block guarded and metered (before B714 only the reverb did). Weir's tail (horde-interim, `weir_adapter.cpp`): unbounded while its state holds anything, 0 once Weir's own flush has made it exactly zero (before B714 the shell stopped it at a level of 1e-7).
- **Memory:** every module's buffers are allocated at activation, on or off (Scape's own figure, 12 to 27 MiB per instance).
- **Saved** in a version 7 chunk's `fx` section (`tools/rack/chunk.h`: per slot its manifest's sha256, per corner its switch and each key apart from its default in the module's units at %.17g, Device keys once outside the corners, then an empty `prefs` section reserved for the device preferences), written only when some slot isn't at the dry state, so every other chunk is what it was. **Old chunks:** version 5's filter line and version 6's Scape lines migrate into `fx` through the ledger's frozen legacy table; versions 1 to 4 load dry; anything else is refused LOUDLY (the host hears false, the session log says why, and the frame's `load` member carries the reason). A chunk with one module on plays bit-identically to main's build before B714 (`fixtures/migration-goldens.json`); with both on, the pre-B714 chain rounded to float between the two modules and the rack keeps double, a measured difference (max 1.97e-07).
- **FX still persist across a preset change** in this stage: S2 (patches carry FX) flips it.
- **Pinned:** each tree at its `.pin`'s commit with its clean paths clean (`weir.pin`, `scape.pin`; the variables modules.json names, `HORDE_WEIR_DIR` and `HORDE_SCAPE_DIR`, default to the checkouts in `~/Documents/Claude/synthetic-worlds`), and FOUNDATIONS by tree (`foundations.pin`, `HORDE_FOUNDATIONS_DIR`), every module's vendored `fx_operator.h` byte-identical to it; the configure stops otherwise. Scape's `core/` is built by its own CMakeLists, so `scape_core` keeps Scape's `-ffp-contract=fast`. Moving a pin is a re-test, `tools/admission_check.py` first.

**The rack's keys on the bridge** (B711, B714). The page reaches every slot key as it reaches an engine row, by key, and they stay out of the manifest and its hash:
- **`hello.slots`** describes each slot: `{ledger, refused, slots: [{slot, module, name, pin, version, budget: {bytes, status}, owns_io, usable, fixed: [{label, key}], on: {key, id}, keys: [{key, id, name, cls, law, mod, min, max, default, stepped, labels?, unit}]}]}`, keys by SPEC-ENGINE MO-28's names (`fx/1/fxfilter.cutoff`, `fx/2.on`), min, max and default in the module's units. A page's v for a key is its place by its law.
- **`hello.preview`** carries the pre-B714 keys (`preview.filter.*`, `preview.scape.*`), generated from the ledger's alias table, in the form each was published in, so GUI 3's page reads them unchanged until it moves to `hello.slots` (S6 retires them).
- **`set` and `gesture`** take either name and reach the host parameter as begin, value, end (or only the values inside a page gesture); **`params`** reports each by key in v; an unknown `fx/` or `preview.` key is refused in `refused.unknown`.
- **`observe.meters.slots`**: `[{slot, in: {peak, clip}, out: {peak, clip}, nonfinite}]`, each running slot's peaks since the last frame and its guard's count of zeroed non-finite samples.
- **In Live:** unreachable until the page draws them (Configure learns a parameter only from a touch in the plug-in's window).

**Every build is labelled** with the engine commit and a build number that only counts up. The label shows in the page (the snapshot's `plugin.build`), in the plug-in's description and in the log's first line, so a test build in Live is never a guess.

**What it saves:** the preset and every engine row that differs from what that preset loads ("current settings only", the human's ruling). A chunk holding only a preset's own values is about 30 bytes. Since B636 the morph saves with it, each piece only where it differs from what a load rebuilds by itself: D.2's settings that aren't their defaults, the position when it isn't corner A, each corner's rows and texts that differ from the preset's (not the audible corner while the morph is off: it is the sound, which the rows hold), and each key's mode and count that isn't the default. Since B639 the morph's lines also hold each key's waypoints, the waypoint law and clamp when not the defaults, and each key's lock (about 100 bytes for a waypoint, the law and a lock). That is version 4 of the chunk; a patch that never touched the morph still writes version 2, byte for byte, and version 3 chunks load with no waypoints or locks. A four-corner patch with three keys apart per corner is about 0.5 KB; 40 keys apart in each of four corners about 6 KB. Older chunks still load (the morph at its defaults), and a `voices` line in them is ignored.

**Silence costs next to nothing.** While the engine reports itself silent (OU-4) and no event or edit arrives, the shell skips it. On 1ad270a a silent `process()` cost 7 to 13 % of a core per instance; `skip()` costs about 0.1 to 0.4 %.

**Its session log.** Each instance writes `~/Library/Logs/horde-engine-preview/session-*.tsv`: for every preset played, the blocks that had sound, their mean and worst share of the block's time, and how many overran. Idle blocks don't count, so the figures say what a note costs. Since B642 each overrun also gets its own line after those totals: when it fell (seconds of audio since the plug-in was activated), the preset, the block size, its share of the block's time, the morph's state (`off`, `still`, or `moving` when the resolver sent the engine something during the block) and both oscillators' unison counts as the engine held them. The audio thread writes each into a preallocated ring of 1024; the main thread moves them into the log every time it rewrites it (about every 2 s, and at deactivate). A session keeps 4096 lines, and the header line counts any more, and any lost to a full ring. These figures are from a real session, not PF-3, and they don't replace it.

**Measuring the demo bank** (B645): `demo_render.cpp` (`preview-demo-render <presets.json> <demo_bank.json> <out dir> [--only <name>] [--target <LUFS>] [--runs <n>]`), built on demand, never by `build.sh` or `./verify`. It reads `demo_bank.json` through the same reader as `gen_bank` and renders each demo through a fresh engine and the clean room's resolver, driven as the plug-in drives them (corner A loaded, the corners, settings and modes at sample 0, spans cut at every control interval, a silent quarter second before the first note): each corner on its own and a 16 s sweep of the pad A → B → D → C → A, with the chord 60 64 67 71 held 3 s (struck again every `render.retrigger` seconds for a pluck or a hit), and a single note for a lead or a bass. It writes 16-bit WAVs and `metrics.json`, and prints a line per demo flagging silence while notes are held, a peak above −1 dBFS, non-finite samples, DC above 0.01, a worst block above 70 % of a 512-sample block, a unison above 9, corners whose colours sit less than 2 dB apart (third-octave levels), and a corner of a preset not marked `render.bass` holding more than 5 % of its power below 150 Hz. It also reports each preset's supersaw-ness ((members − 1) × detune × the detune range's factor, per sounding oscillator) and how many Morphable and Structural rows differ between its corners, and plays a demo's routes as the plug-in does. CPU is thread time per block, the least of `--runs` runs of the same block (3 by default), which must also render identical audio. `--target` adds each corner's out.level move to that loudness (BS.1770, ungated, as OU-2), capped at a −1 dBFS peak.

**Diagnosing drop-outs** (B642). Two programs, built on demand (`cmake --build <build> --target preview-morph-probe preview-morph-hole preview-morph-wholespan`), never by `build.sh` or `./verify`:
- `morph_probe.cpp` (`preview-morph-probe <clap> --law blend|quantum|stepped|off ...`) holds a chord through the plug-in's own CLAP interface while the page's `position` messages move the pad over four corners that differ (a source on in some and off in others, waves, blade modes, unison counts, Morphable values). It times every `process()` call (wall and thread CPU against the block), records what each frame says the engine changed, and reports every drop-out: a 5 ms window more than 30 dB under its neighbours within 200 ms, lasting while it stays there, with the sources on and the blocks around it. Its controls: `--plant-gap` (20 ms zeroed) must read one, `--law off` none. `--pair <clap>` runs a second instance block by block beside the first, in alternating order, and says whether the outputs are bit-identical and what each cost; `preview-morph-wholespan` is the measurement build for it, with the morph's events riding in the host's whole span instead of one span per control interval. Point `HOME` at a scratch folder with a `Library/` in it, or its runs write session logs beside the human's.
- `morph_hole.cpp` (`preview-morph-hole`) is the minimal reproduction of the one silent class found: under Quantum each source's on switch picks its corner by MO-7 on its own (MO-26 (3)), so between a corner that sounds only osc 1 and one that sounds only osc 2 the pad has stretches where both switches pick the corner their source is off in. It drives the clean room's resolver alone, no audio. Its control: Blend over the same sweep must find none.

## Build

```bash
HORDE_LIBS_DIR=<a full checkout>/libs HORDE_SDK_CACHE=<a full checkout>/build-release/_deps tools/engine-preview/build.sh <engine commit> --install
```

Set each module tree's variable (`tools/rack/modules.json`: `HORDE_WEIR_DIR`, `HORDE_SCAPE_DIR`) and `HORDE_FOUNDATIONS_DIR` to clones at their pins when the default checkouts in `~/Documents/Claude/synthetic-worlds` are elsewhere (the configure stops otherwise). The engine comes from `git archive` of the named commit, never the builder's working tree. Everything builds outside the repo. `--install` copies the VST3, AU and CLAP into `~/Library/Audio/Plug-Ins` and runs `auval`. Run it outside Claude Code's sandbox, or the install lands in an overlay Live can't see.

## The oracles

`build.sh` runs them all, and each has a control that must fail. Since B714, `./verify full`'s `tools/rack_check.py` runs the slot library's own tests and plants and a RealtimeSanitizer run of its audio path, and this smoke and bridge test too when `HORDE_PREVIEW_ENGINE` names an engine commit (the engine isn't in this repo or in CI, B568).

- `bridge_test.cpp`: the rack's part of the chunk (B714): a dry rack writes no `fx` and no new version; the `fx` section round-trips its four corners and the reserved `prefs` section exactly, save, load, save byte-identical; version 5 and 6 lines migrate through the ledger's frozen table (a non-finite or out-of-range line is no line; with no table none migrates); an unknown version or magic is refused with its reason, and a known one carries none. The rack's keys: one row per switch and key by MO-28's name and one per ledger alias, each at its own id; an old Scape row is published as it was and reaches the host through its law, an old filter row is the host value itself; `set` and `gesture` reach each key's row and report an unknown one (the control: with no rack keys every such key is unknown); every key reaches its own id (the control: a key map one row off misses every key); the hello reply carries `preview` and `slots`, and one without them is the reply it was. and the bridge's pure half (`bridge_core.h`, `morph_core.h`), headless. The morph's messages parse to what the morph system acts on (a key D.2 lacks, a mode the menu lacks and a reserved row are each reported); D.2's defaults as v are the page's and decode to D.2's units; the morph member carries a changed corner in its place and a heard set's settings; a chunk with no morph is version 2 byte for byte, and a version-4 chunk round-trips the corners, position, settings, texts, modes, waypoints, waypoint law and locks exactly (a chunk missing a corner line reads back without it), and a version-3 chunk loads with none of B639's; `waypoints`, `waypointLaw` and `lock` parse, and an unreadable one (a point without its value, a law MO-21 lacks, two offsets) is caught. Every message type is acknowledged; a key the manifest lacks is reported and never sent; rack and midi keys and gestures never become Params; the manifest hash matches a value Python computed, and one changed row reads as a mismatch; a frame carries members only when `want` asks; the saved state round-trips and stays small; the polyphony cap takes 16 to 8 and leaves 8 or fewer alone. The test rows (B711): one per host parameter of the filter and the reverb, each keyed by its host name at its own id, with its range, default, stepping and a label per option; v reaches the host value by the stated rule, clamped and rounded where stepped; a `set` sends each test key to its own row beside engine rows and reports an unknown `preview.` key (the control: with no test rows every such key is unknown and nothing is sent); a gesture opens the test row's, never an engine row's; every key reaches its own id (the control: a key map one row off misses every key); the hello reply's `preview` is JSON with the rule and a descriptor per row, and a reply without them is the one it was.
- `smoke.cpp`: the rack (B714), generated from each build's own `hello.slots`, on the default build and on the test configuration with its third module: every slot and key published, held to its host parameter; every key, by MO-28's name and by alias, set from the page reaches the host as one gesture and comes back as the page's v (the controls: `preview-plant-map` and `preview-plant-droptest` must fail it); a drag is one gesture; host automation reaches the frame; an unknown key is refused; every slot off, every preset is bit-identical to `preview-plant-norack`, before and after each slot ran; per slot, its idle tail equals an instance that never cuts it, rings on the idle path, and every block it writes is guarded and metered (the control: `preview-plant-rack-idle` is silent there); the state round-trips a non-default fixture of every slot and key, byte-identical, playing the same; and `preview-plant-module-branch`, the test configuration with one `if (module == ...)` planted, must fail checks the clean one passes. The old chunks migrate and say so, and with one module on play bit-identically to main's build before B714 (the goldens; `preview-smoke --migration <clap> <main clap>` measures them directly, and the both-on difference); an unknown chunk version is refused loudly (the control: `preview-plant-silent-refusal` says nothing). It reports, never gates, what the slots cost. Also: drives the built CLAP through its own interface and holds the output against the engine's own `horde_offline_render`, bit for bit, on five presets at blocks of 128 and at uneven blocks; that render shares no code with this shell, and its phrase carries the chord's glide, written in the test from item 15b's generator. A full pitch bend reaches a note's pitch input at +2 semitones exactly (a plant that drops bends must fail); a note glides by 10.3's law sample for sample from the most recently started note, and a chord glides note by note (a linear law and a glide from the wrong note must read as different). Every host parameter set by a host event reads back in the engine, the host and the frame (an event sent to the next id must fail).
