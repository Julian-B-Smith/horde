# horde ENGINE PREVIEW

A throwaway plug-in that lets the human play the clean-room engine in Live (B624, ADR-366). It tests sound and CPU, and since B628 it also carries GUI 3 on the engine. It isn't the horde 2 shell (B398), it plays no part in the cutover decision, and it's deleted when that shell exists. Its bridge is planned as that shell's first slice (`docs/proposals/gui-on-engine.md`).

**What it has:** all 83 bank presets, levelled as the rendered previews are, with their blade-envelope routes played. **Every engine row is a host parameter** (B632, ADR-370): the 317 non-reserved rows plus Preset, 318 in all, each under the engine's own id and key, so every setting automates in Live. Above 64 parameters Live's panel opens empty and fills as controls in the plug-in's window are touched: a touch on the page reaches the host as one gesture (begin, value, end). **Polyphony is the one voice control** (the human, 2026-11-05: "One control: Polyphony"): the engine's own `voice.polyphony`, set from the page or the fallback window, with no separate Voices limit. **The plug-in's own safety rule:** a preset that loads asking for more than 8 voices, by the page, the host's Preset, a saved state or as the default, plays 8, set through the engine's Param path before the load completes, so the page shows 8. On engine `1ad270a` every bank preset asks for 16. A polyphony set by hand, at any value, stands, and a saved state keeps it.

**Its window is GUI 3's page** (B628), in a fixed 980 × 720 web view, talking to the engine through the bridge the plan's section 3 signs: the page sends `hordeNativeSend(JSON)`, and a 30 fps timer pushes `window.hordeNativeSnapshot(snapshot)`. The page's `hello` and `preset` are LOADs: the bridge answers each with one frame that acknowledges it and carries every engine row, and for a preset only once the new engine is playing, so the page never adopts the old preset's values. Host automation reaches the page as ordinary changed rows. With `want.summed` the page also gets the plug-in's own output for its scope (GN-4): `observe.summed = {rate, samples}`, the newest 2048 samples of (L + R) / 2, every 16th (128 points at 2756.25 per second at 44.1 kHz). The default page is a stand-in (`standin_page.html`): the presets, Polyphony, a few rows by key and one phase picture. `HORDE_PREVIEW_PAGE=<file>` builds another page in, such as the one `tools/gui3_inline.py` writes. `HORDE_PREVIEW_WEBVIEW=OFF` builds the old AppKit window instead (preset menu, Polyphony, every row and a CPU readout), the fallback until the page has been tried in Live.

**Pitch bend and the bank's glide** (B632), a stand-in for the pitch system (RC-3) until B504 rules it: MIDI pitch bend (in CLAP's MIDI dialect, as Live and the wrapper send it) at a fixed ±2 semitones, and each preset's `glide` and `glideAlways` from B.1 played exactly as SPEC-ENGINE 10.3 states them for the phrases: exponential in log frequency, 95 % in the glide time, from the most recently started note, a chord's notes each from the one before. A note's pitch goes to the engine only once it glides or is bent, from its first sample, and while it moves through IF-2's audio-rate input (float32), so a glide costs no extra engine segments. No travel law, quantizer or setting beyond these: they are B504's.

**What it lacks, because the engine lacks it:** filters, effects, the modulation matrix and the morph. Changing preset builds a new engine, which cuts off anything sounding. **No standalone app:** clap-wrapper's standalone format needs RtAudio and RtMidi, which it downloads, and neither is in this repo, so it would add two dependencies (a human gate).

**Every build is labelled** with the engine commit and a build number that only counts up. The label shows in the page (the snapshot's `plugin.build`), in the plug-in's description and in the log's first line, so a test build in Live is never a guess.

**What it saves:** the preset and every engine row that differs from what that preset loads ("current settings only", the human's ruling). A chunk holding only a preset's own values is about 30 bytes. Older chunks still load, and a `voices` line in them is ignored.

**Silence costs next to nothing.** While the engine reports itself silent (OU-4) and no event or edit arrives, the shell skips it. On 1ad270a a silent `process()` cost 7 to 13 % of a core per instance; `skip()` costs about 0.1 to 0.4 %.

**Its session log.** Each instance writes `~/Library/Logs/horde-engine-preview/session-*.tsv`: for every preset played, the blocks that had sound, their mean and worst share of the block's time, and how many overran. Idle blocks don't count, so the figures say what a note costs. These figures are from a real session, not PF-3, and they don't replace it.

## Build

```bash
HORDE_LIBS_DIR=<a full checkout>/libs HORDE_SDK_CACHE=<a full checkout>/build-release/_deps tools/engine-preview/build.sh <engine commit> --install
```

The engine comes from `git archive` of the named commit, never the builder's working tree. Everything builds outside the repo. `--install` copies the VST3, AU and CLAP into `~/Library/Audio/Plug-Ins` and runs `auval`. Run it outside Claude Code's sandbox, or the install lands in an overlay Live can't see.

## The oracles

None is in `./verify`, because the engine isn't in this repo or in CI (B568). `build.sh` runs them all, and each has a control that must fail.

- `bridge_test.cpp`: the bridge's pure half (`bridge_core.h`), headless. Every message type is acknowledged; a key the manifest lacks is reported and never sent; rack and midi keys and gestures never become Params; the manifest hash matches a value Python computed, and one changed row reads as a mismatch; a frame carries members only when `want` asks; the saved state round-trips and stays small; the polyphony cap takes 16 to 8 and leaves 8 or fewer alone.
- `smoke.cpp`: drives the built CLAP through its own interface and holds the output against the engine's own `horde_offline_render`, bit for bit, on five presets at blocks of 128 and at uneven blocks; that render shares no code with this shell, and its phrase carries the chord's glide, written in the test from item 15b's generator. A full pitch bend reaches a note's pitch input at +2 semitones exactly (a plant that drops bends must fail); a note glides by 10.3's law sample for sample from the most recently started note, and a chord glides note by note (a linear law and a glide from the wrong note must read as different). Every host parameter set by a host event reads back in the engine, the host and the frame (an event sent to the next id must fail). The scope's window equals the output the host received (a frozen tap and a tap of silence must fail). Through the bridge's extension (`bridge_ext.h`), a `set` on a row the host never sees reaches the engine and its seq comes back as `ack`; `hello` and `preset` are answered only in the frame that completes them, with every row (a preset only after the engine swap); a frame during silence claims no sound, and one during a chord does. A preset above 8 voices loads at 8; a held 12-note chord at polyphony 12 sounds 12 voices (the plant with the old Voices limit of 4 sounds 4). The mapping audit sets every engine row through the bridge and reads its exact v back from the engine and the next frame (a plant with the key map one row off must fail it).
- `gui_shot.mm`: opens the plug-in's real window as a host does. For the page, it sends from inside the page as GUI 3 does and checks the host and the page both hear of it, a touch as one gesture; for the AppKit window, it moves real controls. It saves a picture.
- `frames_dump.cpp`: records the frames GUI 3's `ReplayTransport` plays, to `tools/labharness/fixtures/gui3-replay.json`, with `gui3-display.json` beside it (the engine's x, unit and option name for five values of every row). `build.sh` holds a fresh dump against the committed pair, byte for byte. **Re-recording them is a human gate.**

Last verified 2026-11-06 against engine `1ad270a`: bridge test, smoke and window GREEN with the stand-in page and with GUI 3's page from main. The recorded frames no longer reproduce: the recorded chord now glides (B632), and re-recording waits on the human.
