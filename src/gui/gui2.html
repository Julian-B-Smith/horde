Output & perception

Routes

Right-click any knob or slider and choose “Send to mod matrix”; the route arrives on ENV 1 and the select re-aims it at any source. Depth is ±1 of the destination's full range; the destination's own bounds always clamp the result. A parameter can carry more than one modulator — right-click it again for “Send another”, or pick it above; the depths sum. The cell beside each source sets that route's polarity — as-is (the source's own), uni (0…1), bi (±1) or inv (negated); it is a property of the route, so one modulator can drive one destination unipolar and another bipolar. Right-click a routed parameter to release it (releasing lets go of all of its modulators at once). The Env > Pitch knob on OSC owns the Pitch row — its depth is in semitones, its source is fixed, and edits in either place stay in step.

Sources

ENV 1 — the amp envelope (loudest voice). ENV 2 — the pitch envelope's own ADSR (the P.Env knobs on OSC). LFO 1/2 and ENV 3/4 are below (B171). The LFOs are bipolar: a route reads ±1 about the destination's base unless the route's own polarity cell says otherwise. The bottom bar is B40.

ENV 1 — the amp envelope

ENV 1 is not a dedicated envelope. It follows whichever voice is loudest across the enabled oscillators, so its shape is each oscillator's own Envelope panel on OSC — the same knobs, shown here, not copies. Changing them changes how loud the note is, not only what ENV 1 modulates.

Diagnostics — lag bisect

Each switch kills one periodic subsystem LIVE — no reinstall, no reload. Turn them off one at a time and watch the corner's raf number; the line names whatever is off. These are session-local and never saved.

Visualizers

Shows CHROME-002 on MAIN (the phase circle lives on OSC). The specimen was exonerated by the excision experiment (the lag was the param-sync repaint, ADR-147) and is fully live again — create-on-show, so OFF means no GL context exists at all.

Keyboard

Off keeps focus in this window, which is what makes computer-keyboard notes linger in Live. On hands focus back to the host after every click.

Routing

Off (the default): the FX page's matrix well edits feeds from 0 upward, because a negative feed inverts polarity and is rarely what you want. Nothing is hidden either way — a cell that already holds a negative value (a patch authored with this on, or a morph blend) still shows it, marked ±, and renders exactly the same. A preference of this INSTALLATION: saved with the interface, never with the patch.

Patch transfer

COPY puts the whole patch on the clipboard as JSON — the quickest way to send a problem patch. PASTE reads a prompt rather than the clipboard, because clipboard-read permission is unreliable inside plugin webviews while a paste box behaves the same everywhere.

Performance

Voice Cull sets how quiet a released note gets before the engine stops rendering it. Raising it frees CPU in proportion to how many tails you stack up — most under fast playing with short releases — but it is audible: at −40 dB a tail is still present in a quiet mix. −80 dB is the shipped behaviour.

Panic

Also permanently in the tab bar: it is the control you reach for when something is already wrong, and a stuck note should not outlive a page change.

Morph field

Drag to morph. Each parameter follows the corner that wins its flip — temperature loosens the borders, coupling makes parameters move in blocs, the seed is the patchwork's identity.

Corners

SAVE stores the CURRENT sound as a corner preset — no capture needed. Load it into any corner below; the dropdown keeps the loaded name.
CAPTURE stores the current patch into a corner. Each corner's colour is the swatch beside its name above, and it is what marks that corner's parameters everywhere else in the interface. (Corner baseline-editing — the four color boxes on every page — is the recorded next phase, not this one.)

Morph engine

History

One entry per GESTURE, not per parameter write: a morph-pad drag that rewrites every owned parameter is one step, as is a preset load, a corner capture or apply, and the morph toggle. Click any entry to go back to it — the next edit then BRANCHES from there, so nothing you pass through is destroyed. Newest at the top. The bold lane is the path to the current state; a yellow dot is a fork; other lanes are branches you left. Dimmed rows are ahead of the current state — the redo side. "Coalesce runs" folds consecutive drags of one parameter into a single row with a count.
Host automation is deliberately absent: this records the states YOU made, and an automation lane keeps writing over the top after a restore exactly as it does after any edit. The last 200 states are kept, in memory, for this session — the oldest is dropped as new ones arrive and its children become roots of their own — but never a state on the path to where you stand: eviction takes the oldest state OFF that path first, so a base you keep branching from survives while an abandoned run goes.

About the rack

Four slots in series, slot 1 first. Order IS the slot index, so "reordering" means reassigning types. An Off slot is a bit-exact passthrough — it does not touch the buffer at all.
data-fixed on every control here, and that is load-bearing. The rack is ONE object shared by the whole patch, not one per oscillator, and the shell dispatches these by RAW id (id >= 57 && id <= 64), not by base id. Without the pin, selecting oscillator 2 would remap 57 to 1057, match nothing, and silently do nothing — which is exactly what gui.html did until 2026-08-12.
Comp and Comb are real cores (ADR-071), not placeholders; Drive / Filter / Gain are the increment-1 placeholders kept because order is audible with them.

Matrix

Rows FEED columns. A cell is a gain, and 0 IS "not connected" — so connecting and disconnecting is one continuous motion, which is what lets a morph corner hold a whole topology (ADR-088). Drag or scroll a cell to set it; double-click resets a cell to the shipped chain (1 on the series diagonal, 0 everywhere else); right-click is the usual parameter menu. Every edit lands on a WELL cell — the rail beside it is a readout and takes no gesture but hover, which lights the matching cell (and hovering a cell lights its ribbon). OUT is a slot's terminal contribution, and only a slot nobody reads is summed there. init drives a slot with nothing connected to it.
Cells that are simply absent are edges the read side does not accept this release: a slot may feed a LATER slot only. They are missing rather than greyed because legality is enforced where the audio is read, not where the grid is edited — a disabled control would be a second, bypassable copy of that rule. Feedback edges (ADR-128) are in the engine already and get their cells with the rack rebuild.
data-fixed on every cell, for the reason the rack's own note gives: the matrix is ONE object per patch, so an unpinned cell would be remapped by effId() when oscillator 2 is selected and would silently address nothing.

Editing

Selects which oscillator this page edits AND which one the engine renders in the visualizers. Global parameters are unaffected — they have no per-oscillator twin, so they never remap.
