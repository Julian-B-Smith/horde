# b446-w3b-devtools — the labs server, the preview script and lab loading stop trusting what they serve and run

- **Queue item:** ROADMAP B446 / ADR-194, P1 Wave 3, item W3b (the plan's B7 and B8).
- **Why:** three developer tools handed more than they should. The labs server served the whole
  checkout, with no Host check. `labs_preview.sh` ran code from merged, unreviewed lab branches.
  `./verify` ran lab and packet JavaScript in `node:vm`, which is not a sandbox, over files taken
  from the disk rather than from git.

## What changed

- **`tools/serve_labs.py`.**
  - Serves only `docs/design/` and `reference/`, plus an explicit list of the files the lab pages
    load (found by scanning the pages, not guessed): `docs/H2-PLAN.md`, `ROADMAP.md`,
    `DECISIONS.md`, `src/gui/gui.html` and `gui2.html`, and three `tools/patchspace/` files.
  - Everything else is 404. The Host header must be `localhost:<port>` or `127.0.0.1:<port>`,
    otherwise 403.
  - No `..` and no dot-file component. No symlink anywhere below the served root is followed.
    Directories are never listed. Binds 127.0.0.1 only.
  - New optional second argument: the root to serve, so the preview's merged tree is data to the
    main checkout's server.
- **`tools/labs_preview.sh`.** The index generator and the server are the MAIN checkout's copies
  (`tools/gen_lab_index.py` now takes the tree as an optional argument, run with `python3 -I`).
  Git runs in the scratch tree with `--no-verify`. The script prints the exact serve command. The
  `local/sluice` link is no longer made, because the server no longer serves `local/`. The
  explicit-branch mode is unchanged.
- **Lab loading.** New `tools/labharness/sandboxed_node.mjs` runs a harness under Node's
  permission model: read-only on a short named set of lab trees, no writes, no child processes, no
  addons, workers only for the two checks that use one, and a scrubbed environment. Each script has
  a row in its `PROFILES` table; an unlisted script is refused. A node with no permission model
  fails closed. `sandbox_guard.mjs` is the first import of six harnesses
  (`lab_load_check`, `fxlab_check`, `gui_history_check`, `morph_editor_check`,
  `lab_wheel_scroll_check`, `fxmorph_check`), so a bare `node tools/labharness/x.mjs` is sandboxed
  and the `./verify` command lines (which the playbook and the wiring check read literally) are
  unchanged. The packet oracle `reference/scalpel/verify/verify.js` cannot take an import (it is in
  the protected tree), so `./verify` calls it through the launcher.
- **`lab_load_check`** now takes its default file list from `git ls-files` (computed by the
  launcher outside the sandbox), so an untracked HTML in a lab tree is never executed. Same 65
  labs as before.
- **Three new checks, wired into `./verify fast`:** `tools/serve_labs_check.py`,
  `tools/labs_preview_check.py`, `tools/labharness/sandbox_check.mjs`. Each runs in about two
  seconds, with no network.

## Alternatives rejected

- Wrapping every harness call in `./verify` with the launcher: the playbook anchors and
  `test_table_check` read those command lines literally, and a hand-run harness would stay
  unsandboxed. The import guard fixes both.
- A path-limited checkout of `docs/design` instead of a merge (the plan's other option): a lab
  that depends on a changed `reference/` file would break. The brief asked only that nothing in the
  merged tree runs.
- A `local/sluice` opt-in flag on the server: not in the brief, and it re-opens a private
  sibling's tree. Left as a question.

## Known residue (kept visible)

- **Network** is not covered by Node 24's permission model. A script that escapes `vm` could send
  out what it can read, which is why the read grant is short and the environment is scrubbed.
- **Symlinks:** Node follows a symlink inside a granted tree even when it points outside it. A
  tracked symlink would show in review; an untracked one in a lab tree is not detected here.
- **Not covered:** the other harnesses that evaluate lab code with `new Function` rather than `vm`
  (`tools/golden/*`, `station_check`, `subosc_check`, `composed_engine_check`,
  `filter_fidelity_check`, the patchspace checks) and the manual tool `glide_roundup.mjs`, which
  writes a report. Follow-up for the plan, not part of W3b.
- **CI's node version is unverified** (the log prints none). The launcher accepts either flag
  spelling and fails closed without a permission model, so a CI node older than 20 would turn
  `verify fast` red rather than run unsandboxed. The escape rows of `sandbox_check` SKIP, loudly,
  if `process.getBuiltinModule` is missing (Node before 20.16 / 22.3).

## Needs the lead

- **`.claude/launch.json`** (name "labs") still starts the merged tree's own copy of the server:
  `<main>/.claude/worktrees/labs-preview/tools/serve_labs.py 8146`. That is the W2-06 shape. Change
  it to `<main>/tools/serve_labs.py 8146 <main>/.claude/worktrees/labs-preview`
  (runtimeArgs: server path, port, root). Until then, the preview runs whichever server the merged
  tree carries.
