# b584-gui3-slice7: map keys always, a whole MAP control, a fixed info box that explains sections

- **Queue item:** B584 slice 7 and B582 (ADR-335, ruled by the human 2026-10-30; ADR-261, ADR-333). Built on `origin/main` after slice 6 (#1293) merged.
- **Acceptance (the lead's brief), in short:**
  1. The map keys (M tap latches / hold is momentary, Esc, 1 to 9 only while MAP is on, P, Backspace) work with keyboard mode on or off, handled in the shell by calling the session's own methods (the bundle untouched); the scope is one named constant citing ADR-335 so reversing is one line; no key fires in a text input, select or contenteditable; seam tests with plants.
  2. The panel docks only while MAP is on (slice 6's behavior; confirm with a test).
  3. The MAP control widened so nothing in it is buried, at every source-name length.
  4. The info box a fixed square-ish size, left of the modulator bank at the bottom, on every page; hovering moves and resizes nothing (a test, with a plant that grows).
  5. Hovering a section's header or empty space explains the section: descriptions in ONE data file, drafted from the spec text, each with its source, marked DRAFT; none invented; a section without source text says so and is counted; the generator's check holds every entry to a source that exists and a sentence, with must-fail controls.
  6. The port ledger's rows updated, nothing untrue added. 7. `./verify fast` green. 8. Screenshots. 9. This trace. 10. A PR, never merged.
- **Why:** the human, 2026-10-30, verbatim in ADR-335: "keys always ... I may ultimately reverse the "keys always" decision after some use", "panel only while MAP on", "the map button needs to be widened; there's a part that appears to be buried", "The info box ... should be a static square-ish box that stays one size to the left of the modulators box at the bottom ... offer information about entire sections in addition to specific parameters."
- **What changed:**
  - **`docs/design/gui3/shell-logic.js`:** `attachMapKeys(S, win)` (capture phase) and the constant `MAP_KEYS_ALWAYS = true` with its ADR-335 comment. With keyboard mode off the shell calls `S.setMap`, `S.setSrc`, `S.cyclePol`, `S.remove` itself (tap/hold tracked by the shell, because the session's own keyup reads a press time only its own keydown sets, so every tap would read as a hold); with keyboard mode on it stands aside, so each key is handled once and keyboard mode's other behavior (digits pin corners with MAP off, Esc unpins, undo) stays the bundle's. A key in an input, textarea, select or contenteditable is never taken, and the session's listener is kept from taking it either; Cmd and Ctrl keys are the host's. `sectionInfo(sections, id, find)`: the info box's content for a section (its DRAFT text and source, or "No section description yet.").
  - **`docs/design/gui3.html`:** `.mapbar #mapHost { flex: 0 0 auto }` (the MAP control no longer shrinks; the strip scrolls) and the HOLD tag's room reserved; a foot row (`#footrow`, 216 px high) holding the info box (224 px wide, fixed, its text scrolling inside) left of the bank (which scrolls inside itself); `data-section` on every section host (dense sections, classic cards, the console's strips); the hover handler shows the control's parameter, else the section, else idle; `SH.attachMapKeys(S, window)`; review flags `src=<source id>` and `info=<section id or key>`; four self-checks (MAP control whole; info box fixed; section info; map keys with keyboard mode off).
  - **`docs/design/gui3/sections.json` (new):** 46 sections, 40 described (a sentence each, with its source: path and the heading it cites, from SPEC-ENGINE 5.2 to 5.6, 6.1, 6.2, 6.5, 6.10, 7.1, Appendix D and D.2), the whole file marked `DRAFT — the human has not read these`. 6 sections have none and say so: the FX page's five cards (four hosted modules; Bulwark has two faces) and Arp's; their vendored manifests carry keys, ranges and laws and no description of the module. `as` entries reuse one text for sections of the same kind (the dashboard's cards, Osc 2, ENV 3 and 4, the Mix strips).
  - **`tools/gen_gui3_controls.py`:** every group gets a section id (`<page>/<title slug>[-num]`, checked unique per page); `check_sections` holds `sections.json` to the rules above; its result travels in `shell-data.js` (`sections`); 8 new must-fail controls (a description for a section that does not exist, empty, no source, a source file that does not exist, a heading the spec does not have, an alias to an alias, a file no longer marked a draft, two sections with one id): 35 in all (from 27). The GREEN line prints the section counts and the must-fail count it actually ran.
  - **`tools/labharness/gui3_seam_check.mjs`:** the fake DOM runs capture-phase listeners before bubble-phase ones and honours `stopImmediatePropagation`; `mapkeys` now runs the whole key set with keyboard mode off and on (each key once, digits free with MAP off); new tests `mapkeysfield`, `mapkeysflag`, `sections`, `infofixed`, `mapbar`; 34 tests (from 29) and 48 plants (from 34), each red for its own test (`--verbose`).
  - **`docs/design/gui3/port-tab.json`:** `quick-map`'s `missing` (the keys now work always, provisional; the inspector's docking is ruled, so it leaves the list) and `descriptions` (now `partial`, with what is missing). **`README.md`** (a slice-7 section, proposals 23 and 24, the gates), **`shell-data.js`** and **`params.json`** regenerated, **`docs/design/index.html`** regenerated from the tagline.
- **Evidence consulted:** ADR-335 (`git show origin/lead-records-378:DECISIONS.md`); the bundle's `Session.start` (the keys), `MapControl`, `ModInspector` (`docs/design/arp-face/bundle.js`, read only); `docs/design-system/HORDE-Map-Mode-Spec.md` (read only); SPEC-ENGINE for every section sentence; slice 6's trace and the files as they stood.
- **Measured (headless Chrome, own profile):**
  - **What was buried in the MAP control:** the source drop-down and the name in it. The control was 87 px wide of its 213 px (measured by reverting the one CSS line): the bundle's `.hd-map` is `overflow: hidden`, so as a flex item it has no minimum width, and the source strip beside it (`flex: 1 1 auto`) shrank it. Now 213 px with "Gravity offset", the longest name (84 px of a 101 px text area).
  - **The info box:** 24 hovers (the longest parameter text and the longest section description of 14 pages) moved and resized none of the page column, page area, bank, box and foot row; one box size on every page; the longest descriptions scroll inside it. A box allowed to follow its text moves the layout (the check's control).
  - **Page room:** the page area is 374 px on every page with the foot row (slice 6 measured 436 px on a page whose bank held no cards; with cards the old bank and box stacked taller): Main, Dashboard and Mix fit with the bank shown or hidden; Osc 1, Osc 2, Sub and Noise scroll as before. **The bank toggle no longer gives its height back** (the box holds its place and size).
  - **Plants by hand in the page:** the MAP control's CSS reverted to the slice-6 line reds its self-check; `MAP_KEYS_ALWAYS = false` reds the map-key self-check.
  - **In-page self-checks:** 25 lines, none FAILED, on `#osc1`, `#main,morph,map` and `#mix,dark,nobank`.
- **Alternatives rejected:**
  - **Patching the bundle's keyboard gate:** the bundle is vendored and read only (the brief); the shell takes the keys while keyboard mode is off instead. The bundle gate stays proposal 22.
  - **The shell handling the keys in both modes:** it would have replaced keyboard mode's other behavior (digits pin corners with MAP off, Esc unpins), which the brief asks to keep.
  - **A foot row of the whole window's width (box at the window's left edge):** it would take the pad dock's and the inspector's height from them; the box is at the page column's bottom left, so it moves sideways when the dock opens (not on a hover).
  - **A box and a bank of different heights, so hiding the bank gives room back:** the box's top edge would move when the bank hides ("keeps its size and place").
  - **Writing descriptions for the FX modules' cards and Arp's from their module names:** no spec text describes them, so none is invented; they are counted.
- **Verify:** `nice -n 10 ./verify fast`, run last on the committed tree; its tail is in the report and the PR body. The git hash is in `.harness/last-verify.json`.
- **Open questions:**
  1. Hiding the bank no longer returns its height to the page (ADR-335 says the box keeps its size and place). Is that the shape, or should the foot row shrink to the box's height when the bank is hidden, the box staying at the bottom left?
  2. The foot row is 216 px (box 224 x 216) so a pending modulator card's note is not cut; a smaller one gives the pages more room (`--foot-h` in the shell's CSS). What size does the human want?
  3. Digits with MAP off still pin morph corners only in keyboard mode (keyboard mode's behavior, kept unchanged); ADR-335 names digits as source keys only while MAP is on. Is that what is wanted?
  4. The 40 section descriptions are drafts from the spec; none has been read by the human. The FX modules and Arp have none until their manifests or a spec describe them.
  5. `./verify`'s comment on this generator still says "Twenty-seven must-fail controls" (now 35) and out of scope here: the comment is stale until a lead edits it.
