# b212-compact-lab — the compact horde face: three layouts at plugin size, six decisions surfaced

- **Queue item:** B212 (`git show origin/lead-records-81:ROADMAP.md | grep '^| B212 |'`).
  Acceptance, verbatim: "at least two competing compact layouts at plugin size, side by side,
  built from REAL parameter names and ranges (read `src/param_presentation.tsv`); the six
  decisions above listed in the lab with a recommendation each; both themes screenshotted;
  loads under `lab_load_check`; `docs/design/index.html` untouched (the lead regenerates it)."
- **Why:** The human wants most parameters reachable but hidden behind a simplified face, and
  said up front that this needs decisions. So the lab is built to pose those decisions, not to
  answer them quietly. Each of the six is a set of pills. A pill drives the frames, so an option
  is judged by using it. REC marks the lab's recommendation, with its evidence. The
  safety invariant (decision 6) is the architecture of the file, not a caption. There is one
  store keyed by table address. `put()` is its only writer. History, host lanes and the preset
  snapshot are all fed from it.

## What the lab is

`docs/design/compact-lab.html` (new). Everything else is untouched: `src/`, `specs/`,
`reference/`, `docs/design/index.html` and gui2.

- **Frames at plugin size.** A (fixed spine, ours), B (the preset's eight named macros) and
  C (spine + macros + preset pins, recommended). All three read and write the same store, and
  each has a COMPACT/FULL switch. Window sizes are 720×440 and 980×720. Those numbers come from
  `hypersaw_gui_common.h:27-28` and `hypersaw_clap.cpp:9333-9338`.
- **Real addresses.** An embedded table of all 368 rows joins `src/param_presentation.tsv`
  (label/page/group/widget/shown_when/scale) to `kParams` (min/max/default/stepped/enum
  captions) in `src/hypersaw_clap.cpp`, generated at `fb64f70`. The join was a scratch script
  that matched on address. The rules: `osc1.`/`osc2.` → bare key with id < 4000, `sub.` →
  bare key with id ≥ 4000, globals as-is. All 368 matched and 0 were missing. The file header
  says the table is a copy and says how to regenerate it. The intent names are the shell's
  defaults (`hypersaw_clap.cpp:4152`).
- **Lab-invented content, labelled as such in the header.** The three presets: INIT,
  GLASS CHOIR (morph on) and SAW STACK. Their values, routes, corners, pins and renames are
  all invented. The morph is a bilinear blend (the shell's default mode is quantum flip), and
  corner arming is not modelled.
- **Decision 5's strip.** It is computed per frame from what that frame shows. Visible controls
  keep gui2's ADR-137 halo, copied from gui2:617-730: the knob holds the base, a violet reach
  arc shows the modulation range, and a live tick shows the current value.
- **Macro suspension.** Macros follow today's `macroLive` law (`hypersaw_clap.cpp:3847`), not
  B170's planned retirement of it. So GLASS CHOIR shows B's face dead under morph, with a
  caution inside the macro row.
- **Deep links.** `?theme=dark&preset=GLASS_CHOIR&reach=drawer&size=same&strip=count&shadow=1&who=ours&view=full&open=tone&page=OSC`.
  A screenshot of any option is then a page load, not a synthetic click.

## The six recommendations (as the lab states them)

1. WHAT: **mix** (frame C). A macro-only face is dead on INIT (no routes) and dead under
   morph (`:3847`). Composed module faces would put 16 FX knobs on the face first. So the face
   takes only each module's ADR-169 Amount role; B210 owns the faces themselves.
2. HOW: **toggle** plus an ↗ jump to page and group. Page and group are table columns, so the
   jump needs no hand-kept map. Expanding in place breaks at 720×440 (Image & tone alone is 13
   rows). The drawer covers the face.
3. WHO: **both, layered**. The spine is ours and fixed. The macro row and up to four pins
   belong to the preset. Pins are presentation data carried in the patch, like intent names
   (`:4148-4151`). They are never parameters.
4. SMALLER WINDOW: **yes, 720×440**, which is the existing minimum. The shell makes no
   request_resize call today (grepped `src/`), so compact must degrade when the host refuses.
   Host behaviour is a HYPOTHESIS, not measured.
5. HIDDEN MOTION: **named strip** (address, source glyph, live tick, click to reveal). A count
   says nothing you can act on, and showing nothing is the failure the human named.
6. INVARIANT: **a view of the same address**. SHADOW mode demonstrates what breaks: no history
   node, no lane, no snapshot, lost on save/reload. SET's `specimen` (`:632`) is an existing
   view choice that IS a parameter, and compact should not follow that precedent.

## Alternatives rejected

- **Committing the join script as a tool plus a drift check.** It would add a tool and a
  `./verify` wiring edit, and this dispatch may not edit `./verify`. The table is instead a
  labelled, dated copy, the same trade the station lab made with its tokens.
- **Designing FX module faces.** That is B210's work. The lab uses only the Amount role.

## Open questions

- Host resize behaviour (decision 4) is untested in Live, Bitwig and REAPER.
- The pins format (a list of addresses in the patch chunk) is a proposal. Its storage home
  (beside intent names) is the port's to confirm.
- The lab's blend morph differs from the shell's quantum default. The strip's behaviour under
  flip (the owner changes discretely) has not been drawn.
- The table is a copy at `fb64f70`. B213 (units/tapers) may change labels and tapers, and
  then this file needs regenerating.
