# b441-c2 — the base wave once per blade evaluation; load guard B441-3

- **Queue item:** ROADMAP B441 phase 2, candidate C2 (the phase-1(B) audit's second output-neutral candidate), plus protocol B441-3. Lead brief of 2026-10-04 (horde lead session, after C1 merged as #937). ROADMAP B441 phase 2: each experiment must "leave every parity digest unchanged (output-neutral; ADR-187 §5) ... plus a measured speedup under the frozen protocol, with the ledger updated".
- **Why (B441-3):** a Chrome tab, other sessions' Node runs and a sibling repo's mutation tests each burned a full core on 2026-10-04, and the 1-minute load average alone did not keep them out of the timed region. `tools/measure_h2_engine.cpp` now snapshots `ps -A -o pcpu=,pid=,comm=` before every repeat, outside the timed region. It waits, as for the load, while any other process uses ≥ 50 % of a core: the same 20 s × 30 budget, then exit 3. Every `LEDGER` row now carries `guard_waits` and `foreign_top3`, which records each process's basename and %CPU at the start of the cell's best repeat. The change is measurement-only and is documented in `docs/port/cpu-ledger.md` §1. That section also notes that B441-1 and B441-2 absolute figures may carry contamination, while their interleaved ratios stay fair. Commit `435cffc`.
- **Why (C2):** `wave(p.base, phi)` was evaluated up to three times for one phase in one output. In `out()` it ran in blade 1's `voicePlain`, in blade 2's `voicePlain` and in blade 2's `- wave(g.base, phi)`; the twins did the same at φ−½. `outSerial` computed its base and then again inside each `ev`, and `dcEst`/`dcPair` subtracted a base their `voiceOut`/`out` had just computed.
  - `voiceOut`/`voicePlain`/`voiceAA`, `out`, `outSerial` and `ev` now take `base` from their caller.
  - One evaluation serves the blade and the subtraction beside it.
  - Blade 2 reuses blade 1's value when `sharesBase(g.base, p.base)` holds. Commit `1176e69`.
- **The proof that the reuse is legal:**
  - **Purity.** `wave(sh, x)` is a const member. It reads `sh` only through `js::sel(sh)`, and it reads the members `gmr`/`gmn` only in case 6 (sine→saw); `engine.h` `wave`. So equal `sel`, the same `x` and a case other than 6 give the same bits whatever `gmr` holds. That is exactly `sharesBase`. Case 6 recomputes under blade 2's own `gmr`/`gmn`, as before.
  - **Every reused value has bit-identical inputs.**
    - Blade 1's base is computed by the caller of `out()` under the `gmr` in force at the call. `out()` changes `gmr` only inside the blade-2 block and restores it, and `outSerial` restores its `mr0`/`mn0`, so the value equals what `voicePlain` computed at entry.
    - `base2` at φ−½ uses the same `ph2` expression in both the blade-1 and blade-2 twin paths.
    - In `outSerial`, `d1.mr = mr0 =` the entry `gmr`.
    - `voiceAA`'s second base was at the same `p` and `phi`, with no `gmr` write between.
  - **The expressions are unchanged.** Every `- base` subtraction keeps its operand, and only the source of the identical value moved. For example, `outSerial` still subtracts blade 1's base from `ev(A, …)` even when A is blade 2. Nothing was reassociated. `-ffp-contract=off` holds, and the flags are untouched.

- **Alternatives rejected:**
  - **Out-parameters returning the base from `out()`.** These would add a pointer and a sequencing hazard (`out(...) - b` with `b` written by the call). An explicit `base` parameter is plain data.
  - **Keeping the old parameter order with `base` appended.** A stale call site would silently convert `bool hasInp` into `base`. Placing `base` after `phi` makes every unconverted call a compile error.
  - **Keying the blade-2 reuse on `gmr`/`gmn` equality.** This would add ±0 and NaN corner cases (a `-0` `gmn` flips the sign of case 6). Excluding case 6 is simpler and provably safe.
  - **Making `outSerial`'s unconditional `base2` lazy.** It is a different saving and was left out of scope.
