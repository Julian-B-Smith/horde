# b157-osc-scope — the OSC page's waveform pane paints into its own visible canvas

- **Queue item:** B157 (`origin/lead-records-50:ROADMAP.md`), dispatched 2026-09-19.
- **Why:** the OSC page's waveform had been structurally blank since B106 gave MAIN
  both oscillators. `paintScope` resolved its target with `activePane()` — a
  `canvas.wavosc` that lives on MAIN — and while OSC is showing MAIN is
  `display:none`. `fitViz` clamped that hidden pane's bitmap to 1×1 (`Math.max(1,
  …)` hid the zero a guard would have caught), the whole trace was drawn into that
  one pixel, and `blitScope` copied the 1×1 image onto the OSC page's 330×80
  canvas, which nothing cleared and nothing ever filled. The fix is to paint the
  canvas that is ON SCREEN and delete the copy step, which also removes the
  freeze trap: the HOLD badge used to be stamped on the hidden pane, so freezing
  from OSC showed neither a wave nor a badge saying why.

## What changed (`src/gui/gui2.html`, GUI only)

- `fitViz` REFUSES a canvas whose CSS box is zero (returns `false`, bitmap
  untouched) instead of clamping to 1×1. Callers already read `false` as "bitmap
  unchanged"; a hidden canvas now keeps its last size until it is shown.
- `paneFor(canvas)` caches one 2d context per `canvas.wavscope` — MAIN's
  per-oscillator panes and the OSC page's single canvas alike. `wavPanes` is built
  from it, so the B106 derive-from-the-markup rule is unchanged.
- `visibleScopes()` = the `.wavscope` canvases on `.page.on` with a non-zero
  `offsetWidth`; `activeScope()` picks the pane that OWNS `editOsc` where a page
  has one per oscillator, else the page's own canvas. `paintScope` uses it and
  draws nothing when there is no visible target (setting `SCOPEDIAG = 'hidden'`
  so the footer's `wave:` token cannot report `ok` over a refusal).
- `activePane`, `scopeCopies` and `blitScope` are DELETED — with the painter on
  the visible canvas there is no second copy to keep in sync. The unused outer
  `wvx` binding went with them (every use in `paintScopeInto` is its own local).
- The freeze handler badges every canvas in `visibleScopes()`, which always
  includes the one clicked, and no longer blits.
- No markup change: the OSC canvas already carries `wavscope`, which is the class
  the feed gate and now the paint target both select on.

## Pixel proof (headless Chrome, `file://`, dpr 2, stubbed `hzFrame`)

Bridgeless: the probe replaces `window.hzFrame` with the real frame protocol
(base64 int16 blocks, `oscScope16` for MAIN, `scope16` elsewhere) and reads the
canvas bitmaps back with `getImageData`. `ink` = pixels differing from the
bitmap's modal colour; `cols` = how many x columns carry ink. Three builds, same
probe.

**Detector zero-control (must read zero, every run):** a fresh never-painted
canvas → `ink 0, alpha 0, cols 0`. The detector can report zero, so its non-zeros
mean something.

| build | OSC page waveform canvas | MAIN pane 0 / pane 1 |
|---|---|---|
| **before** (`origin/main`) | `330×80, ink 1, cols 1 / 330` — one pixel, the 1×1 blit | `628×154 ink 53386` / `628×154 ink 48824` |
| **after** (this branch) | `628×154, ink 53386, cols 628 / 628` | `628×154 ink 53386` / `628×154 ink 48824` |
| **must-fail control** (this branch, old `activePane()` target planted back into `paintScope`, nothing else changed) | `330×80, ink 0, cols 0` — blank | unchanged |

Identical in LIGHT and DARK (after/OSC: `ink 53386` light, `53386` dark; the
painter has no theme branch — only the resolved `--scr-*` tokens differ, which is
why the ink counts coincide).

**HOLD badge**, OSC page, badge rect `(w-34, 3, 31, 11)`, before → after freezing:

- before (`origin/main`): `ink 0 → 0`, `colors 1 → 1` — no badge, the trap.
- after: `ink 93 → 175`, `colors 2 → 68` (light) / `2 → 69` (dark) — badge lands.
- MAIN still badges both panes: pane 0 `93 → 175`, pane 1 `185 → 249`.

**`wave:` token (d).** Page walk, after: `MAIN:ok · OSC:ok · MIX/FX/MOD/MORPH/SET/HIST:nofeed`
— byte-identical to the before build's walk, so the diagnostic is unchanged where
it was already true and now also refuses to say `ok` over a hidden target.
Frozen from OSC: `SCOPEDIAG = 'frozen'`, and the footer reads `wave:frozen` once
its own 2 s `setInterval` has come round (the health line's cadence, not staleness
in the token).

Screenshots (OSC page, before/after × light/dark, PR body): before the waveform
box is empty; after it carries the L trace over the dotted R trace, footer
`wave:ok`.

## Alternatives rejected

- **Give the OSC canvas the `wavosc` class** so it joins `wavPanes`: it would then
  claim to be oscillator 0's pane and pull MAIN's two-oscillator feed (bit 8) on a
  page that draws one — the label-resolved-from-active lie B106 removed.
- **Keep `blitScope` and just guard it**: the copy only ever existed because the
  painter wrote somewhere invisible. Fixing the target makes it dead weight, and
  keeping a second copy is keeping a second thing to get wrong.
- **Clamp `fitViz` to the attribute size instead of refusing**: silently
  plausible, which is exactly the failure mode being removed.

## Open questions

- The proof runs in Chrome at `file://`, not in the plugin's WKWebView. The
  mechanism (`display:none` → `clientWidth 0`) is not engine-specific, but the
  human's confirmation in the DAW is still the gate that matters.
- Headless Chrome on this Mac never exits after `--dump-dom` (GoogleUpdater is
  spawned and inherits stdout, so a piped `subprocess.run` hangs forever —
  measured: four flag variants all timed out at 45 s while the DOM had been
  written within a second). The harness redirects to a file, polls it, and kills
  the process. Noted here because the next session to reach for headless Chrome
  will otherwise lose the same half hour.
- `paintScope`'s `SCOPEDIAG = 'hidden'` branch is unreachable while any
  `canvas.wavscope` is on the visible page — it exists so a future page that hides
  its scope behind a collapsed cluster reports the truth rather than `ok`. Not
  exercised by the proof.
