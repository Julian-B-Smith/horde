# b446-w2-ci-release — CI and release hardened, SDKs pinned by commit, two approved removals, two new checks

- **Queue item:** ROADMAP B446 (security overhaul), P1 Wave 2 (items B4 and B5 of the private P1 plan). Lead brief of 2026-10-07; the batch approval for workflow edits and the two file removals is ADR-194 (D-S4, and "Also approved"). Findings come from the private P0 lane-3 and lane-4 reports, which are local-only and not cited by content here.
- **Why:** the build, validation, packaging and release path is the route by which bytes reach users, so each link is now pinned or checked by construction: third-party actions and tools by commit or hash, packaging in a job that runs no third-party tool, signing before packaging, artifacts outside the source tree, releases only from `main` with an explicit file list, checksums and an SBOM.
- **What changed:**
  - `.github/workflows/ci.yml`: top-level `permissions: contents: read` (only `release` widens, to `contents: write`); every action pinned by 40-hex commit with a `# vX` comment; `persist-credentials: false` on every checkout. Per platform the old single job is now build → validate → package: the build job tars the bundles into `$RUNNER_TEMP` and publishes the tar's SHA-256 as a job output; the validate job runs pluginval, whose download is checked against the SHA-256 in the workflow's `env` (a mismatch fails); the package job needs both, re-checks the tar against the build job's hash, and packages into `$RUNNER_TEMP`. macOS packaging is `tools/package_macos.sh`, called by `package-macos` (main pushes, no secrets referenced) and `sign-macos` (tags only, `environment: release`, the only place the Apple secrets are read). `release` checks the tag's commit is an ancestor of `origin/main`, requires exactly the three expected inputs, generates the SBOM and `SHA256SUMS` (verified with `sha256sum -c`), and attaches five named files; the notes state the macOS signing mode taken from `sign-macos`'s output.
  - `tools/package_macos.sh` (new): signs every bundle first (ad-hoc with no credentials; Developer ID + notarize + staple bundles with all five; RED with some), then builds the zip and pkg from the signed bundles (pkg productsigned, notarized and stapled in Developer ID mode). Keychain with a random password, key usable by codesign and productsign only, certificate file removed right after import, keychain deleted on exit. Refuses an output directory inside the source tree or a non-empty one.
  - `tools/gen_sbom.py` (new): CycloneDX 1.5 JSON listing every submodule (from the index and `.gitmodules`), every FetchContent SDK at its pinned commit, and both pluginval zips (scope `excluded`, with their SHA-256). Deterministic (commit time, uuid5 serial); fails closed on any missing piece.
  - `CMakeLists.txt`: the VST3 SDK and AudioUnitSDK are fetched with `FetchContent` at commit `9fad977…` (tag v3.8.0_build_66) and `53a9a20…` (tag AudioUnitSDK-1.1.0), handed to clap-wrapper as `VST3_SDK_ROOT` / `AUDIOUNIT_SDK_ROOT`, and clap-wrapper's own tag-based download is forced OFF (fail closed: any other SDK it wanted would stop the configure). The stale "pinned there" comment is gone. Network use is unchanged in kind: a fresh configure fetches, as before.
  - `.github/workflows/cpu-derate.yml`, `docs.yml`: top-level read-only permissions, checkout pinned by commit, `persist-credentials: false`.
  - Removals (ADR-194): `tools/__pycache__/gen_gui_controls.cpython-313.pyc` untracked (`git rm --cached`); `dist/cpu_bench` removed. `.gitignore` already carried `__pycache__/`, `*.pyc` and `dist/cpu_bench`, so it is unchanged. `dist/README-cpu-bench.md` kept (it is the only build and run instruction for the bench) and edited: the binary is no longer committed, build it yourself into the gitignored path; the stale "built from commit" line removed. The matching comment in `tools/cpu_bench.cpp` updated (comment only).
  - `tools/binary_hygiene_check.py` header flipped to `WIRED: ./verify fast` and wired after `private_name_gate`.
  - New checks, both `WIRED: ./verify fast` (ADR-180 §1 additions), stdlib only, controls in memory every run: `tools/workflow_pin_check.py` (every `uses:` a 40-hex SHA with a version comment; top-level `permissions:` in every workflow; no `pull_request_target`; no `github.event` expression inside `run:`) and `tools/release_path_check.py` (`gh release` attaches named files only, including SHA256SUMS and the SBOM, after an ancestry check; artifact `path:` under `${{ runner.temp }}`; no packaging command names a tracked top-level path; and `gen_sbom.build_sbom` succeeds on the tree and lists every submodule, SDK pin and pluginval pin).
- **Must-fail controls against the pre-change workflows** (the three `origin/main` files exported to a scratch dir, `--paths`): `workflow_pin_check` RED with 3 missing top-level permissions and 10 tag-pinned `uses:`; `release_path_check` RED with 3 artifact paths in the workspace, 3 packaging outputs under tracked `dist/`, the glob attachment, no checksums/SBOM, and no ancestry check. `binary_hygiene_check` was RED on `origin/main` (the bytecode file) and is GREEN after the untracking.
- **Local exercise:** a Release build of this branch configured with the pinned SDKs (`git rev-parse HEAD` in each fetched tree equals the pinned commit; no CPM package added). `tools/package_macos.sh` run on those bundles after the same tar round trip CI uses: ad-hoc mode produced exactly the zip and the pkg; partial credentials, an output dir inside the tree, and a missing bundle each exited 1.
- **Evidence consulted:** `CLAUDE.md`; ADR-194 (commit `be9abb2`); the private lane-3 report (L3-H2, H3, M1–M5, M9 and their guards), lane-4 (L4-H1, L4-M5), the P1 plan (B4, B5); `libs/clap-wrapper/cmake/base_sdks.cmake` (root-before-download order), `make_clapfirst.cmake`, `shared_prologue.cmake`; `tools/test_table_check.py` (wiring rule); `tools/banned_api_check.py` (header idiom). Re-verified today: both pluginval v1.0.4 zip hashes (downloaded and hashed), the three action tags' commits and both SDK tags' commits (GitHub API).
- **Alternatives rejected:** SDKs as new submodules (touches `libs/` and `.gitmodules`, larger change, and arguably a new dependency entry); keeping clap-wrapper's CPM fetch and overriding by package name (couples to CPM internals); one macOS job with an expression-valued `environment:` (an empty environment name's behaviour is not verified, and the macOS path is not exercised by PR CI); running pluginval after the build job's upload (a process in that job could rewrite the job's own hash output); a `$RUNNER_TEMP/dist/*` glob in the release step (the rule is an explicit list).
- **Verify:** `./verify fast` exit 0 and `./verify full` — the two `.harness/last-verify.json` lines are in the PR body and the hand-back.
- **Open questions:** (1) the macOS jobs (`build-macos`, `validate-macos`, `package-macos`, `sign-macos`) and `release` run only on push/tag, so PR CI cannot exercise them; the first post-merge run on `main` is their first real run, and the first tag is `sign-macos`/`release`'s first; (2) post-merge macOS cost rises from one 10x job to three (build, validate, package); (3) the Developer ID path in `package_macos.sh` has never run (no secrets exist); a dry run on a throwaway tag before the first real release is advised; (4) the GitHub `release` environment must be created by the human (steps in the PR body) before the first tag and before any secret is added; (5) the SBOM lists the VST3 SDK at its commit but not its four submodule commits separately (they are fixed by that commit's gitlinks); (6) neither check requires download hash verification in general (only pluginval is pinned, by construction in the workflow) — a generic "every download is hash-checked" rule was not in the brief.
