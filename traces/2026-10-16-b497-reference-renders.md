# b497-reference-renders — the reference renders' generator, metadata, phrase set and version-0 states

- **Queue item:** ROADMAP B497 part 2 (acceptance: "the renders' manifest reproduces from the generator"), under ADR-223, ADR-226 item 9, `specs/SPEC-ENGINE.md` 10.1, 10.3 and Appendix B. Brief: the horde lead, 2026-10-16, with the human's storage ruling ("release asset, all four phrases").
- **Why:** the test author receives frozen renders of today's engine as input data (10.1). The audio is too large for git (373 MB), so the tree holds the generator, the phrase set, each render's parameter metadata and a SHA-256 manifest, and the lead uploads the zip as release `engine2-reference-renders-v1`.
- **What changed:**
  1. `engine2/data/phrases/phrases.json` (new): the four phrases as sample-timed event lists at 44.1 kHz, from the lead's definitions; README rewritten (the lead supplies them; glide rule stated, not encoded).
  2. `tools/engine2_reference_renders.mjs` (new, `WIRED: ./verify fast` for `--static-check`): `--out` renders through `h2_harness_render` (the composed engine's adapter), `--verify` hashes a copy of the audio against the manifest, `--static-check` checks the tracked metadata against its inputs, with 13 must-fail controls. Reuses `harness.mjs`, `presetGain()` and the WAV writer of `tools/h2_ab.mjs`; adds nothing to them.
  3. `engine2/data/reference-renders/manifest.json` and `parameters.json` (new, generated) and its README.
  4. `engine2/data/version0-states/`: 13 example states and a README (what each exercises and the level B.2's formula gives).
  5. `engine2/data/README.md`: three table rows updated. `./verify`: one block added at the end of `fast()`; nothing removed, skipped or relaxed.
- **Evidence consulted:** `h2/harness/{render_cli.cpp,harness.mjs,gen_patches.mjs,README.md,adapter_composed.h}`; `tools/h2_ab.mjs` (settings, WAV writer, entry-script test); `h2/engine/{engine.h,blade.h}` (key tables, defaults, `monoOn`'s glide rule, `gain` 0.0875); `specs/SPEC-ENGINE.md` 5.2 to 5.3, 6.9, 7.1 (IF-1, IF-2, IF-4), 10.1, 10.3, Appendices A and B; `tools/engine2_cleanroom.sh`, `tools/engine2_cleanroom_check.py` (the builder's tree and its identifier scan); ROADMAP B497.
- **Findings:** (a) `engine2/data/bank/presets.json` equals `reference/scalpel/data/presets.json` byte for byte per preset (83 of 83), so the A/B tool's bank is this bank. (b) Bank presets are not all fully resolved against B.1 (key counts per preset vary, e.g. `A` is stored in 47 of 83); omitted keys take B.1's base values, which the generator sends explicitly; for all 95 presets that render is bit-identical (float64 digest, chord phrase) to sending only the listed keys, so B.1's base values equal the engine's defaults. (c) All 99 keys of B.1's base list and the five settings are known to the engine (probed one at a time): `notExpressible` is empty everywhere. (d) The engine's glide acts only in its mono/legato modes (`monoOn`); 22 bank presets store a `glide` in poly mode where it has no effect; 14 presets are mono (12 bank, 2 envelope), 28 renders glide (chord and trill). (e) Reproduction: two runs into separate directories gave identical SHA-256 for all 380 WAVs and byte-identical manifests; the tracked manifest equals both.
- **Alternatives rejected:** a per-render parameter file (380 files, each repeated four times; one entry per preset in `parameters.json`, named by each render's `preset_id`); a separate `*_check` file (the generator's own `--static-check` mode keeps the check beside what it checks); recording the repo commit as the engine hash alone (it would move with every commit; the manifest holds both `engine.git_tree` and `engine.commit`); reading the engine's defaults from `blade.h` (the spec's own B.1 sentence is the owner of the base values; the render is the evidence they agree).
- **Verify:** `./verify fast` on the staged tree; the exit code, its closing lines and the `.harness/last-verify.json` tree check are in the hand-back and the PR body. `python3 tools/engine2_cleanroom_check.py` also green (the builder's tree holds `phrases/` and the READMEs only).
- **Open questions:** (1) Phrase length for the 2 s tail is the sample of the phrase's last note-off (fast line 1.59 s, trill 1.93 s), not the grid length (1.6 s, 1.92 s); say if the other reading was meant. (2) The settings are the A/B tool's (`os` 1, `frameHold` 1, `stealFade` 1, `poly` 8), not the new engine's defaults (Standard, polyphony 16); `poly` 16 is a one-constant change in the generator. (3) 10.3 says a preset "glides" by `glide`/`glideAlways` without saying poly presets are excluded; today's engine does not glide them, so the renders do not, and a test author applying 10.3 literally would glide 22 poly presets the renders did not. (4) Version-0 example 12 (dropped keys) uses arbitrary non-zero values: which keys B.2 reports is a function of the new engine's behaviours, not of the file. (5) The zip's own SHA-256 is not reproducible (zip stores file times); the WAV hashes are.
