# b595-design-chain — the design master in the repo, the ledger's format, lab statuses, and one check for the chain

- **Queue item:** B595 (ADR-336: one chain of custody for design; the master's source in the repo; the audit, B596, runs on this format).
- **Why:** the human, 2026-10-30, wanted to know where the sources of truth are "so I don't create anything that isn't properly wired up". Before this PR the design master lived only in the artifact, no record said which rulings had reached the master or the shell, no lab carried a status, and nothing compared the vendored bundle with the master.
- **What changed:**
  - `docs/design-system/master/` (new, 137 files): the Design System artifact's `project/` tree at version `1793374583-b6a5`, byte-identical. Confirmed against the artifact's own file listing (137 `project/` files, sizes spot-checked on eleven files, total 1,201,608 bytes) and `diff -r` against the downloaded tree (no difference). No CRLF in any file, so git's `eol=lf` stores the same bytes. The ten logo PNGs are in the artifact's asset store, not in `project/`, and are not imported.
  - `docs/design-system/master/VERSION` (new): artifact URL, version, date, file count and a sha256 per file, written by `tools/design_vendor.py record-master`.
  - `tools/design_vendor.py` (new): the vendoring transform as code. `bundle.js` and `bundle.css` get one stamp line; `tokens.css` is generated from `tokens.json` by the rules the arp-face README states. Two commands: `record-master` (rewrite VERSION after a publish) and `vendor` (re-vendor). Not run in vendor mode here: no re-vendor in this PR.
  - `docs/design/design-ledger.json` (new): the format (top-level note, the five `states`, `master_versions` with evidence, `vendoring.known_drift`, `labs`, `not_labs`, `rows`, `not_design`), three example rows (knob, map control, corner glyphs; all in-shell by grep evidence, wiring left to B596), two not_design entries, and a status for all 50 labs: `composition-lab.html` exploring (ADR-334, B589, the lead's instruction), the other 49 `unaudited` until B596; `gui3.html` is in `not_labs` (the shell, not a bench).
  - `tools/design_chain_check.py` (new), wired into `./verify fast` beside `gen_gui3_controls --check` (ADR-180 §1). Tags: master, vendored, ledger, labs, numbers; coverage report-only (`AUDITED = False`, flipped by B596). 20 plants (one per finding kind, some kinds several), two must-read-clean controls.
  - `tools/gen_lab_index.py`: each card shows its chain status from the ledger (a lab without one reads "no status" in pink); `docs/design/index.html` regenerated, additions only.
  - `tools/golden_registry_check.py`: one `EXCLUDED` entry for `docs/design/design-ledger.json`, which its DATA rule (`docs/design/*.json`) found. A ledger, not an expected result; classifying a new file is the rule's designed path, and no existing file lost coverage.
  - `tools/ledger_owner_check.py` (a code-owned guard): `docs/design/design-ledger.json` added to `KNOWN_UNLISTED`, because its basename says "ledger" and three tools name it. It is not an approval ledger (the GUI session writes it with each hop), so it is not put under CODEOWNERS; the entry prints every run until the human rules whether it should be. This edit needs the human's code-owner review.
  - `docs/design-system/README.md`: the chain, the master's home, the publish procedure, the known drift, a new "Last verified" line (and an honest note that the older sections were last re-read on 2026-10-24).
- **The vendoring finding (the lead's report was not borne out):** `docs/design/arp-face/bundle.js` and `bundle.css` minus their first line are byte-identical to `master/components/bundle.js` and `bundle.css`, and `tokens.css` minus its first line is exactly what `design_vendor.tokens_css_body()` generates from `master/tokens.json`. The stamp on all three names `1793336699-65f2` (as commit `bdc7027` says), not `1793080392-2372`; `2372` appears only in the arp-face README as the earlier version. So the only drift is the stamp: the master moved to `b6a5` without changing these three bodies. Whether the bodies equal `65f2`'s cannot be checked (the repo never held that tree). Recorded as three `known_drift` entries of kind `stamp`, pinned to each file's sha256 and to the master version, citing ADR-336; the check prints them every run and goes red if the drift changes, grows or disappears.
- **Pre-existing duplicates found:** ROADMAP.md has two rows each for B147 and B155 (stale copies with different status cells, lines 7132/7134 and 7142/7143). No ADR has two primary headings (333 primaries, `## ADR-n — ` or `· `; ADR-113 is a `###`; ADR-120 to 122 have no heading of their own). The check pins B147 and B155 by count in `KNOWN_DUPLICATES`; fixing them is the lead's (ROADMAP is not ours), and the pin must move in the same PR.
- **Leak check on the master import:** `grep -r -I -i -F -f .leakcheck-names` over the tree: no hit; machine-absolute home paths, the owner's username and the owner's email: no hit. `./verify fast`'s leak, private-name and binary-hygiene gates then ran over the staged tree, green.
- **Alternatives rejected:**
  - **`lab-status` meta tags in each lab:** 50 lab edits, two of them in files other branches were editing (`gui3.html`, `composition-lab.html`), and a lab cannot honestly say it was harvested or retired: that is the chain's fact, so it lives in the ledger.
  - **Letting a stamp-only difference pass silently because the bodies match:** the stamp is the record of which master the shell runs; a pass would hide that the record is behind. The recorded entry names it instead, for the human.
  - **Comparing against `master@stamp`:** the repo holds only the current master, so the honest comparison is `vendor(master@VERSION)` with the drift written down.
- **Verify:** `nice -n 10 ./verify fast`, last, green; the tail is in the PR.
