# b446-w1b-hygiene-checks — binary identity scan (unwired), worktree-aware private-name gate, banned C calls, secret-file ignores

- **Queue item:** ROADMAP B446 (security overhaul), P1 Wave 1, item W1b. Lead brief of 2026-10-05 (horde lead session; the human: "let's proceed" after the P0 audit). Findings from the private P0 lane-4 report (hygiene, L4-H1, L4-M2, L4-M3, L4-M4), which is local-only and not cited by content here.
- **Why:** (1) the text leak gates read `git grep -I`, which skips binary files, so an identity string inside a tracked binary or archive is invisible to them; (2) the private-name gate read its untracked names file from the working tree, which agent worktrees never have, so it passed silently there; (3) nothing stopped unbounded C string calls or shell-outs entering `src/` or `h2/`; (4) no ignore coverage existed for secret-bearing file types.
- **What changed:**
  - `tools/binary_hygiene_check.py` (new, header `UNWIRED:`): scans tracked binary files (git's NUL test on index content), symlink targets and archives (zip incl. member names and nesting, gzip, bzip2, xz) for POSIX/Windows home paths, the dash-encoded form and the private names, with the vendored gate's placeholder allowances. Fail closed on an unreadable blob, an unopenable archive, an encrypted/oversized/over-nested member, an empty index. Prints path and kind only. Controls run every run (planted bytes of each kind, a real compiled-bytecode blob, zip/nested zip/gzip/member-name-only, corrupt zip, unreadable blob, empty index, and an end-to-end scratch repo with a planted binary file). UNWIRED because it is red on the tree until the already-tracked bytecode file is removed, which needs the human's approval; the wiring is one line in `fast()`, stated in its header.
  - `tools/private_name_check.py` (new, `WIRED: ./verify fast`) replaces the inline body of `private_name_gate` in `./verify`. The names file is resolved through `git rev-parse --git-common-dir` (the main checkout, the same from every worktree), falling back to this checkout's own copy. Absent everywhere: a visible WARNING and exit 0 by default (the file is machine-local by design, so CI and anyone's clone cannot have it and a hard failure would make `./verify` unpassable for them); `HORDE_REQUIRE_LEAKCHECK_NAMES=1` makes it a failure where the owner expects the file. Also: a git/PCRE error is now red (the old `|| true` read a malformed pattern as no hits), and a hit prints `path:line` only instead of echoing the matched line. Controls every run in a scratch repo + worktree with a fake name: planted name in a worktree whose own tree lacks the file is caught; the clean worktree reads clean; absent file is a visible warning; the strict switch turns it red.
  - `tools/banned_api_check.py` (new, `WIRED: ./verify fast`, wired in `./verify` after `portability_gate`): strcpy, strcat, sprintf, vsprintf, gets, system, popen (also `std::`/`::` qualified) as calls in code under `src/` and `h2/`, comments/strings/raw strings/char literals blanked first (digit-separator and backslash-continued-comment traps handled), snprintf allowed, member and other-class-qualified calls allowed. Controls: each name flagged, each in a comment/string/raw string/char literal not flagged, plus a planted line in a scratch repo layout reported exactly, and an empty layout read as blind (red).
  - `.gitignore`: `.env`, `.env.*` (with `!.env.example`), `*.pem`, `*.key`, `*.p12`, `*.mobileprovision`, `*.keychain*`. No tracked file matched (checked with `git ls-files`).
- **Evidence consulted:** `CLAUDE.md` (Gate wiring, Human gates); `.kit/kit-gates.sh` (`leak_gate` regexes and placeholder allowances; read only, not touched); autonomous `kit/vendor/kit-gates.sh` and `governor/leak_scan.py` (the dash-encoded form from kit 2.7.0); `verify` (`private_name_gate`, `fast()`); `tools/test_table_check.py` (rule 5, wiring detection by invocation); `tools/sluice_hold_check.py` and `tools/golden_pin_check.py` (header and control idiom); `tools/labs_preview.sh:39` (common-dir trick); the P0 lane-4 report sections L4-H1, L4-M2, L4-M3, L4-M4.
- **On today's tree (paths and kinds only):** `binary_hygiene_check` scanned 10 tracked binary files (the bench binary, five images, three state fixtures, one bytecode file) and reports exactly one hit: `tools/__pycache__/gen_gui_controls.cpython-313.pyc`, kind machine-absolute home path. `dist/cpu_bench` and the other eight binaries are clean, including for private names. No tracked archive exists. The `.gitignore` rules match no tracked file.
- **Alternatives rejected:** failing hard on an absent names file by default (makes `./verify` unpassable in CI and in public clones); scanning every tracked file byte-level instead of only what `git grep -I` skips (duplicates the text gates and has to replicate their path exclusions, so two policies drift); deleting or untracking the bytecode file (human gate, not given); adding the live `$USER` as a needle (in CI it is a common word and would false-positive); touching `.kit/` (open PR, kit-owned); porting the kit's 2.7.0 dash form into `.kit/kit-gates.sh` (kit-owned; the new binary check covers the form for binaries only, and L4-M3's text-gate gap is a kit sync, not this change).
