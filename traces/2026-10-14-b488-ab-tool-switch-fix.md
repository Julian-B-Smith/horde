# b488-ab-tool-switch-fix — the A/B page's Switch no longer seeks (corrects traces/2026-10-14-b488-ab-tool.md)

- **Queue item:** B488 (0), ADR-220 item 2; PR 1091.
- **Why:** the lead drove the page in a browser (24 audio elements, served over HTTP): Play started both elements in step (A 0.74 s, B 0.75 s), then one Switch 0.5 s later left A at 1.23 s and B at 0.45 s, readout "B 0.2 / 7.0 s". The first trace's open question (b) said the page had never been run in a browser; this is the cost of that.
- **Cause (entailed by the code, then confirmed by the control, not reproduced in a browser here):** the Switch handler flipped `which` and then SET `currentTime` on the element being made audible, while that element was playing. A seek on a playing media element is asynchronous, and the element landed at a stale time instead of the other one's. Both elements were already in step; the seek was the only thing that could move one.
- **Fix:** Switch now changes only `which`, the volumes and the label: no seek, no play, no pause. To keep the pair in step the silent element follows the audible one (`align`, on `timeupdate`, only while playing, when they differ by more than 20 ms), never the reverse; Play lines the silent one up with the audible one while both are paused (it used to set B from A, which seeks the audible element once B had been switched to).
- **Check without a browser:** `pageSwitchProbe` in `tools/h2_ab.mjs` runs the page's own script (`PAGE_JS`, exported) against a stub DOM with audio elements (`currentTime`, `volume`, `paused`, `play`, `pause`, every seek/play/pause logged): Play, 0.74 s, the silent element drifts 0.1 s, a `timeupdate` (the page must re-align the silent one), 0.5 s, Switch. Required: no media call on Switch, the new element within 20 ms of the other, volumes A 0 and B audible, nothing paused, the drift undone. Wired as control (d) of `--self-test`, so `./verify fast` and `full` run it. Its must-fails run every time on the page text with the Switch handler replaced: the old handler (a seek to the other's time) and a seek to 0. Both read red.
- **What the stub cannot see:** the browser's asynchronous seek itself (the stub's seek is instant). The control therefore judges "a seek was issued", the cause, and the time check only catches a seek to a wrong place. The fix is not shown to work in a browser by this check; the lead's browser run is the proof that remains.
- **Evidence consulted:** the lead's report in the coordinator message; `tools/h2_ab.mjs` `PAGE_JS` before and after.
- **Alternatives rejected:** a Web Audio path (the brief's original; still blocked on `file://`); re-seeking the new element in a `seeked` handler (an async dance the volume-only switch avoids).
- **Verify:** `./verify fast` and `./verify full` on the staged final tree; the result and commit are in the PR comment and the report. Result recorded in `.harness/last-verify.json`.
- **Open questions:** the lead should replay the Switch in the browser (it should now leave A and B within a timeupdate's worth of each other); whether `align` fights a browser that quantises `currentTime` coarsely (it seeks only the silent element, so the worst case is silent seeking).
