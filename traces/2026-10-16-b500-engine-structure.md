# b500-engine-structure — engine2's declared structure as data, and the gate that holds it to the spec

- **Queue item:** ROADMAP B500 (acceptance: "the declaration exists in the agreed format and place; horde's gate fails on a planted unknown spec id and on a planted missing signal-path stage; loupe renders it byte-identically on two runs. Verify target: `./verify fast`"). The last clause is loupe's to show. Brief: the horde lead, 2026-10-16, after loupe's answer (loupe PR #19, `integrations/hypersaw/response-engine-structure.md`, read through `gh api`; nothing written to loupe).
- **Why:** the human asked for a deterministic diagram of how the engine works, drawn by loupe. loupe draws from a declaration with no inference, so the declaration has to state only what `specs/SPEC-ENGINE.md` states, and nothing but a gate keeps that true as the spec moves.
- **What changed:**
  1. `engine2/structure/engine-structure.json` (new): format `horde.engine-structure/1`; 65 items (53 blocks, 12 slots; 54 engine, 11 external) nested host | instrument ⊃ engine ⊃ voice ⊃ oscillator ⊃ member; 85 edges (31 audio, 36 control, 6 event, 3 modulation, 9 observation); the 32 stages of §4.2's diagram mapped to items or edges; `spec.blob` 85bf7f5a165f314705473f2c209024c6128876ca; its own counts. Canonical form (sorted keys, items and edges by id). Written with a scratch authoring script that is not committed: the JSON is the artifact, `--canonical` re-prints it.
  2. `engine2/structure/README.md` (new): the format, its fields, the edge kinds' meanings, the nesting, the gate.
  3. `tools/engine2_structure_check.py` (new, `WIRED: ./verify fast`): format and fixed fields, unique ids, edge id = `<from>-><to>`, no dangling parent/endpoint/stage id, no parent cycle, scope consistent with nesting, edge kinds from the closed list, every cite parsed from the spec's own headings, requirement tables and bullets, every §4.2 stage (parsed from the diagram, in order) mapped, every RC-n cited by an item, counts true, the deny list (imported from `engine2_cleanroom_check.py`, one list), canonical form, spec blob current ("the spec changed: review the declaration, then update spec.blob"). Nine must-fail controls on in-memory copies; the report is computed twice and compared.
  4. `tools/engine2_cleanroom.sh`: `!/engine2/structure/` added to the recipe (BD-10: the builder reads the spec, not a reading of it). `tools/engine2_cleanroom_check.py`: a `diagram-only` tag and an eleventh must-fail control (a recipe that hands the builder the structure reads red). `engine2/README.md`, `engine2/CLEANROOM.md`: the new directory and the new exclusion.
  5. `./verify`: one block added to `fast()` after the engine2 block; the cleanroom block's comment says eleven controls. Nothing removed, skipped or relaxed.
- **Evidence consulted:** `specs/SPEC-ENGINE.md` in full (§1, §2, §4.1 to §4.3, §5, §6, §7, Appendix C); loupe's response (format, fields, nesting, edge kinds); `tools/engine2_cleanroom.sh`, `tools/engine2_cleanroom_check.py` (the deny list, the exclusion pattern, the control pattern); `tools/test_table_check.py` header (the WIRED grammar); `traces/2026-10-16-b497-cleanroom-tree.md`.
- **Alternatives rejected:** declaring osc 1 and osc 2 as separate subtrees (the spec defines one oscillator, "rows exist once per oscillator"; a `multiplicity` field says two); the brief sketch's cross-mod and feedback "between the oscillators" (C.14 runs them between members in a ring inside one swarm, so they are a self-edge on the member's loop tap); the sketch's serial base wave → blade 1 → blade 2 chain (§4.2 writes "base wave + blade 1 + blade 2" and C.11 makes the serial order depend on `stacking`, so both blades take the base wave and each may hear the other); a hand-kept list of §4.2 stages in the gate (parsed from the diagram instead, so a diagram edit shows up as well as the blob change); an edge from the allocator to the host for VO-10's lifecycle (the spec does not name who receives it).
- **Verify:** `./verify fast` on the staged tree; the exit code, its closing lines and the `.harness/last-verify.json` tree check are in the hand-back and the PR body. `python3 tools/engine2_structure_check.py` run twice: byte-identical output.
- **Open questions:** (1) §4.2 omits stages the spec states elsewhere: the oscillator's DC blocker (C.16, declared after the member sum) and the return from the internal rate to the host rate "before the per-voice filter slot" (not declared: its exact place is not stated). (2) IF-1's volume expression (a per-voice gain on the voice's output) and pan expression have no stage in §4.2; not declared. (3) VO-10's lifecycle and IF-1's load readouts are "published" with no named consumer; not drawn. (4) Gravity is drawn inside the voice, as §4.2 and §4.3 place it, though C.6 couples held voices; a self-edge on the voice's gravity block carries that. (5) The kinds `control` and `observation` for edges such as the allocator reading envelope levels (VO-2) are a classification the spec does not make; the README defines each kind.
