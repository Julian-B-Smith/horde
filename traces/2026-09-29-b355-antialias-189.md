# b355-antialias-189 — ADR-189 D1–D3 in the composed engine, each behind its own default-off flag; the SCALPEL lab plays them on; the ADR-187 divergence ledger starts

- **Queue item:** B355, read verbatim from `origin/lead-records-141:ROADMAP.md` (records PR #849) beside B310, B323, B325, B335 and B346, with ADR-189 and ADR-187. The human: "I ratify your recommended aliasing fixes, and we should skip the ones you recommended against."
- **Why:** B346 found where the composed engine's aliasing comes from and measured cures; ADR-189 ratified three of them as ADR-187 divergences from the SCALPEL oracle. Each had to land behind its own flag, default off (so the listening pass, the gauntlet and every fingerprint keep the heard engine), mirrored in the lab JS (the composed engine is the lab JS), measured with B346's own estimator, and ledgered.
- **B346 (PR #847) was not merged:** `origin/patchspace-alias-sources` was merged into this branch (the first commit) for `aliasConvergence` and `alias_sources.mjs`.

## What changed

- `docs/design/scalpel-horde-engine.js`: three `d` flags, all 0 by default: `aaCarrier` (D1), `aaXin` (D2), `aaLoop` (D3). A header block (ADR-189) and comments at each site state the why.
  - **D1** `voiceAA()`: first-order ADAA of the carrier (the oracle's `RazorCore.F`), on real member states only (probes and DC estimators stay plain, as in B346). It recomputes `cp` with `voice()`'s own expressions and returns `voice()`'s blend with the carrier replaced. `|Δcp| < 1e-7` takes the midpoint. Blade entry, the render that turns D1 on (`aOk`), and sine→saw take the plain sample. The carrier wrap BLEPs are removed in `scan()`: replaced, never stacked. `voice()` is static and called by name, so while a D1 render runs `RazorCore.voice` is swapped and restored in a `finally`, the oracle's own idiom (`RazorCore.mr/mn`).
  - **Half a sample of delay:** the ADAA mean lags the carrier content by half an internal sample. The base, the gate and the note are not delayed, so this is a fixed carrier-phase offset of `kk·dphi/2` inside each blade. It is uncompensated, because compensating needs a look-ahead (a real latency) or an extrapolation that FM and xin break. It is B346's measured form.
  - **D2** `scan()` override: the step's xin is added at both ends for carriers (B346's `blepXin`). With both D1 and D2 off it is `super.scan`.
  - **D3** `bladeStep()` and `loopIn()`: the loop taps `m.prev` (this sample) through a one-pole 3 kHz low-pass (`LOOP_FC`, coefficient in `setOS`). The oracle's xin is overwritten before the blade step reads it. The oracle's `render()` is untouched.
- `tools/labharness/composed_engine_check.mjs`: an AA section (17 rows) plus one DET row, 142 rows, green.
  - AA0: fingerprints of 4 presets pinned on main d443eb6, with flags absent and written 0; each flag on changes at least one (AA0c).
  - AA1: D1 on a periodic PM carrier and on a Band-limit-off carrier. The inharmonic residual (the power off the harmonic grid) falls ≥ 3 dB. The control, BLEPs off without ADAA, must read ≥ 3 dB above D1.
  - A FINDING line prints the plain-sync regression (below).
  - AA2: a constant xin fixture of 0.37. With D2 the residual equals the xin-0 case, −31.1 against −30.3, and D2 off reads −12.1. The control, a scanner reading −xin, reads −9.9.
  - AA3: broad#828 E5 at os 1, the line over its local floor at R/5 and R/3. D3 reads +0.3/+3.0. The controls: the oracle's loop reads R/5 +13.0, and D3's tap without the filter reads R/3 +18.2. An INFO line gives the filter over the old tap: +1.2.
  - DET: the toString() bundle with all three flags on renders the direct class's samples exactly.
- `docs/port/divergences.json` (new): the ADR-187 ledger. It has D1–D3 built and D4 `planned` (owner B356), and each entry pins the oracle's blob. `allOff` pins 4 preset fingerprints from main d443eb6 (engine blob 5f96285), and every entry carries its metric.
- `tools/labharness/divergence_ledger_check.mjs` (new, `WIRED: ./verify fast`, ~3 s):
  - rows: L1 shape; L2 the oracle blob, computed from the file's bytes with no git; L3 each flag exists with default 0 and each evidence path exists; L4 all off equals the pins; L5 each flag changes a scenario;
  - must-fail controls: C1 a missing flag, C2 a pin off by one digit, C3 a flag defaulting on, C4 an oracle pin off by one digit.
- `verify`: the ledger check is wired in `fast`, beside metrics_check (ADR-180 §1, an addition).
- `docs/design/scalpel-interface-lab.html`:
  - a header chip "anti-aliasing (ADR-189) ON/OFF", `LAB.aa189`, which defaults on (`?aa189=0` starts it off);
  - `oracleParams` maps the setting onto the three flags. It is a lab setting, not an SP row, so the patch space never samples it. Self-check scratch instances built from DEF hear the flags off, as the drawing does.
- `tools/patchspace/dependency_tree.json`: regenerated. `aaCarrier`, `aaLoop` and `aaXin` joined `unsampled` (fixed 0), and anchor lines drifted. There are still 0 structural disagreements.

## Alternatives rejected

- **D2 with the PREVIOUS xin at the interval start** (the oracle's collision idiom). The BLEP height probe (`hAt`) reads the current xin, so edges placed on the interpolated xin were probed off the edge, with height ≈ 0. Measured: at most 6e-7 of output change, so it corrected nothing. Built B346's form.
- **D2 shifting the crush scan too** (B346's harness did): crush steps do not move with xin.
- **Gating D1 on Band-limit:** 8 of B346's 17 helped have Band-limit off. The ratified cure is ungated. Left as a question.
- **D3 additions:**
  - a loop-gain bound: measured, it fails;
  - os: it only moves the line, at 1.5–3× the CPU;
  - a filter above 3 kHz: it leaves a line.
- **Text-patching the oracle in the engine** (B346's method): the brief asked for overrides.
- **Copying stepM, out, outSerial and voice:** about 180 lines, where swapping the one static is enough.

## Open questions

1. D1 on plain sync/ring carriers with Band-limit on is worse than the PolyBLEP it replaces (−30.3 → −22.8 dB). Restrict D1 to FM carriers, Band-limit off, and xin-moved carriers? This is a scope ruling on ratified text, so it goes to the human.
2. Should D1 follow Band-limit (off where Band-limit is off)?
3. D3's tap change is ratified, but on broad#828 the 3 kHz filter over the old tap also removes the cycle. Keep the tap change?
4. D3 is not a guarantee: a slow saw carrier under strong feedback can still chatter, attenuated, whenever xin's jump × 2π × 3 kHz exceeds the carrier's rate.
5. D1's CPU is about 1.1× in this implementation, against B346's ≈ 1.0×. The wrapper runs `voice()` and then recomputes cp. A C++ port would fold it in.
