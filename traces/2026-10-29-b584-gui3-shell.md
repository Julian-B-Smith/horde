# b584-gui3-shell — GUI 3's prototype, first slice: one wired shell, generated controls, a stub engine behind one adapter

- **Queue item:** B584 (ADR-316, amending B302's gate; ADR-315 for the chrome). Acceptance, verbatim: "(1) a shell page in `docs/design/` (or the path the design system's README prescribes) with page navigation for Main / Osc 1 / Osc 2 / Sub / Noise / Filters / Mod / Morph / Mix / FX / Random / Settings, built only from the design system's vendored bundle; (2) a generator that reads the engine's parameter table (SPEC-ENGINE §5, or a machine-readable form of it already in the tree) and emits the shell's control list, with a check in `./verify fast` that every engine parameter reachable on a page appears in the shell (B302's `gui_reach` idea) and that no control lacks a parameter, with plants; (3) a no-audio engine stub behind one adapter with the engine's interface (set parameter, morph position, mod routes, patch state, observation view), and the seam where the WebAssembly engine plugs in documented; (4) the Sub and Noise pages built (B514's rulings, SPEC-ENGINE §5.5 and §5.6); (5) the page chrome per ADR-315: the docked morph pad while morph is on, with a hide toggle, the hover info box fed from parameter descriptions, and right-click 'Open in manual' as a stub; (6) seeded and deterministic, no audio, `./verify fast` exit 0."
- **Why:** the human asked for one global interface lab built from the design system's modules that connects every wire without the audio engine (ADR-316). This slice makes the wiring real and gated, so the remaining page labs land as pages of one shell.
- **What changed:**

Twelve tabs; the docked pad (bundle `XYPad` and `CornerChips`) only while morph is on, hidden by a Pad toggle, no space with morph off; a fixed info box; a right-click menu with Reset to default and Open in manual (stub); a seam panel; eight in-page self-checks, each with a control. Every parameter control is built in `mountControl` from `GUI3_DATA.pages`; the file names no key.
  - `docs/design/gui3/layout.json` (new): page and group per key; Sub and Noise designed key by key in chain order, with PA-8's live-when; draft pages by block.
  - `docs/design/gui3/params.json`, `shell-data.js` (new, generated): SPEC-ENGINE §5 as data (330 rows, 317 host, 13 reserved) and the control lists.
  - `docs/design/gui3/engine-stub.js`, `device.js` (new): the stub engine (`GUI3Engine.METHODS`) and the adapter (morph, routes, history).
  - `docs/design/gui3/README.md` (new): map, gates, the seam and what the WebAssembly wrapper owes it, design-system proposals, gaps.
  - `tools/gen_gui3_controls.py` (new, WIRED `./verify fast`): the generator and its gate, ten must-fail controls.

- **Measured:** the generator's expansion equals §5.8 on every count it states (164 table rows, 330 parameters, 317 host, 18/4/10/48/30+2/28/28 per table). The seam check's plants each went red for their own reason (`--verbose`). Headless Chrome (file://, `#sub`, `#noise,morph`, `#osc1,morph`, `#sub,morph`): all eight in-page self-checks OK, no console error from the page.
- **Alternatives rejected:**
  - **Hand-typing the parameter list**, or a JSON with no parser: the brief and ADR-316 want a control unable to exist without its parameter; parsing the spec's own tables, checked against §5.8's counts, keeps one source.
  - **The engine stub holding the morph and the undo stack:** RC-11.1 and RC-11 put the morph position and the history outside the engine, so they sit in `device.js`; the stub carries only what the engine owns, so the WebAssembly build can replace it one for one.
  - **Embedding the spec's git blob in the outputs** (as `engine2/structure` does): every spec edit would turn the gate red even when §5 did not change. The freshness check compares content instead.
  - **Drawing the menu, the info box and the dock locally** (the page-chrome lab's way): ADR-316 forbids it. They are assembled from `hd-card`, `hd-btn` and `hd-pill`, and listed as proposals.
  - **Hiding inert controls:** PA-8's inert controls are drawn idle, never hidden, so a wrong condition can never make a parameter unreachable.
- **Verify:** `nice -n 10 ./verify fast`, exit 0. `.harness/last-verify.json`: commit 0fd29e4 (HEAD before this commit; the change set was uncommitted), tree 0701f61b, 2026-10-29T20:49:40Z; `gen_gui3_controls` and `gui3_seam_check` GREEN inside it. A first run was RED on `tolerance_registry_check` (an epsilon `<= 1.0 + 1e-12` in the generator). The epsilon was removed (an exact range test in x, then a clamp), not registered, and the outputs regenerated byte-identical. The only edit after verify is this line.
- **Open questions:** in the report to the lead (morph-off semantics, whether morph position and morph on are undoable, the seam's sync/async contract and whether `observe()` maps to IF-10 or RC-8, the widget rule, where the machine-readable §5 should live, the PA-8 transcription for designed pages). B302's `gui_history_check` and `presentation_check` are not yet built for GUI 3; this slice checks history on the knob props path and one real click only.
