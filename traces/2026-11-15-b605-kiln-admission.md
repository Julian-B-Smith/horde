- **Queue item:** B605 (ADR-351).
- **Why:** the human ruled (ADR-351, 2026-11-02) that Kiln's two modules are admitted by the same
  harness as Scape, with A4's causality clause read as a leading-edge threshold (nothing above
  -60 dB of the response's peak before latency - 1) and A6 judged against the module's own
  reference renders where there is no exact dry setting. Built as ruled; the drive's A4 reads FAIL.
- **Evidence consulted:** integrations/kiln/brief-admission-adapters.md §1-§6 and reference-adapters/;
  response-state-budget.md (A19 sizes); Kiln origin/main bbdf290 (clean export, never its live
  checkout); tools/admission/{module.h,harness.cpp,plants.h,scape_adapter.cpp,CMakeLists.txt};
  tools/admission_check.py; run logs in the session scratchpad (b605-run1.log, b605-run2.log).
- **Alternatives rejected:** detecting dryExact at run time (a broken exact module would read clean on
  the reference path: it is declared by the adapter); adopting Kiln's 1e-12 ramp bound (an unruled
  tolerance: the tap and the twin make the ramp readings exact); vendoring FOUNDATIONS' header (the
  2026-08-15 ruling keeps it out of the tracked tree: located like a module tree instead); a pin or a
  wider window or threshold to make the drive pass (the human's ruling, not an implementer's).
- **Verify:** `python3 tools/admission_check.py` (Scape, Kiln EQ, Kiln drive) exit 1: Scape GREEN, Kiln
  EQ GREEN, Kiln drive RED on A4 only (early[default], early[Default]: offset 2 is -18.38 dB re the peak,

  `./verify full` NOT run: it would run admission_check and go red on the drive's A4.
- **Open questions:** (1) the drive's A4 needs the human: a different window or threshold, or a pin.
  (2) A4 window is `latency - early` (= the ruled latency - 1 for the drive, one sample stricter than
  the literal text for a module with no early residual); the literal `latency - 1` is one sample looser
  than before for those: confirm which. (3) kCausalThresholdDb = -60 was registered through
  `tolerance_registry_check --approve ... ADR-351` (the ruled value, not a widening): lead to confirm.
  (4) ROADMAP B605's "Shriek's half-band meets the same clause" does not hold by measurement: its own
  half-band reads -70.4/-38.1/-17.2 dB at offsets 0-2, peak at 4, declared 3 to 5. (5) pre-echo is

## Amendment 2026-11-15, same change set: the human's poll (ADR-402, to be recorded by the lead)

- **Why:** the poll kept -60 dB and shortened A4's window: a module that DECLARES an early residual is
  judged at offsets < latency - 3 (kCausalMarginSamples, new), one with none at offsets < latency; every
  report line names the window judged. Kiln's drive reads -72.9 dB at offset 0 (Shriek's half-band -70
  per the earlier measurement), so it now passes. Both constants re-registered with
  `tolerance_registry_check --approve <id> ADR-402` (entries regenerated by the tool, governs text a
  sentence). The pre-echo plant moved from kD = 3 to 4 so its leak lands inside the drive's window:
  it fires on Scape, Kiln EQ and Kiln drive (drive: offset 4, -39.8 dB, before latency - 3).
- **Also fixed:** a partial skip is named in the last stdout line and in a `KIT-GATE skipped: PARTIAL,
  not measured: ...` receipt line (the kit's receipt knows only skipped/cases, so partial reads as
  skipped, never as a full pass); the docstring's claim that RealtimeSanitizer reads zero under nice is
  replaced by what was observed (A10 PASS, malloc plant fired, under `nice -n 10`); dryExact() stays a
  declaration.
- **Verify:** `admission_check.py` exit 0 (Scape, Kiln EQ, Kiln drive all GREEN); with a nonexistent
  HORDE_FOUNDATIONS_DIR exit 0 and PARTIAL line naming Kiln EQ and Kiln drive; `nice -n 10 ./verify
  fast` exit 0 (horde 577b1478 + this change set, uncommitted). This supersedes open questions 1, 2, 3
  and 5 above; 4 and 6 stand.

  `partial` state would need the autonomous repo.
