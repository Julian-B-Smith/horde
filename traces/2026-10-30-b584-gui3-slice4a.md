# b584-gui3-slice4a — GUI 3, slice 4a: the parameters outside the engine that already have a manifest

- **Queue item:** B584, slice 4a (ADR-330, on `lead-records-373`, horde PR #1281). Stacked on `origin/spec-round-48` (horde PR #1280, spec round 48, not merged: Appendix D and D.2's thirteen morph settings).
- **Acceptance (the lead's brief, from ADR-330), verbatim:**
  1. "`tools/gen_gui3_controls.py` reads these sources beside SPEC-ENGINE §5, namespacing keys so they cannot collide with engine keys (e.g. `morph.*` as the spec names them, `arp.*`, `fx.<module>.<key>`); it applies the same widget rule and the same refusals (unknown key, unplaced host parameter, reserved row placed); its `--check` in `./verify fast` covers every new source, with plants (a module key left unplaced is red; a vendored snapshot whose provenance row is missing is red)".
  2. "The Morph page shows D.2's settings as generated controls (keep the existing hand panel's corner/snapshot functions). The FX page shows one ordinary card per module in rack order … holding that module's parameters as generated controls … Arp: … its own draft page 'Arp'".
  3. "module and Arp parameters go through the adapter to the rack/device side (RC-5, IF-7; Arp as the device's MIDI module), not through the engine's setParam; the stub holds them. Morph settings go to the morph resolver (IF-12's calls), not to the engine. Extend `tools/labharness/gui3_seam_check.mjs` to prove each path, with a must-fail control each".
  4. "The bank, info box (descriptions from each manifest where it has one; otherwise say 'no description in the module's manifest') and right-click stub work on the new controls".
  5. "Seeded, deterministic, no audio; `nice -n 10 ./verify fast` exit 0 …; a trace entry in `traces/`; README 'Last verified' updated".
- **Why:** the human asked why the GUI 3 shell showed none of the parameters outside the engine (ADR-330). Slice 1 had scoped the shell to SPEC-ENGINE §5, so this slice reads every source that has a machine-readable manifest today.
- **What changed:**
  - **`tools/gen_gui3_controls.py`.** It reads:
    - Appendix D.2's table, with the step division's options taken from RC-7.4's table, and the host/non-host split taken from D.2's own sentence;
    - Arp's vendored params snapshot, with the pattern options from the bank snapshot;
    - Echo's `spec/params.json`, cross-checked against its lock;
    - the lockfiles of Scape, Shriek and Bulwark (per face).

    Keys are namespaced (`morph.*`, `arp.*`, `fx.<module>.<key>`, `fx.bulwark.<face>.<key>`). The same widget rule and refusals apply; Shriek's retired row is reserved. A provenance table check (sha256 per vendored file) is new. Three new plants make 17: a module's keys left unplaced, a vendored file with no provenance row, and one whose bytes changed. `params.json` stays §5 alone; `shell-data.js` carries every source with `target` and `source`.
  - **`docs/design/gui3/vendor/`:** five verbatim copies (Echo ×2, Scape, Shriek, Bulwark). Arp reuses `../arp-face/params.snapshot.json`, which is byte-identical at Arp's current HEAD.
  - **`docs/design/gui3/engine-stub.js`:**
    - `ResolverStub` (D.2 settings and the position, IF-12) and `DeviceSideStub` (the rack's modules and the MIDI module; it refuses a key it does not own or one sent to the wrong side).
    - `SyncTransport(engine, resolver, device)` with `morph`, `position`, `rack` and `midi` messages.
    - The `io` and `io-cut` laws (`docs/proposals/module-io-gain.md`).
  - **`docs/design/gui3/device.js`:**
    - Each value goes to its owning side (`MSG`), and the position goes to the resolver.
    - `morph.on` and `morph.audible` read and write the adapter's morph state, so the chrome switch, the generated control and the resolver agree.
    - Routes reach continuous module and Arp rows, and refuse the morph's settings.
  - **`docs/design/gui3.html`:**
    - Three stubs behind one transport.
    - FX module cards with a labelled `.viz` screen-placeholder inset.
    - The Morph page's hand "audible corner" picker is removed: D.2's `morph.audible` is now a generated control there.
    - Device-class knobs are drawn `locked` with `g` through the device. Before this, D.2's knobs showed no value: `S.editing` returned null for D rows.
    - The info box shows the description's source, the target side, undeclared laws and labels, and "a page choice, not a host parameter".
    - A new eleventh self-check covers the new sources' paths, bank, info box and right-click.
  - **`tools/labharness/gui3_seam_check.mjs`:**
    - A `paths` test: rack, MIDI module and resolver each hold their values, and the engine's refusal counter stays put. It has three plants, one per side routed to the engine.
    - `laws` now covers every continuous row.
    - The routes and mapdrop plants were widened, because the pv test alone refuses stepped engine rows. That makes 18 tests and 19 plants.
  - **`layout.json`:** `sources`, `owed`, the Morph, FX and Arp pages' groups, and PA-8-style live-when for the morph's Quantum and Stepped settings. It was re-serialised with two-space JSON, which is why the diff is large.
  - **`docs/design/gui3/README.md`:** the provenance table, the sources table, proposals 16 and 17, and the gaps; "Last verified" updated.
  - **`verify`:** comments updated to the new counts only. `docs/design/index.html` regenerated.
