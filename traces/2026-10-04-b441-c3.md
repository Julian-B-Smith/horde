# b441-c3 — specialised member kernels: 10 kernels plus the generic path, bit-identical

- **Queue item:** ROADMAP B441 phase 2, candidate C3 (the phase-1(B) audit's §C3). Lead brief of 2026-10-04 (horde lead session, after C1 #937 and C2 #939 merged). The acceptance text is the C3 note on the lead's records branch (`lead-records-189`): "both self-digests 543/543 with no re-pin; parity check green; a coverage counter shows every specialisation hit by at least one scenario; a must-fail control (swap one `+`'s operands in one kernel) moves only that kernel's rows; a libm census diff of the hot functions; timing under protocols B441-1/2/3 for the heavy class plus one preset per kernel; `./verify fast` and `full` 0. Land kernel by kernel, each with a digest A/B."
- **Why:** the discrete selectors (`mode`, `hot`, `mirror`, `fmType`, `mshape`, `b2on`, blade 2's view, `aa`, `aaCarrier`) are copied from `d` at a render call's start and nothing writes them again until the next call, yet the member step re-tested them every oversampled step through `js::sel`/`js::truthy`, un-inlined `wave`/`voicePlain` calls, and `fmStep`/`scan` calls that return at once. A kernel compiled for the call's combination removes all of that without touching one floating-point expression.
- **Design (one body, not copies):**
  - The member step (`renderCall` → `stepMember` → `stepBlade` → `out` → `voiceOut` → `voicePlain` → `wave`/`mod`, and `fmStep`) is templated on a kernel descriptor. A blade descriptor `BK<mode, hot, mirror, fmType, mshape>` fixes some selectors; `kAny` leaves one to run time. Every templated read of a fixed selector goes through `kv<V>(x)` / `kt<V>(x)`, which return the constant, so its `switch` or test folds. Nothing else in the body changed: the expressions, their operands and their order are the generic path's.
  - `pickKernel()` runs once per `renderCall` (the dispatch `switch` in `renderCall`), never per member. A kernel is picked only when every fixed selector `==` its constant, read from `d` exactly as `renderCall` copies it into `s` and as `fillG2` derives blade 2's view. `==` lets a `-0` pick a `0` kernel; that is exact because every read of these fields is a comparison, `js::sel` or `js::truthy`, none of which tells `-0` from `+0`. NaN or a non-integral selector matches no kernel and runs the generic path.
  - Inside a specialised kernel `wave`, `mod` and a fixed blade's `voicePlain` are force-inlined (`waveAt`/`modAt`/`voiceOutK` choose); the generic path (id 0) keeps every out-of-line call it made before. The per-function libm census of the generic functions is identical to `origin/main`'s, names apart.
  - Dead calls: `fmStep` folds to `return 0` where the blade fixes `fmType` 0 or a non-FM mode (its first line returns before any side effect). `scan` is not called where `BK::scanDead` proves it would return at its first test (a fixed mode and carrier that are neither a saw/square/ramp carrier nor a crush): the ring and FM kernels. `scan` has no side effect before that return (`engine.h` `scan`).

- **Must-fail control** (planted locally in `outK`, never committed; reverted with `git checkout h2/engine/engine.h`): in kernel 6 (`fm+b2`) only, `y += voiceOut(blade 2) - gb` regrouped as `y = (y + voiceOut(blade 2)) - gb`. Both self-digests went RED, exit 1: `518 of 543`, TOTAL `263e6dbb376d42cf`, 25 rows changed, the same 25 in both builds. **All 25 are kernel-6 rows** (`--kernel-rows`: 31 scenarios run kernel 6; every scenario runs exactly one kernel). The 6 kernel-6 rows that stayed green are Collision bite and Occlusion sweep (×3 phrases each), which are serial (`b2mix` > 0) and so take `outSerial`, not the planted line.
  - **Deviation from the letter of the criterion:** "swap one `+`'s operands" cannot fire. IEEE 754 addition is commutative exactly (`a + b == b + a` bit for bit), so a literal operand swap is a no-op and its control would stay green by construction. The control used is the nearest perturbation that rounds differently: regrouping one three-term sum (`y + (v − gb)` → `(y + v) − gb`), which is what the audit's "non-associative under rounding" intends.

- **Alternatives rejected:**
  - **Hand-written kernel copies.** Every copy is a place an expression can drift; one templated body with `kv`-folded selectors cannot drift from the generic path, and the generic path is literally the same body at `kAny`.
  - **A function pointer or `switch` per member step.** The brief forbids per-member selection, and an indirect call per step would cost back part of the gain.
  - **Force-inlining the generic path too.** It would change the generic path's code shape (four inlined `voicePlain` copies in `out`) for no tested gain; the generic path keeps its calls, so its census is unchanged.
  - **Per-call int caches of `js::sel` in the generic path.** In the kernels `js::sel` folds to a compile-time constant, which is stronger; the generic path was left untouched on purpose.
  - **Specialising blade 2 per kernel.** It multiplies the kernel count; left for a measured need.
- **Verify:** `./verify fast` exit 0 at `dc0eb1b` + the template commit's tree (before any kernel). `./verify fast` and `./verify full` on the head that adds this trace (they run the parity check and both self-digests, COVERAGE included) are recorded in the PR body with `.harness/last-verify.json`.
- **Open questions:**
  1. **A second 48 kHz round is owed:** it was refused twice (22:04), so 48 kHz rests on one pair. The 44.1 kHz figure has three pairs (two of them with calibration drift, stated).
  2. **No scenario switches kernels mid-render.** Every one of the 543 scenarios runs exactly one kernel (`--kernel-rows`), so the dispatch's switch between kernels at a call boundary (e.g. `b2on` toggled between calls) is exercised by construction, not by a row. The kernels share all state and each call re-derives its kernel from `d`, so this is entailed, not verified. Is a scenario that toggles `b2on` or `mode` mid-note worth adding at the next scenario-set change (a re-pin under case b)?
  3. **`./verify` echoes only the self-digest's `PASS  (control|KEYSELF|SELFDIGEST)` lines**, so the new `PASS  COVERAGE` line is judged (a red COVERAGE fails the run) but not echoed. Adding `COVERAGE` to that grep is an edit to `./verify` that adds output only; left to the lead.
  4. **The coverage of ring (3 scenarios), crush+b2 (4) and ring+b2 (6) rests on P/ presets alone**, no T/ row. Bit-identity there is proven only on those presets' phrases.
  5. **`measure_h2_engine --also`** is new in this PR (measurement only, UNWIRED): the frozen cells and the row format are unchanged, but the doc's §1 "How to run it" names it.
