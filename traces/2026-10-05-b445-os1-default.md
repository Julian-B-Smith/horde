# b445-os1-default — os 1 as the device default and os 2 as HQ: measured, rendered for the listening gate, the flip prepared but not landed

- **Queue item:** ROADMAP B445 (ADR-191). Lead brief of 2026-10-05 (horde lead session; the human: "Oversampling rec ratified. I had always intended it as optional", then "B445 proposal ratified"). Acceptance, verbatim from B445: "the device default is os 1 and os 2 is selectable and saved per preset; aliasing measured at os 1 vs os 2 on the heavy class (B346 method) and reported; a listening gate with the human before the default flips; JS lab and C++ together (ADR-187), with any digest re-pin listed (preferred: none, by defaulting the device parameter rather than the core); timing at the default for the ledger presets; `./verify fast` and `full` 0."
- **Why:** after C1–C3b, Glass horde pad is still ×1.88 over the B439 slice, and os 2 → 1 was the largest single lever (audit D1). ADR-191 makes os a quality option. This PR measures what os 1 costs in aliasing and saves in CPU, renders the pairs the human hears, and prepares the default flip as one change the lead lands after the gate.

## Where the default lives, and how it flips

- **There is no C++ device yet.** `horde2::engine::Engine` is built only by tools (`tools/h2_engine_*`, `tools/measure_h2_engine.cpp`), and horde 2's preset system is "planned" (`docs/H2-PLAN.md`, `presets`, B395). The engine core's default is `setOS(2)` (`h2/engine/engine.h:149`), which the brief puts out of scope and every pinned scenario relies on.
- **The product default today is the SCALPEL interface lab's `DEF`** (`docs/design/scalpel-interface-lab.html:1643-1650`): the oracle's constructor values (`{ os: REF.os }`, so 2) with `LAB_DEF` written over them. `DEF` is what the lab boots with (:1753), what a preset loads over (`applyPreset`, :8277: `Object.assign({}, DEF, pr.params, …)`), what INIT resets to, and what double-click resets a control to (:4416, :4461, :4495). The lab already has the switch: row 88 `Oversample`, 1× / 2× (:1568). `os` is in `ORK`, so it reaches the engine (:1637).
- **Per preset:** a preset that carries `os` keeps it on load, because `applyPreset` writes the preset's own keys over `DEF`. No bench preset carries `os` today (0 of 83). The lab has no "save preset" path, and horde 2's preset format does not exist yet (B395). `tools/port_legacy_presets.mjs` already maps legacy row G5 to `os` (`:189`). So "saved per preset" holds as far as the lab and the porter go; the real save path is B395's (open question 2).
- **The flip (chosen form: prepared as one change, not landed; os 2 stays the lab default until the gate).** Three edits:
  1. `os: 1` in `LAB_DEF`, with its reason. ACCOUNTING row G5 agrees: horde's oversample "ships OFF" (`docs/scalpel/ACCOUNTING.md:226`).
  2. Row 88's 2× labelled "2× (HQ)".
  3. A re-pin of the lab's golden blob, `6abf848…` → `77ccee779baa09ce9fddb9d6527ecc0d68e77a8f`, in `h2/README.md` (the pin source `golden_pin_check` and the parity check's PIN row read) and in `docs/port/h2-engine.md`'s pins table.
- **Why the flip needs a re-pin.** The lab is one of the composed engine's five pinned goldens; B407's metadata edit broke CI for exactly this reason (#905, LIBRARY L0073). It is a CONTENT pin, not a digest re-pin. `tools/h2_engine_render.mjs` reads only the `ENV_PRESETS` literal from the lab (`:83-88`), so `LAB_DEF` changes no scenario and no digest. The self-digest references carry the lab's blob in an `# ORACLE` comment header. On a moved oracle, `h2_engine_selfdigest_check` prints a NOTE, not RED (`tools/h2_engine_selfdigest_check.cpp:580`), so after the flip both self-digests should stay 543/543 with that NOTE. This is entailed from the code; the flip was not run under `verify full`.
- **The patch:** `local/listening/b445/os1-default-flip.patch` (gitignored), reproduced here so the record holds it:

## Aliasing: os 1 against os 2 (B346's estimator, at 44.1 kHz)

- **Tool:** `tools/patchspace/os_quality.mjs conv` (new, UNWIRED). It imports `metrics.mjs` `aliasConvergence` and `spectrum` unchanged and restates, with the rate as a parameter, the three pieces of `alias_sources.mjs` that read `space.mjs`'s fixed `SR = 48000`: the render with the pre-decimation capture, `decimGain2`, and the spectrum call. Presets are played as the parity scenarios play them (`presetCmds`: the params, gain 0.35, the smoothers snapped), with `os` written over them. B346's notes are A1, E5 and A5, with seed 0xB316. **One departure:** the 12 000-sample window starts at max(0.05 s, A + 0.05 s), because B346's 0.05–0.3 s window is inside Glass horde pad's (900 ms) and Breathing pad's (1500 ms) attack.
- **Must-read controls, at 44.1 kHz, every run:** blades off on a sine base reads `-120`, clean (must be clean); blades off on a raw saw base (aa 0) at E5 reads `-18.7`, folding (must be over). Both fired as required.
- **Threshold: -33.4 dB**, `gauntlet.mjs` `THRESH.aliasConvDb`, imported. It is the only threshold in the repo fitted to the human's own ratings on this estimator (B351: v2 ratings, n = 33, AUC 0.88, agreement 0.79). It was fitted at 48 kHz on the gauntlet's E5 window, so here it is a reference line, not a ruling.
- **One number per preset = its worst note** (all 36 rows are in the run's JSON lines):

  | preset | os 1: worst, dB (class) | os 2: worst, dB (class) | os 2 − os 1 | os 1 vs −33.4 | os 2 vs −33.4 |
  |---|---|---|---|---|---|
  | Glass horde pad | −20.7 at A5 (dynamics) | −28.5 at A5 (dynamics) | 7.8 dB | over | over |
  | Crushed bells | −12.1 at A5 (dynamics) | −52.1 at A5 (folding) | 40.1 dB | over | under |
  | Breathing pad | −14.6 at A5 (dynamics) | −120 (clean, all three notes) | > 100 dB | over | under |
  | Fold over sync | −20.8 at A5 (folding) | −30.2 at A5 (folding) | 9.4 dB | over | over |
  | Crush vs FM | −42.8 at A5 (folding) | −50.1 at A5 (dynamics) | 7.3 dB | under | under |
  | Sync over fold | −24.5 at A5 (folding) | −35.8 at A5 (folding) | 11.3 dB | over | under |

  E5 rows, os 1 / os 2: Glass −30.8 / −44.2, Crushed bells −37.1 / −61.1, Breathing pad −22.1 / −120, Fold over sync −24.0 / −34.6, Crush vs FM −55.7 / −51.9, Sync over fold −27.7 / −43.2. At A1, every preset is under the gate at both settings.
- **Reading it.** os 1 crosses the gate on 5 of the 6 heavy presets, and os 2 on 2 (Glass horde pad and Fold over sync, both at A5). Crushed bells and Breathing pad change most. On Breathing pad (noise blade 2) and on Glass and Crushed bells at A5, the os 1 excess is class "dynamics": it converges with os, but the source test does not explain half of it as folding. A hypothesis, untested: the noise blade and the rate-scaled blade caps (`kCap = 0.45·sr·os/fi`, B346) make the os 1 sound differ from finer renders in ways that are not aliasing. The estimator counts every such difference, so the human's ear decides.

## The listening gate

- `node tools/patchspace/os_quality.mjs wav` into the main checkout's `local/listening/b445/` (gitignored): six pairs, `0N-<preset>-os1.wav` / `-os2.wav`, 44.1 kHz, 24-bit stereo, the same seed and notes. Each file is peak-matched to −1 dBFS. The phrase is the preset's chord in its register (`h2_scenarios.mjs` `notesFor`'s table), held past the attack, then E5, A5, E6. After matching, the level differs by ≤ 0.1 dB in every pair except Breathing pad, where os 1 is 0.64 dB louder. The README there lists each pair, its estimator figures and what to listen for. Pair 5 (Crush vs FM, under the gate at both settings) is the control pair.

## CPU at the default (Layer-E, B441-3)

- `tools/measure_h2_engine.cpp` gains `--os N` (ledger mode): it writes `os` over every cell after its preset, and the row's `os` reads N. Without it, the cells and rows are the frozen ones.
- The ledger's §2b "B445" section (`docs/port/cpu-ledger.md`) has the full tables and the r1 44.1 kHz LEDGER rows. Four back-to-back pairs (44.1 kHz r1 and r2, 48 kHz r1 and r2), the frozen seven plus Crush vs FM and Sync over fold, all at `1bce33a`, 13:23–13:37. **os 1 saves 34–40 %** (1.52–1.67× raw), against §3's 43–45 % at `deb4d1a`. A hypothesis: C1–C3b already shrank the per-member-step frame that os multiplies. The os 2 rows reproduce C3b's after figures (Glass 43.01 against 42.59; Crushed bells 24.10 against 24.09).
- **Against the 34 % slice at os 1** (8 voices, min-spec ×1.5 ASSUMED, 44.1 kHz r1 / r2): Glass horde pad **40.3 / 40.8 % (over, ×1.19–1.20)**; Breathing pad 29.8 / 29.9; Crushed bells 22.5 / 22.7; Crush vs FM 10.6 / 10.6; Fold over sync 10.4 / 10.4; Sync over fold 10.3 / 10.3 (all under). At 48 kHz: Glass 43.9 % (×1.29), Breathing pad 32.4 % (under).
- **Guard and refusals:** the first attempt (13:20) waited 7 times behind `Creative Cloud Helper` at 96–99 % of a core. I stopped it by hand, unrun, to run `./verify fast`. In the eight passes, guard waits were 0–12 per pass. `--force` was never used.

- **Evidence consulted:** ROADMAP B445, B441, B346 and B351; DECISIONS ADR-191 and ADR-187 (items 3, 5, 7); the audit's §D1 (gitignored `local/cpu/2026-10-04-h2-engine-optimisation-audit.md`); `docs/port/cpu-ledger.md` §1, §2b and §3; `h2/engine/engine.h` (`Engine()`, `set`, `setOS`); `docs/design/scalpel-interface-lab.html` (`R('os'…)`, `ORK`, `LAB_DEF`/`DEF`, `applyPreset`, `presetCheck`, `scratch`); `tools/h2_engine_render.mjs`, `tools/h2_scenarios.mjs`, `tools/h2_engine_selfdigest_check.cpp`, `tools/golden_pin_check.py`, `tools/patchspace/{alias_sources,metrics,gauntlet,space}.mjs`, `tools/port_legacy_presets.mjs`, `docs/port/divergences.json` (D4's planned shape), `docs/scalpel/ACCOUNTING.md` (G5, row 58, D2), and commit 62fdc9a (the B407 revert).
- **Alternatives rejected:**
  - **Changing the core's `setOS(2)`:** out of scope, and it moves every scenario and both self-digests.
  - **Landing the flip in this PR:** ADR-191 and the brief put the listening gate first.
  - **`os` in the lab's boot and preset paths instead of `DEF`:** the lab's double-click reset and its "changed from default" view read `DEF`, so a default anywhere else would contradict itself.
  - **Running `alias_sources.mjs` unchanged:** fixed at 48 kHz through `space.mjs`; changing that shared constant would move every patch-space tool.
  - **A `divergences.json` entry:** ADR-191 calls this a ledgered divergence, but the ledger describes the ENGINE, and the id scheme is the lead's (open question 3).
- **Verify:** see the PR head's run below. Before the docs commit, `./verify fast` exited 0 at `1bce33a` (`{"target":"fast","exit":0,"git":"1bce33a","ts":"2026-10-05T17:23:16Z"}`).

## Open questions

1. **The listening gate is the human's.** Then the lead lands the flip patch (one commit; it re-pins the lab's content blob only, with no digest re-pin) or asks for a change.
2. **"Saved per preset" in the product** waits on B395's preset format: it must carry `os` (absent = the device default, 1). Should the bench presets that need HQ carry `os: 2`? `reference/scalpel/data/presets.json` is protected, so that would be lab- or B395-side.
3. **A ledger entry for ADR-191?** `docs/port/divergences.json` lists D4, a non-engine "planned" divergence, as a precedent. Which id should the os default take, and should it be added before or with the flip?
4. **Glass horde pad is still over at os 1** (×1.19–1.20, and ×1.29 at 48 kHz), and os 2 already aliases on it at A5 (−28.5). os 1 alone does not close the heavy class. D2 (fdlibm plus SIMD) or a voice cap remain.
5. **After the flip, the lab's in-page self-checks** (`runChecks`, 162 rows; not run by `./verify`) run their `DEF`-based scratch engines at os 1. The exactness checks already pin `os: 1`, but the rest have not been re-run at os 1. Run the lab's checks once after landing.
6. **`space.mjs`'s defaults** (the gauntlet and the random-patch sampler) read the engine's os 2, not the lab's `DEF`. After the flip, patch-space measurements are at HQ, not at the device default. Is that intended?
