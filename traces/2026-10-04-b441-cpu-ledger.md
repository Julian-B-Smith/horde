# b441-cpu-ledger: the frozen CPU protocol, the baseline ledger and the stage attribution of `h2/engine`

- **Queue item:** ROADMAP B441 phase 1(A) (the row is on the records PR #928, `lead-records-183`, open when this was written; it is not yet on main).
- **Why:** The human (2026-10-04) asked for research, optimisation audits and experiments to cut the engine's CPU weight. Phase 2's one-experiment-per-PR loop needs a fixed yardstick, and phase 1(B)'s audit needs to know where the time goes. This PR measures and changes no output.
- **What changed:**
  - `tools/measure_h2_engine.cpp`: still UNWIRED. Checkpoint 4's replay mode is unchanged. It gains:
    - `--ledger`, protocol B441-1: 48 kHz, 128-sample blocks, the preset's os, `poly 8`, 1/8/16 voices, interleaved best of 5, checkpoint 4's calibration loop and its ratio, a `getloadavg` guard at 3.0, and `LEDGER {json}` rows;
    - `--sweep`, a coarse one-voice ranking of the whole bank;
    - `--hold`, a render loop for `sample`;
    - `--stages`, built only into the new target.
  - New CMake target `measure_h2_engine_stages`: the same file with `-DH2_ENGINE_STAGES`, `-O3 -ffp-contract=off` (`h2_rules_check` GREEN, 11 h2 targets).
  - `h2/engine/engine.h`: eight measurement-only skip sites behind `H2_ENGINE_STAGES`. Every other build folds them to `false`, the `H2_ENGINE_FAULTS` pattern.
  - `docs/port/cpu-ledger.md`: the protocol, the ledger, the attribution and the interpretation.

- **Measured (Layer-E, this Mac, Apple M3, 2026-10-04, head `deb4d1a`):**
  - **The ledger, 8 voices, % of one M3 core, then min-spec ×1.5 (ASSUMED):**
    - Quarter sync: 3.71, then 5.6 (under the slice).
    - The oracle defaults: 16.05, then 24.1 (under).
    - Harmonic stack: 24.22, then 36.3 (OVER).
    - Fold over sync: 25.47, then 38.2 (OVER).
    - Crushed bells: 47.71, then 71.6 (OVER).
    - Breathing pad: 53.10, then 79.6 (OVER).
    - Glass horde pad: 72.32, then 108.5 (OVER).
  - **The run conditions:** calibration 190.2 ms, load 2.69–3.38. An earlier run of the same engine code agreed on every cell to within 1.6 %.
  - **The attribution** (subtractive toggles, cross-checked with `sample`). On Glass horde pad and Crushed bells:
    - the blade evaluation is 52–62 % (44 % by sampling);
    - the per-step frame (remainder) is 22–26 %;
    - PolyBLEP is 11–15 %, almost all of it edge search (0.0055 edges per member-step);
    - `couple` + `spread` is 1.5–5.8 %;
    - the DC estimate is 3.6–4.2 %;
    - the swarm control tick is 0.5–0.8 %; the phase advance, the decimation biquads and the output stage are each under 1 %;
    - going from os 2 to os 1 saves 43–45 %.
  - **Load averages seen** across the session: 2.2–10.1. The guard waited out every reading above 3.0, and gave up twice (exit 3, no figures taken) while system indexing ran.
- **Alternatives rejected:**
  - **Hand-rolled timers around each stage:** the M3's 24 MHz counter is too coarse for ~100 ns member-steps, and reading it in the hot path perturbs what it times.
  - **`xctrace`:** it needs Xcode (`xcrun` cannot find it).
  - **Op counts alone:** they cannot price a transcendental against a branch.
  - **Ablation alone:** its shares interact (sums of 99–106 %). So `sample` is the independent cross-check.
  - **A C++ JSON reader for `presets.json`:** that would be new parsing code. The tool reads the presets from the parity stream instead, so it plays them exactly as the parity check does.
- **Verify:** `./verify fast` exit 0 on this tree before the commit, and re-run on the committed head, which `.harness/last-verify.json` records. The PR body quotes that file verbatim. A trace cannot carry its own commit hash.
- **Parity (the normal build):** `build-release/h2_engine_parity_check --full-from <stream>` (this PR's engine.h, built normally), exit 0. It printed: "h2_engine_parity_check: GREEN — 540/543 scenarios at parity (rms < 1e-06, max < 1e-06, events and readouts identical), 3 excluded as chaotic (onset window 384 frames, events, readouts, bounded and finite), 0 miss parity, 0 red". The mean bit-exact share was 37.00%, the same figure `h2/README.md` records, so no sample moved.
