  human's request of 2026-09-19: *"a sine with a slightly phase-shifted third

## The derivation of the defaults (acceptance (a))

Rendered one period of `y = sin θ + a·sin(3θ + φ)` on a grid and measured the
two positive lobes (scratch `b155-bump/derive.mjs`, `refine.mjs`; the shipped
core then reproduced the analytic value to five decimals via
`tools/golden/extract_core.mjs`).

- **The mechanism.** Two positive lobes appear when the third harmonic's crest
  lands inside the sine's — `a > 1/9`. **φ breaks the symmetry between them and
  its SIGN decides which leads**: φ < 0 leads with the big one, φ > 0 with the
  small one, φ = 0 makes them exactly equal. Half-wave antisymmetry
  (`y(θ+π) = −y(θ)`) is structural for two odd partials, so the negative half
  always mirrors the pair; a bump shape asymmetric between the halves is not
  reachable with this formula.
- **φ = −0.25 rad** for "slightly smaller": trailing/leading = **0.8823**
  (1.09 dB down). Measured alternatives: φ = −0.15 → 0.928 (imperceptible),
  −0.20 → 0.905, −0.30 → 0.860, −0.35 → 0.839 (reads as noticeably smaller, not
  slightly).
- **a = 0.35** for "reads as two bumps": the trough between them sits at
  **0.637** of the leading peak — deep enough to see at a glance. a = 0.30 gives
  0.712 (a nick in one crest, not two bumps); a = 0.40 gives 0.566 (a deeper
  notch and more third-harmonic buzz than a sub wants). 0.35 is also mid-range
  in the exposed 0…0.6.
- **Measured on the shipped core** at MIDI 24/36/48/60: ratio 0.88231 / 0.88232
  / 0.88237 / 0.88238, trough fraction 0.63694…0.63752, peak 0.74998…0.75002.
  Analytic value for the same (a, φ): 0.882307.
- Render of the default period: scratch `b155-bump/bump-one-period.png` (the
  dashed rails are ±1, so the headroom L7 leaves is visible).

## Normalisation — the alternative rejected

Normalised by the **analytic bound `1/(1+a)`**: `|sin θ + a·sin(3θ+φ)| ≤ 1 + a`
for every (a, φ), so peak ≤ 1 is true by construction and costs one divide.
Rejected: peak-exact normalisation. It has no closed form for a two-partial sum,
so it needs a ~180-transcendental scan in `_recalc` — a path the mod matrix
drives per block, since both rows are morphable — and a scan is only
*approximately* a bound (a coarse scan that undershoots the true peak breaks the
very invariant the criterion states). The price is stated rather than hidden:
the worst peak over an 8 × 9 (a, φ) grid is 0.999999 and the quietest 0.707262,
so the bound leaves up to **3.01 dB** unclaimed — spec limit L7, ruling R7 for
the human.

## Alternatives rejected

- **Peak-exact normalisation** — above.
- **Gating or fading the third partial above f0 = sr/6** so the band-limiting
  claim held at every pitch. A hard gate clicks on a sweep through the boundary
  and a fade is a curve nobody has asked for; the boundary is three octaves
  above where a sub lives, so it is recorded as L6 and *pinned by a test*
  instead of engineered around. If the module is ever played up there, the fix
  is priced in the limit.
- **One "bump" macro walking a curve through (a, φ)** instead of two controls.
  The lab is where the axis is being learnt; a macro chosen before the human has
  played both axes is a guess. Filed as ruling R8.
- **A seventh entry in the `default:` case** — the render switch keeps noise on
  `default` and gives bump an explicit `case`, which is the smaller diff and
  leaves the existing line untouched.
