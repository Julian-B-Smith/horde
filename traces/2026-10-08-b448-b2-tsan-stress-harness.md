# b448-b2-tsan-stress-harness — multi-thread stress harness for parameters, presets and state

- **Queue item:** B448 Wave B item B2 (ADR-197 risk row 2); also B446 Tier C's first step.
- **Why:** risk row 2 names "ThreadSanitizer over a stress harness that hammers params, presets, and save/load during render" as its armor, and no such harness existed. Added `tools/tsan_stress.cpp` (audio thread rendering with host events and params_flush; one main thread interleaving editor and host operations from a seeded mulberry32 schedule, bounded by iteration counts) and `tools/tsan_stress_check.py` (builds it under `-fsanitize=thread`, runs a planted-race detector proof, a control and a full run; red on any report). Declared `UNWIRED:` per ADR-180 §1; not wired into `./verify` or `tools/sanitize_oracles.sh`.
- **Evidence consulted:** `docs/strategy/blind-spot-armor.md` (risk row 2); `tools/sanitize_oracles.sh` and its call site in `.github/workflows/ci.yml` (read only); `CMakeLists.txt` HYPERSAW_SANITIZE block (instruments host executables only, never the impl library — why the harness is one TU including the shell); `src/hypersaw_clap.cpp` (params_flush, state_save/state_load, applyStateJson, initState, enqueueParam/drainQueue, gui_create's hostIf lambdas); `tools/hostile_events_check.cpp` (host-side instantiation pattern); `tools/test_table_check.py` (declaration grammar).
- **Alternatives rejected:** linking HYPERSAW-impl like the other probes (TSan would not see the shell's accesses, so it would read clean for that reason); one thread per category (CLAP main-thread calls and the editor share one thread, and the editor queue is single-producer, so extra producer threads would manufacture reports no host can produce); a `.sh` check (test_table_check scans `*_check.py`, not `.sh`, so its declaration would go unchecked).
- **Verify:** see the verify block of the handoff; `./verify fast` with the git hash in `.harness/last-verify.json`. The check itself is RED on this machine for a toolchain reason: the Command Line Tools 16 TSan runtime segfaults during its own initialisation on macOS 26 (a five-line program reproduces it; ASan fails a CHECK the same way), so the planted race is not reported and no plugin verdict is produced. The harness runs to completion unsanitized (control and full, seeds 1-6).
- **Open questions:** where to obtain a working TSan (newer Xcode/CLT, a local Linux run, or Homebrew llvm — each a human gate); the harness has not yet been compiled on Linux.
