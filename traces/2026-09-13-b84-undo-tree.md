# b84-undo-tree — shell-owned undo history (snapshot tree) + HISTORY page

- **Queue item:** B84 (ADR-160). Dispatch brief
  `briefs/2026-09-13-b84-undo-tree.md` on `lead-records-5`.
- **Why:** The 1.0 definition of done carries undo (human 2026-09-11: "we
  desperately need an undo history"); ADR-160 ratified the design 2026-09-13.
  Shell-owned because a GUI-side history dies with the window and cannot see a
  preset change made while the editor is closed, and because the shell already
  produces the snapshot (`stateJson`) and receives every gesture bracket
  (ADR-121). One node per GESTURE, never per write; host parameter events and
  automation never mark.

## What landed

- `src/undo_tree.h` — pure, framework-free `UndoTree`: 200-slot ring of
  `{live, parent, tick, born, label, json}`, all strings reserved at
  construction. Eviction takes the oldest slot and re-parents its children to
  its parent, so the structure is a FOREST; `push` dedups against `current`,
  `restore` is navigation only so the next push forks.
- `src/hypersaw_clap.cpp` — `undo` member + `undoMark` / `undoService` /
  `undoGoTo` / `undoStep` / `undoTreeJson`, the five mark sites
  (`applyStateJson`, `cornerApply`, `morphCapture`, `state_load`, the
  `hostIf.gesture` END), and `hypersaw_debug_undo`. Nothing in `process()`,
  `drainQueue` or any RT path changed.
- `src/gui/hypersaw_gui.h` / `hypersaw_gui_common.h` — four `GuiHost`
  functions, four binds, `hzFrame` pumps `undoService()` first.
- `src/gui/gui2.html` — `pg-HIST` page + tab, depth-column renderer, Undo/Redo,
  Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z, ~5 Hz refresh while visible only.
- `tools/undo_check.cpp` + its `CMakeLists.txt` target — standalone, UNWIRED.

## Three judgement calls, and why

1. **The morph toggle is marked at `hostIf.setParam`, not at `morphOn =`.**
   The brief named the `morphOn` param handler. That handler lives in
   `applyParam`, which is the AUDIO thread and is also where host automation
   lands — a mark there would both touch the RT path (criterion 3: "the audio
   thread touches nothing") and give automation a node (criterion 2 and
   ADR-160 (3), which forbid exactly that). The main-thread GUI seam gives the
   same node with neither cost. The checkbox's own `pointerup` already marks
   through the gesture latch and `undoMark` keeps the LAST label, so the pair
   still collapses to one node, labelled "morph on"/"morph off".
2. **A root node ("start") is taken at the first pump.** Criterion 2 says
   nodes are created only by marks. But every mark's snapshot is the state
   AFTER the edit it names, so without a root the first edit has no parent and
   Undo is dead until the second one. The root is taken on the first
   `undoService` with a drained queue; a mark already pending dedups against
   it, so an editor opened onto a just-loaded patch shows one node, not two.
3. **`cornerApply` and `morphCapture` share the label "corner N"** (1-based),
   as the brief specifies. The tick distinguishes two visits to one corner.

## Measurements

`stateJson()` is **5,269 bytes** at defaults and **10,774 bytes** in the
adversarial case (all 323 continuous params at full `%.17g` precision, morph
field present). ADR-160's "~35 KB × 200" was pessimistic by ~3.3×. The 48 KB
reservation is kept as headroom for the parameter table to grow; the ring is
9.6 MB of main-thread memory. `undo_check` prints both numbers every run and
asserts the adversarial case fits, so the reservation cannot silently be
outgrown.

## Alternatives rejected

- **Deltas instead of snapshots** (B43(b)'s preference). ADR-160 overruled it
  after ADR-159: a positional delta over a derived order is precisely the shape
  that broke there, and a snapshot restore is one existing call, provably
  bit-identical through the fixture corpus.
- **A second gesture latch for undo.** B43(e) and ADR-121 already bracket every
  drag; the END callback is the listener, no new plumbing.
- **A `treeJson()` on `UndoTree`.** The shell owns every other `*Json()`
  builder; putting it there keeps the core free of serialisation.
- **A grandparent-adoption test.** Unreachable by construction: parents are
  always created before children, slots are handed out in creation order, and
  eviction takes the oldest — so a node's parent is always evicted (and its
  edge already rewritten to `kNone`) before the node itself. `undo_check`
  asserts the invariant that IS reachable instead: after churn every parent
  edge points at a live node or `kNone`.

## Open questions

- **`undo_check` is not wired into `./verify`** — a gate is the human's
  decision (charter). Proposed: run it in `fast` beside `state_check`; it takes
  under a second and needs no golden.
- **The gesture-END mark is not covered headlessly.** `hostIf.gesture` is
  reachable only through `gui_create`, which needs a window; `undo_check`
  drives the shell-side mark the lambda calls. The lambda itself is one line
  and is evidenced by reading, not by an oracle.
- **`hzFrame` does not pump on a page that wants no feed.** `frameFetch`
  returns early on `!want`, and HISTORY wants nothing. The page polls itself
  while visible and every undo bind pumps, so a node is never owed at the
  moment someone asks — but a mark made on a feedless page does sit pending
  until something asks. That is the documented "collapse" behaviour, not a bug.
- **ADR-160's snapshot size should be corrected** to the measured 5.3 KB /
  10.8 KB (lead-only file; reported, not edited).
- **Not built, by design:** app-support persistence (criterion 5 — history is
  in-memory for 1.0).
