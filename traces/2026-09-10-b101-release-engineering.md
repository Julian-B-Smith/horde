# b101-release-engineering — CHANGELOG, LICENSE options, CI artifacts/release/sanitizers, robustness matrix

- **Queue item:** B101 (ROADMAP §"1.0 — DEFINITION OF DONE", ratified 2026-09-10; brief from the lead organ, same day).
- **Why:** 1.0's definition of done names release engineering as a deliverable and an external audit had verified it absent (no LICENSE, no CHANGELOG, zero tags, no CI artifacts, no notarization, no sanitizer runs). Everything a subagent can prepare without a human act is prepared here; the human acts (LICENSE choice, tagging, Apple credentials, Reaper/Bitwig loads) are left as clearly-marked gaps, not guessed.

- `CMakeLists.txt` — `HYPERSAW_SANITIZE` (cache STRING, default OFF): adds `-fsanitize=<list>` to EXECUTABLE targets only; OFF is bit-inert (verified: `flags.make` for `parity_check` and `HYPERSAW-impl` contain no `fsanitize` in `build-release`; `CMakeCache` shows `OFF`). New `robustness_matrix` target.
- `tools/robustness_matrix.cpp` (new, diagnostic, not gated) — real plugin through the CLAP factory, 4 rates x 7 buffers: allocations in `process()` (rtsafety_probe's counter), NaN/Inf, subnormal output, peak, held level (must-read-loud control), tail RMS, cost; plus the denormal section (8 s tail in windows, FTZ/DAZ detection, a synthetic subnormal-chain control that says whether the CPU can show a stall at all). Its own allocation-counter can-fire control caught a real probe bug: clang elided a paired `new`/`delete` expression, so the first draft's control read NO; a direct `::operator new` call is what it plants now.
- `tools/sanitize_oracles.sh` (new) — parses the oracle list and golden generators from `./verify` (no second list), configures with `HYPERSAW_SANITIZE`, builds only existing targets, runs each oracle with UBSan halt-on-error and ASan leak detection off.
- `docs/ROBUSTNESS.md` (new) — the published matrix with the measured numbers, sample-rate/RT gates quoted, sanitizer table, denormal section, host-load table with Reaper/Bitwig UNVERIFIED — human.

On the shipped platforms it is allocation-free by library implementation detail (measured 0/0 on macOS and MSVC), not by construction.
