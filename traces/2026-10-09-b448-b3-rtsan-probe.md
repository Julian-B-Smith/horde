# b448-b3-rtsan-probe — RealtimeSanitizer probe of the real process(); one violation found, check left unwired

- **Queue item:** B448 Phase 1 Wave B item B3 (ADR-197 risk row 1, re-scoped by ADR-199: Homebrew LLVM,
  macOS-local in `verify full`, no workflow edit).
- **Why:** `rtsafety_probe` counts `operator new` over parameter ids 1-99 and sees one kind of offence.
  RealtimeSanitizer intercepts the libc layer (malloc from any caller, locks, I/O, sleeps, static-init
  guards) and names the source line. `tools/rtsan_probe.cpp` is one TU that includes the shell source and
  runs every host audio-thread call (process, params.flush, start/stop_processing, reset) inside
  `__rtsan_realtime_enter/exit` over a seeded schedule; `tools/rtsan_check.py` builds and runs plant,
  control and full with the sanitizer compiler (`HORDE_SANITIZER_CXX`, else `brew --prefix llvm`; absent
  means WARNING and SKIPPED, exit 0, no verdict).
- **Result (seed 1, 1400 blocks; seed 7, 7000 blocks gives the same set):** plant reported (1), control
  clean (0), full RED with ONE violation site: `swarm_core.h:118 anchorTables()`, the function-local
  static `AnchorTables`, built on the first rendered voice behind libc++abi's `__cxa_guard` mutex. Four
  sanitizer stacks (guard acquire and release, each a lock and an unlock), all kind "lock", reached via
  `renderSeg` swarm_core.h:1084 <- `renderSpan` hypersaw_clap.cpp:8522 <- `process` hypersaw_clap.cpp:8838.
  The comment above it says "Static tables, built at load - never on the audio thread"; the code builds them
  at first use. No allocation, syscall or blocking-call violations. Coverage printed by the probe: 397 of 397
  enumerated params written, 27 voice-steal bursts, both engines, morph blend and quantum, intent bus, mod
  matrix edits, MIDI/expression/transport, 28 state loads and 33 preset loads staged on the main thread.
- **Evidence consulted:** `docs/strategy/blind-spot-armor.md` row 1; ADR-199
  (`origin/lead-records-215:DECISIONS.md`); `tools/rtsafety_probe.cpp`; `src/hypersaw_clap.cpp` process()
  8748-8955, drainQueue 5518, handleEvent 8208, params_flush 9297; `verify` full() rtsafety_probe wiring;
  `tools/tsan_stress*.{cpp,py}` on branch `armor-tsan-stress` (read only: same single-TU build approach);
  `tools/test_table_check.py` (declaration within the first 40 lines) and `tools/weakening_check.py`
  (every `UNWIRED:` text counts).
- **Calibration:** (1) `--plant` (wrapper only) reported; (2) a malloc planted in a COPY of `src/` at the top
  of `Plugin::process` was reported at that line (hypersaw_clap.cpp:8765 in the copy). The first in-process
  plant used a `std::vector` nothing read back and was NOT reported, because the compiler elided the
  allocation; a volatile sink fixed it. Same trap as the non-elidable plant in rtsafety_probe's comment.
- **Alternatives rejected:** a warm-up block before the scope (hides exactly this class of finding);
  `[[clang::nonblocking]]` on process (edits src/, out of scope); suppressing or baselining the one report
  (brief forbids); reusing `build-release` (the sibling harness takes flags.make from its own build dir, so
  a Release rebuild cannot shift this probe's flags).
- **Verify:** `./verify fast`, exit 1, git 79199a4 (`.harness/last-verify.json`). The ONLY red line is
  `weakening_check: FAILED ... tools/rtsan_check.py: unwired 0 -> 1`, the expected +1 for an UNWIRED check;
  not approved here, it needs the human. `test_table_check` GREEN (the declaration is read). `verify full` is
  unchanged because the check is not wired.
- **Follow-up (lead's call, same day): fixed and wired.** `(void)hypersaw::anchorTables();` in
  `plug_activate` (hypersaw_clap.cpp, main thread; `clap_plugin.activate` is [main-thread] and process()
  follows it), with a comment citing B448 B3. `src/swarm_core.h` untouched because `h2/cores/swarm/swarm_core.h`
  is a byte-identical lift. Other function-local statics reachable from `src/*.h` and the shell, grepped:
  none with a dynamic initialiser on the audio path. `computeSpectrum`'s `static thread_local` buffers and the
  `static std::string` JSON getters are editor-thread; `kWanted`, `cornerLetter`'s `L[]` and
  `swarm_core.h:1508 JP[7]` are constant-initialised (no guard). Re-run: plant 1, control 0, full 0 on
  seed 1/1400 (via the check) and seed 7/7000 (probe run directly). `tools/rtsan_check.py` header is now
  `WIRED: ./verify full`, called right after `rtsafety_probe`. `./verify full`: exit 0, git 8969889 -
  parity_check 156/156 (worst 4.262e-09), state_check, stability_check (60 s), hostile_events_check,
