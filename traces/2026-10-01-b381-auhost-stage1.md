# b381-auhost-stage1 — an offline AudioUnit host, dry-run on Apple's AUs and horde only

- **Queue item:** B381 stage 1, read verbatim from `origin/lead-records-156:ROADMAP.md`. The lead's brief was dated 2026-10-01.
- **The human, verbatim (B381's ruling):** "Yes, though it may end up benefitting from my oversight". This was about the host loading the installed Serum 2, and it is why stage 1 loads no third-party plug-in.
- **Why:** B381's CPU, quality and imitation parts all need the same thing first: a host that renders an AU offline from a deterministic script and times it. That host also has to time horde's own code through the same loop. This stage builds the host and proves it on units nobody needs to oversee.

## What was built

- `tools/auhost/auhost.cpp` is a single C++ file built with AudioToolbox and CoreFoundation, using Command Line Tools only.
  - **Commands:**
    - `--list` reads the registry only.
    - `--params` prints id, name, range, default and unit.
    - `--render` takes a JSON script: note on/off, bend, CC, program, and params by id or name at sample frames or seconds. It writes a float32 WAV and times each `AudioUnitRender`. It reports median, p90, p99 and max % of real time per block, and the median divided by voices.
    - `--horde` runs the same scripts through `h2/cores/scalpel/razor_core.h`. The core holds 8 voices, so above 8 the host runs `ceil(voices/8)` cores.
  - **Determinism:** each repeat is a fresh instance compared with repeat 0. The report gives the max |diff| and the first differing frame.
  - **Host tempo:** a fixed 120 BPM tempo callback drawn from the sample count.
  - **Thread priority:** a QoS user-interactive hint for the render thread.
  - **Calibration:** a calibration loop (B236's pattern) runs first.
- **The third-party latch.** The host refuses to instantiate anything that is not manufacturer `appl`, or not exactly `'Hsaw' 'LfTk'`, unless `--allow-third-party` is given. The manufacturer code alone is not enough, because other installed plug-ins share `LfTk`, so the first draft of the latch was too loose. It was tightened before any run. The refusal was demonstrated on this repo's parked SWARM-FX (`aufx Swfx LfTk`), before instantiation: `REFUSED ... exit=1`.
- `tools/auhost/analyse.mjs` is the bridge to `tools/patchspace/metrics.mjs`. It reads a WAV and runs `analyse()`. With `--ref`, it also runs `aliasing()` against a 4x-rate render, cut to the same seconds and using the same bin width. It adds no metric of its own.
- `tools/auhost/scripts/` holds the chord, the keyboard sweep with a bend ramp, and the 1-, 8- and 16-voice scripts. `tools/auhost/README.md` is the map.
- `CMakeLists.txt` adds the `auhost` target under `if(APPLE)` with `-O3 -ffp-contract=off`. `h2_rules_check` now counts it among its 7 h2 targets, GREEN. The host is **UNWIRED** (its header says so) because it is a tool, not a gate. It sits outside `test_table_check`'s census by location: `tools/auhost/` is not `tools/*_check.*`.
- `docs/design/serum-gauntlet-protocol.md` is the plan for stages 2–4, for the human's review.

## Findings (MEASURED)

1. **On Apple's DLSMusicDevice, the first instance in a process is a different instrument from the next ones.** Test: `chord.json` with 4 repeats and no priming.
   - Repeat 0 differed from repeats 1..3 by max 5.034e-02, starting at frame 9175 (0.191 s). Repeats 1..3 were identical to each other. This happened on 3 of 3 process runs.
   - With the reverb send at −120 dB, the difference was 5.96e-08 from frame 9177.
   - With one discarded priming render (`--prime 1`, now the default), all four repeats were bit-identical.
   - **The cause is a hypothesis:** process-wide state that the plug-in builds on its first instance. The fix is measured.
   - The voices-1/8/16 scripts were bit-identical even without priming. So "deterministic" depends on the script, which is why it is measured on every run.
2. **The timing figures are clock-quantised.** Every median is an integer multiple of 0.0015625 % of a 128-sample block, which is one 41.67 ns `steady_clock` tick. Examples: 0.2766 = 177 ticks, 0.2812 = 180 ticks, 0.2875 = 184 ticks. So the installed horde AU and DLS reading the same 1-voice median (0.2812 / 0.2730) is a tick-level coincidence. It was checked by re-running, and both rendered audible C4 (`rootInterval 0`).
3. **Median divided by voices is the wrong per-voice figure for stage 2.** DLS reads 0.277 % per voice at 1 voice and 0.030 % at 16. Its fixed cost dominates, and its marginal cost is about 0.013 % per voice. So the protocol fits a slope.
4. **The aliasing pipeline discriminates**, with the 48 kHz test and 192 kHz reference cut to 0.25–2.25 s:
   - DLS saw-lead chord (GM 81), reverb off: `aliasDb −30.842`.
   - Must-read-low control, AUSampler's near-sine default: `−78.287`.
5. **Effects are not driven.** Apple's delay (`aufx dely appl`) returned −10876 (`kAudioUnitErr_NoConnection`) because the host feeds no input bus. `--render` now refuses non-`aumu` types up front.

## Dry-run timings

48 kHz, 5 repeats, warm-up 8 blocks, prime 1, 3 s. Figures are median % of real time per block. Calibration: 180–184 ms.

| unit | buffer | 1 | 8 | 16 voices |
|---|---|---|---|---|
| DLSMusicDevice | 128 / 512 | 0.277 / 0.269 | 0.370 / 0.352 | 0.478 / 0.449 |
| AUSampler | 128 / 512 | 0.030 / 0.022 | 0.180 / 0.127 | 0.345 / 0.235 |
| horde AU (installed, legacy) | 128 / 512 | 0.281 / 0.273 | 1.766 / 1.754 | 3.492 / 3.524 |
| h2 SCALPEL core (defaults, N 5, os 2) | 128 / 512 | 1.800 / 1.800 | 13.095 / 13.089 | 26.819 / 26.802 |

All of these runs were bit-identical across repeats.

- **Alternatives rejected:**
  - AVAudioEngine manual rendering. It adds a graph between the clock and the unit, and the C API gives sample-offset MIDI directly.
  - A JSON library. That would be a dependency; a 60-line parser covers the script format.
  - Splitting blocks at parameter events. Timed calls would then vary in length; offsets are passed instead, and the limit is stated.
  - Feeding effects an input. Not needed for stages 2–4 (FX off).
