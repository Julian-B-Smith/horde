# b639-morph-bridge-1-0 — the test plug-in plays round 61's 1.0 morph

- **Queue item:** B639 (the horde lead, 2026-11-07: "update the B636 bridge so morph plays properly in Live"), on the builder's engine 6cd98b5 (round 61, spec blob 423878a0, harness header from test-author fd9a8f2).
- **What changed** (`tools/engine-preview/`):
  - **The 1.0 resolver's events forwarded:** `MorphEvent::Kind::Level` becomes `EventType::MorphLevel` (`integer` = source, `value` = g); a `Param`'s `landing` passes into `Event::landing`. The generic count of unknown kinds (`morph.unknown`) stays for later kinds.
  - **IF-10's heard level** of each source (`observe_morph_level`) and the resolver's `ResolverCounters` ride every frame of the `morph` member.
  - **The position is two host parameters,** `morph.x` and `morph.y` (round 61's D.2 rows, IF-11), the last two, under the plug-in's own ids 0xA00001 and 0xA00002, since no morph lockfile is committed. The page's `position` message sets them as a touch (begin, value, end each). `set_position()` takes the event's sample.
  - **MO-21 to MO-24's inputs:** page messages `waypoints`, `waypointLaw` and `lock`, forwarded to `set_waypoints`, `set_waypoint_law` and `set_lock`, held in the morph state, echoed in the frame once applied, fed to every new resolver, and saved (state version 4; versions 1 to 3 still load).
  - **Save current sound (MO-25)** reads `resolved_value`, `resolved_ratios` and `level_sent`, and bakes a fading source's g into its level key's dB gain, or stores the source off below −60 dB (ADR-377 A2).
- **Evidence consulted:** SPEC-ENGINE on main (IF-4, IF-10, IF-11, IF-12, MO-20 to MO-27, PA-7); the harness header diff 4f4afd4..6cd98b5; the B636 bridge.

The five presets stay bit-identical with the morph off. The recorded frames on 6cd98b5 are byte-identical to main's own build's.
