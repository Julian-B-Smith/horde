# B455 H2: the Stop gate judges the tree

- **Date:** 2026-10-10
- **Author:** the lead, first-hand. Agents are chartered never to edit `.claude/`; the human approved this edit in ADR-206 item 3.
- **Why:** the 2026-10-10 repo audit, finding H2 (`docs/audits/2026-10-10-repo-audit.md`). The closing gate had two blind spots:
  - It trusted `.harness/dirty`, a marker only the Edit and Write tools set. An edit made through the shell (a generator, a stream edit, a patch, a merge) never set it.
  - It read `.harness/last-verify.json` only if the file existed. A fresh worktree has none, so a session there could finish without `./verify` ever having run.

## What changed
- **`.claude/hooks/stop-gate.sh`:** after its two existing tests, the hook now compares the tree with the commit the record judged.
  - It looks at tracked changes, commits made since, and new untracked files that are not ignored.
  - Any such file newer than the record blocks the stop, and the message names up to five files.
  - With no record, the base is where the branch left `origin/main`, and any change blocks.
- **Why mtimes, not the record's commit hash:** agents verify and THEN commit, so the record names the parent commit while the files are exactly what was verified. Comparing hashes would force a second run for nothing.
- **Known limit:** a file deleted after verify has no mtime to read, so a pure deletion is not seen by the hook. CI sees it. The check holds this as its LIMIT row.
- **`tools/stop_gate_check.py`** (new, in `verify fast`): runs the real hook file in scratch repositories against 16 situations.
  - Control 1: a hook that never blocks must fail all 9 block rows.
  - Control 2: the hook as it stood before must fail exactly the 7 tree-state rows.
- **`verify`:** one wired block after `deny_hook_check`.

## Evidence
- `stop_gate_check: GREEN (16 rows; a never-blocking hook fails all 9 block rows; the pre-change hook fails exactly the 7 tree-state rows)`.
- The real hook on this worktree:
  - with edits and no record, exit 2, naming the three changed files;
  - after `./verify fast`, exit 0;
  - after a one-byte shell edit to a tracked file, exit 2, naming it;
  - with the file restored, exit 0.
- `./verify fast` exit 0.

## Not changed
- `.claude/settings.json` and `posttool-dirty.sh` are untouched. The marker stays as a second signal.
- The hooks are harness-layer files, so the same change is worth a brief to the kit. Not filed yet.
