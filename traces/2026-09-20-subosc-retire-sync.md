# subosc-retire-sync — hard sync leaves the sub; its id 4011 is retired IN PLACE

- **Queue item:** B184
- **Why:** The human, told the sub's Hard Sync toggle was wired off and inert:
  *"Please [remove] hard sync from the sub. I can't imagine a scenario in which
  it would be useful, and I didn't realize it had entered the spec."* That
  sanctions the protected edits to `specs/SPEC-SUBOSC.md` and
  `reference/subosc.html`. The feature is gone from the core, the lab, the spec,
  the panel and the goldens; the **id is not**, because the SUB block's map is
  positional (`id − 4000` IS `SubOscCore::Param`, proved by the `constexpr`
  `subOscRowsAgreeWithCore`), so deleting the row would slide 4012…4019 down and
  move the host automation lanes of parameters that do sound. Retired in place
  with the repo's existing idiom (params 174–177; mod-matrix slots 10–13).
  Sync is not dead as a concept — it is queued for the SWARM oscillators (B185).

## What changed

- `src/subosc_core.h` — `render()` loses its `master` parameter, the `syncOn`
  branch and `mPrev_`. `kSync` and its `kParamTable` row STAY, each carrying a
  RETIRED / DO-NOT-REUSE comment; the value is still stored and restored and is
  read by nothing.
- `src/hypersaw_clap.cpp` — row 4011 relabelled `"SUB Sync (retired)"` with the
  reservation comment; `subs[s].render(tL, tR, m, nullptr)` → `render(tL, tR, m)`;
  the recorded-refusal comment block now records a RETIREMENT, not a deferral.
- `reference/subosc.html` (protected, sanctioned) — the Sync card, the lab-only
  master-ratio oscillator, the `sync` row of `SUB_PARAMS`, `_mPrev` and the sync
  branch all removed; `render(outL, outR, n)`.
- `specs/SPEC-SUBOSC.md` (protected, sanctioned) — §6 becomes
  "Hard sync — RETIRED", answering its own open ruling in place (R3 is neither
  yes nor no: there is nothing to ship and the BLEP is never priced) and stating
  why the id is reserved. **Heading numbers deliberately unchanged**: `grep`
  shows §7 (×3), §10 (×4), §8.1 (×2), §5.3, §4, §2, §11 cited by number in other
  files, so a renumber would silently point them at the wrong text. L2, the §7
  row and R3 are struck in place for the same reason.
- `src/param_presentation.tsv` — `sub.sync` becomes `widget = none`, reusing
  B176's `sub.on` idiom rather than inventing one; the table header now
  documents `none`'s second case (retired, not merely hand-placed).
  `src/gui/gui2.html` regenerated by `tools/gen_gui_controls.py` (−1 control).
  `presentation_check`, `gui_reach` and `test_table_check` green with **no
  exemption added** — engine-block ids are outside `gui_reach`'s `id < 1000`
  population anyway, and totality is satisfied by the surviving row.
- `tools/subosc_check.cpp` — the three sync scenarios' `@master` support, the
  `masterPhase` helper and §10.4's sync leg are gone. **11e stops being a
  REFUSAL pin and becomes a RETIREMENT pin:** writing id 4011 at 1 / 0.5 / 0
  must leave the render bit-identical, with a must-fail CONTROL writing a live
  id in the same block (4010, tone → 300 Hz) that must change it. Both PASS.
- `tools/golden/gen_subosc_goldens.mjs` — `sync-pulse`, `sync-slow`, `sync-off`
  and the master-phase recurrence removed: 60 goldens → 54.
- Consequential, outside the brief's named files (flagged to the lead):
  `tools/labharness/subosc_check.mjs` (its §4 leg passed `sync: 1` and a master
  buffer into a signature that no longer exists — leaving it would have been a

  properties, 0 failed**) and `tests/feature_tests.tsv` row B172-4 (it described
  the refusal this change replaces; the row now describes the retirement and
  its control).

## Alternatives rejected

- **Delete the enum entry and the id.** Rejected: it renumbers 4012…4019 and
  silently moves a player's automation. The brief's central constraint, and the
  repo has two prior retirements that made the same call.
- **Renumber §7…§11 after deleting §6.** Rejected on the grep above.
- **Leave 11e as the old refusal pin.** Rejected: it would have stayed green
  while describing a reason that no longer exists — a test that passes for a
  retired cause is a lie with a PASS beside it.
- **Keep `sync` in the lab's `SUB_PARAMS` so the harness needed no edit.**
  Rejected: the lab IS the spec (ADR-003); a parameter kept only to avoid
  touching a test is exactly the drift the parity gate exists to stop.
