# b497-renders-48k — the reference renders at 48 kHz, through the same generator

- **Queue item:** ROADMAP B497 part 3 (the test author's Q-TA-2).
- **Why:** the test author asked for the 48 kHz set. The generator now takes `--sr 48000` (default 44100) and writes `manifest-48k.json`; the 44.1 kHz set is untouched.
- **What changed:** `tools/engine2_reference_renders.mjs` (a `RATES` table of the two rates with their manifest and asset names; `phrasesAt` derives each event's sample as `round(time_s * rate)` and the length as the last note-off's sample; frames, jobs, WAV encoding and `--verify` take the rate; `--static-check` now covers `manifest-48k.json` too, with 9 must-fail controls for it plus a check that both manifests come from one engine tree); `engine2/data/reference-renders/manifest-48k.json` (new, 380 renders); `engine2/data/reference-renders/README.md`. `parameters.json` is reused for 48 kHz: nothing in it depends on the rate (keys, settings, level, glide flags are identical; the 380 flags agree render for render), so there is no `parameters-48k.json`.
- **Evidence consulted:** the tool and README as they stood at `b237bbe`; `engine2/data/phrases/phrases.json` (no `time_s * 48000` lies within 0.01 of a rounding tie, so the rule is not fragile here); `h2/harness/harness.mjs` `jobFor` (the rate is per job); `git diff` on `manifest.json` and `parameters.json` is empty after the 48 kHz run with `--meta`. A 44.1 kHz subset (8 renders) re-rendered by the refactored tool matched the tracked manifest entries exactly, hash and levels and digest.
- **Reproduction:** two full 48 kHz runs into two scratch dirs (65.5 s and 69.6 s): all 380 WAV SHA-256s and `manifest-48k.json` byte-identical; `--verify --sr 48000` green on both and on the unzipped asset; `--verify` without `--sr` on the 48 kHz audio is red 380 of 380 (it is the 44.1 kHz manifest), as it must be. Toolchain Apple clang, darwin-arm64, Node 24.
- **Alternatives rejected:** a `parameters-48k.json` (a duplicate of a rate-free file); a free-form `--sr` (an unvetted rate would get an improvised file name); touching the 44.1 kHz manifest to record the rate rule (it must stay byte-identical).
- **Verify:** `./verify fast`; exit code and tail are in the hand-back, with the `.harness/last-verify.json` tree check.
- **Open questions:** the 48 kHz peaks differ from the 44.1 kHz ones by up to 2.3 dB on some renders (the engine's oscillators and anti-aliasing are rate-dependent); not investigated, not a defect by the parity rules, but the test author may want to be told. The release upload is the lead's.
