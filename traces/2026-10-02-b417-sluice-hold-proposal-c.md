# b417-sluice-hold-proposal-c — sluice_hold credits horde-origin text per window, with a never-credit ledger

- **Queue item:** ROADMAP B417 (from B415; the human ruled 2026-10-02: "Yes, build Proposal C with the never-credit ledger."). A human-authorized change to a gate.
- **Why:** The gate credited horde-origin text only up to ONE fixed cut-off (the linked Sluice files' first commit, 2026-09-28). Sluice's spec v2 later adopted horde wording written after that date, so the gate went red on horde's own text (B415: 19 occurrences, after #899 reworded the 5 Sluice-origin ones). Now a hit window is credited only if (a) it is not in the local never-credit ledger, (b) some Sluice commit holds it (first appearance = the earliest commit over all refs and any path except `integrations/hypersaw/**`, time = min(author, committer), epoch), and (c) horde's first-parent tree held it at the last commit strictly before that time. Every window the gate counts is appended to `local/sluice-hold-ledger.json` (gitignored, sha256 only), and no code path removes an entry. First appearances are cached in `local/sluice-hold-cache.json` (gitignored, hashes only), keyed by Sluice's HEAD, its refs and the needle set. Controls 6-7 now test the credit rule. Five new controls (8-12) cover each branch through the pure functions `credit()` and `first_appearances()`, on in-memory copies with injected first appearances. All 7 earlier controls stay.
- **Evidence consulted:** `tools/sluice_hold_check.py` (B359 docstring and code); ROADMAP B415/B417 rows (on lead-records-163); the B415 triage notes and JSON (local, gitignored, main checkout `local/sluice-triage/`). Sluice was read only through `local/sluice` and `git -C` log/ls-tree/cat-file, with no writes.
- **Replay on the pre-#899 tree** (3a4115a, in memory, hashes only): with an empty ledger exactly the 5 Sluice-origin occurrences stay red (phrase#6992438e47a1 ×4, phrase#1d27d6d84f1c ×1), as the triage's simulation predicted. Its 2 common-phrase occurrences and its 19 horde-origin occurrences are credited. With the seeded ledger, the same 5 stay red, and lab:4730 reads as phrase#4e4a126e7a51 with one more run. That window would have been credited by the history rule alone; the ledger keeps it red.
- **Ledger seed:** 7 window hashes. They are every needle-shaped window of the 5 Sluice-origin occurrences (3 phrase hashes), recomputed from the triage's local phrases.json. All 7 are current needles. None of the 3 beyond-gate copies' windows is a current needle, so none is seeded. The seed is written to the worktree's and the main checkout's `local/`; neither is tracked.
- **Scratch checks (not committed, in memory):** a 45-character Sluice spec piece appended to an in-memory README copy FAILS (18 runs, 1 phrase) and appends 18 ledger rows. A second run adds no duplicates. With the plant removed the run is green and the rows remain. A missing ledger is reported ("was MISSING — created") and created.
