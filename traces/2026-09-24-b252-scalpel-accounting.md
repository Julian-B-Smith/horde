# b252-scalpel-accounting — the SCALPEL × horde parameter accounting, as a discussion document

- **Queue item:** B252 (ROADMAP on `origin/lead-records-86`, PR #746), with ADR-184 (PR #745).
- **Why:** The human ruled that SCALPEL is "an extension … more of an overhaul" and asked for "a
  thorough discussion and accounting" before any port. The row's deliverable is
  `docs/scalpel/ACCOUNTING.md`, which gives a fate to every existing swarm parameter and every
  SCALPEL parameter. It also covers the member-limit rule, the mod-matrix surface, a cost frame,
  and grouped questions. Analysis only: no code, spec, reference, ROADMAP, DECISIONS, LIBRARY or
  INDEX edits.
- **What it contains:**
  - Fates: 82 horde per-osc rows (64 SURVIVES · 13 MERGES · 5 RETIRED); 12 overlapping globals
    (7 SURVIVES · 5 MERGES); 107 SCALPEL rows (80 NEW · 17 MERGES · 4 DEFERRED · 6 DROPPED).
    Each row carries its class, morph behaviour, mod-dest unit, smoothing, id plan and priority
    tier.
  - A proposed per-osc id block 300–381 (twins 1300–1381), with a `bl.` key prefix.
  - Member limit: 31/41 factory patches use n > 9, and 5/41 use n > 16. The proposal is a
    revision-gated clamp that keeps the range.
  - At the lead's mid-task request (§4.2a): what growing `kMaxSources` costs (no per-tick scaling,
    no state-format change, appended slots keep saved routes valid, downgrade drops routes on new
    slots). Also a final source list to slot 29 under a proposed cap of 32.
- **Evidence consulted:**
  - `src/hypersaw_clap.cpp` at `origin/main` 6256301: the ParamDef table, kGlobalIds, the ADR-173
    class rule and overrides, morph order, `modAddRoute`/`modStep`/route chunk, `applyParam` clamp,
    the B134 polarity table.
  - `src/swarm_core.h`: coupling, σ, phases, pan, saw/BLEP, output, rebuild keys.
  - `src/mod_core.h`, `src/param_presentation.tsv`, `src/gui/gui2.html` (`modDestOptions`,
    `MOD_SRC_NAMES`).
  - `libs/clap-wrapper/src/detail/vst3/parameter.cpp:123-130`.
  - `docs/presets/factory/**`, `docs/MEASUREMENTS.md` §2, `docs/design/compact-lab.html`,
    `docs/playbooks/integrating-a-source.md` §1.

  - The packet on `origin/ingest-scalpel` aaa2e0e: SPEC, `razor-core.js`, `scalpel-bench.html`

- **Method note:** The three large tables were generated by a scratch script that READS ids, keys,
  ranges, defaults, stepped flags and source lines from the files named above. Only the fate, tier
  and note columns are hand judgements. Coupling-strength and cost figures are arithmetic from the
  cited formulas, not renders, and are labelled so in the document.
- **Alternatives rejected:**
  - Narrowing `n`'s declared range. It re-maps stored values through the load clamp and every
    VST3 lane through clap-wrapper's normalisation.
  - Widening `retrig`/`panLayout` for *settled*/*balanced*. Same VST3 re-map; new rows instead.
  - ψ as a matrix source. It rotates at the note frequency and would alias at the control tick.
  - Exposing the blade envelopes as global sources now. The mod lab's per-note finding argues
    against it.

  verbatim) and in `.harness/last-verify.json`.
