# b488-ab-tool — tools/h2_ab.mjs: an A/B set between two engine builds, rendered offline

- **Queue item:** B488 step (0) (ADR-220 item 2).
- **Why:** ADR-220 lets the engine change its sound subtly for CPU savings provided every change can be heard A/B. This is the tool that makes the set: a fixed phrase set (a held note, a chord, a fast line, a progression that makes the pool steal) on a fixed preset set (the five heaviest of the CPU ledger, Quarter sync, the oracle defaults), rendered by two builds of `h2_harness_render`, with each pair's difference measured and a page to play them from.
- **What changed:** `tools/h2_ab.mjs` (new; no dependency but Node's own and `h2/harness/harness.mjs`), a section in `h2/harness/README.md`, two added lines in `./verify` (fast: `--self-test`; full: `--self-test --bin` on the engine just built, which runs the engine half of control (a)). Nothing in the engine, and no WAV or page is committed.
- **Decisions that were mine, each open to the lead:**
  1. *The page uses plain `<audio>` elements and `volume`, not a Web Audio GainNode.* The brief asked for a GainNode on B. A `fetch()` of a `file://` WAV is blocked, and a media-element source of a `file://` URL is cross-origin and plays silence, in the browsers. `tools/serve_labs.py` serves only `docs/design`, `reference` and a few named files (its `ALLOWED_DIRS`), never a build directory, so the page's real home is `file://`. A media element's volume cannot exceed 1, so with the level match on the louder side is turned down by the measured gain (B matched to A); the pair is matched, its absolute level is not. No browser was available here: the page's script passes `node --check` and was read through, never run.
  2. *The progression is four 5-note chords, not triads.* The brief fixes the pool at 8; with triads the pool of 8 never fills. At 5 notes the second chord finds 3 free voices and takes tails wherever a preset's release is over 0.1 s. Whether a take happens on a given preset is that preset's behaviour (not asserted).
  3. *Tail 3 s after the last key-up, for every phrase* (the pads release over 3 s). 
  4. *"Crush vs FM" and "Sync over fold" are read from the bank directly* (`h2/harness/patches.json` holds only the ledger's seven; these two are the ledger's `--also` rows). The tool checks any preset that `patches.json` also holds against it, value for value.
  5. *The fast target prints SKIP for the engine half when no `h2_harness_render` is built* (it builds none, and a compile line in `tools/` is a `build_flags_check` entry the human pins). The controls then run on a synthetic signal and say so; `./verify full` runs them on the engine. With a binary in `build-release/` or `$H2_HARNESS_BIN` the fast target runs the engine half too (about 7 s).
  6. *`diffDb` above 0 is not "B is louder".* The Breathing pad reads +1.3 to +2.3 dB in the D8 run: its two renders have partly decorrelated (+3.01 dB is two independent signals of one level). The README says so.

- **Alternatives rejected:** a GainNode with a `fetch()` (see 1); embedding the audio in the page as base64 (110 MB page); compiling a renderer inside `./verify fast` (a `build_flags_check` entry, a human pin); a JSON field of `null` for a silent render's `-inf` (reads as "not measured": written as the string `"-inf"`).
- **Verify:** `./verify fast` and `./verify full` on the staged final tree; the result and commit are in the PR body. Result recorded in `.harness/last-verify.json`.
- **Open questions:** (a) whether the lead wants the GainNode path anyway for served use (a second code path, untested here for want of a browser); (b) the page has never been opened in a browser by the author; (c) the D8 run's Breathing pad reads +1.3 to +2.3 dB and its first differing sample is 0: the lead's brief expected a difference on presets with a spread law, and this is that; why the pad's pair decorrelates is not investigated here.
