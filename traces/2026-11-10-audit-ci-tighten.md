# audit-ci-tighten — CI/check coverage tightened per the 2026-11-10 audit (findings 7, 8 CI part, 9, 11)

- **Queue item:** unqueued: the human's poll answer "Tighten CI coverage" on docs/audits/2026-11-10-fable-audit.md; the lead adds the records. Every change tightens coverage; none removes, skips or relaxes a gate (ADR-180 §1).
- **Why:** (7) the sanitize job was GREEN with 19 oracles not built, so a twentieth could break unseen. (8) CI's verify-fast checked out without submodules, so the license-audit and choc-patch rows never ran there. (9) a docs/presets-only PR (the factory bank) triggered no CI at all. (11) the clock/RNG ban scanned only src/.
- **What changed:**
  - `tools/sanitize_unbuilt.pin` (new; plain text, not .json, because golden_registry_check treats any tools/*.json as a golden) pins, per `<sanitizer>|<shard>`, the not-built oracle names from CI run 42903763815 (shard 1/2: 11, shard 2/2: 8). `tools/sanitize_oracles.sh` now runs a `ratchet`: RED when the shard's not-built set is not a subset of its pinned list (names, so a new break is red even if another got fixed; per shard, so slack cannot move); prints FIXED for pinned names that now build. A missing key is red under CI, a note locally; skipped for SANITIZE_ONLY subsets. A must-fail control runs at every start: a planted extra name must read RED and the pinned list GREEN, or the script exits 1 before building.
  - `ci.yml`: `paths-ignore` removed from both triggers; a `changes` job classifies the diff (`code`, `linux`) with `git diff --name-only` and no new action. verify-fast and sanitize run when `linux`; build-windows and build-macos only when `code`. Tags and unknown/zero `before` fail toward running everything. verify-fast checks out `submodules: recursive`.
  - `tools/playbook_check.py`: scans `h2/**` and `engine2/core/**` (.h/.cpp) as well as `src/`, excluding any `harness`, `tests` or `tools` directory; selftest plants clock reads under both new globs (caught) and under tests/ and harness/ (skipped); red if the globs match nothing.
- **Evidence consulted:** the audit's findings 7-9 and 11; CI run 42903763815 log (exact unbuilt names); the whole of ci.yml; workflow_pin_check rules (no `github.event` in `run:`, so the event fields go through `env:`); tools/playbook_check.py.
- **Alternatives rejected:** a count-only ceiling (a fix would hide a new break); a pinned total (per-shard was practical, the script already knows its shard); `paths:` negation (cannot gate Windows/macOS separately); a third-party paths-filter action (no new actions).
- **Not fixed, said plainly:** bank_check and morphlayout_check (shard 1) and preset_pitch_check and offcorner_check (shard 2) are among the 19 that do not build on Linux, so the preset trigger now starts the Linux jobs for a preset-only PR but those four still do not run there. What would: making the oracles link on Linux (the `hypersaw_debug_*` hooks that src/hypersaw_clap.cpp compiles for Apple/Windows only; B256), or running them in a macOS job for preset PRs. Out of scope here. What a preset-only PR now gets on Linux: `verify fast` (paste_cap_check and the rest) and the 54 oracles that do build (27 per shard on the last run).
- **Notes:** ci.yml has ONE verify-fast job here, not two; it is the one edited. A docs-only PR now starts the workflow and runs only the cheap `changes` job (everything else skipped) rather than not starting it.
- **Verify:** `nice -n 10 ./verify fast` in this worktree, exit 0 (first run exit 1: golden_registry_check treats any tools/*.json as a golden, so the pin became tools/sanitize_unbuilt.pin).
- **Open questions:** if branch protection names required checks, a skipped job reads as skipped, not missing; the human should confirm that matches their ruleset. h2/harness is excluded from the clock scan as test scaffolding (no hits in it today).
