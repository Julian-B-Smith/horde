# build-fixes-b454 — the MSVC /STACK loop reaches every executable; glide_core.h includes <cstdlib>

- **Queue item:** ROADMAP B454 items 8 and 9 (ADR-206 item 5, approved by the human 2026-10-10).
- **Why:** (8) The MSVC `/STACK:67108864` loop sat mid-file in `CMakeLists.txt` and stamped only the
  executables declared above it, so the 12 declared after it (`anchor_check` .. `bank_check`) got the
  default 1 MB Windows stack: the same shape #1023 fixed for the sanitizer loop. (9) `src/glide_core.h:243`
  uses `std::labs` without `<cstdlib>`; it compiles on Apple clang by transitive include and fails on
  Homebrew LLVM's libc++.
- **What changed:**
  - `CMakeLists.txt`: the stack block moved verbatim to the end of the file, directly above the sanitizer
    block (the form #1023 chose), with a three-line comment saying both loops are last.
  - `tools/build_flags_check.py`: `sanitizer_reach_gaps` now checks both loops (`REACH_LOOPS`: the
    `-fsanitize` loop and the `/STACK` loop). Must-fail controls added: an executable planted between
    the loops (below the stack loop only) reads red; the stack loop moved back above `anchor_check`
    (the old shape) reads red on `bank_check`; no stack loop at all reads red. `before_san_loop` now
    anchors on the first line of the stack block so the "above both loops" controls stay honest.
    Selftest 49 -> 52 controls (three added).
  - `tools/build_flags_pin.json`: re-pinned `dynamic_loops` only, via
    `--approve dynamic_loops "ADR-206 item 5; approved by the human 2026-10-10"` (the stack loop's
    `executables_covered` gained the 12).
  - `src/glide_core.h` and its horde 2 lift `h2/cores/swarm/glide_core.h`: `#include <cstdlib>` after
    `<cmath>`. `h2_lift_check` pins the legacy source by git blob, so the edit is a deliberate re-lift:
    the identical line in the copy, `src_blob` re-pinned in `h2/cores/swarm/lift-ledger.json`
    (714bd31 -> 5cf891a), `lifted_at` annotated. No ledger entry is added and the FROZEN set in
    `tools/h2_lift_check.py` is unchanged (the copy is still src + NS2). Nothing weakened.
- **Evidence consulted:** `CMakeLists.txt` (stack block, sanitizer block); `tools/build_flags_check.py`;
  `tools/h2_lift_check.py` docstring and FROZEN; `h2/cores/swarm/lift-ledger.json`; `h2/README.md`
  lift rules; `golden_pin_check` pins only goldens named in `h2/README.md`, none is glide_core.
- **Header proof (Homebrew LLVM, libc++, `-std=c++20 -fsyntax-only`, each header alone):** before the
  edit `src/glide_core.h:243` failed twice ("no member named 'labs' in namespace 'std'"; `swarm_core.h`
  failed through it); after, all 26 `src/*.h` are clean, as are `h2/cores/swarm`, `h2/cores/scalpel` and
  `h2/engine` headers. No other missing-include finding.
- **Parity (unchanged by an include):** `parity_check` 156/156 (worst 4.262e-09 @ dyn-ring.seed42);
  `h2_swarm_parity_check` 156/156 (worst 2.485e-9 @ saw-glass.seed1234, equal to the lift ledger's
  figure); `h2_swarm48_check` 171/171, 0 red; `h2_swarm_lift_check` GREEN; `glide_check` GREEN. The h2
  engine includes no lifted swarm header (git grep), so its self-digests are untouched by construction
  and were not rerun.
- **Alternatives rejected:** a `kind: "edit"` ledger entry for the include (would need a FROZEN change
  and gains nothing: a re-lift to a byte-equal copy needs only the blob re-pin); a single combined
  loop for both flags (MSVC and non-MSVC branches differ, and the pin records them separately).
- **Verify:** see `.harness/last-verify.json` (`./verify fast`), recorded in the PR.
- **Open questions:** the Windows build cannot run here; CI `build-windows` and `validate-windows` on
  the PR are the proof of item 8. The h2 README rule says a re-lift is "recorded by the lead in
  ROADMAP": the lead should note the glide_core.h re-lift (ROADMAP is out of the implementer's scope).
