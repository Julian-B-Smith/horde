# b209-filter-lab — filters lab: placement (per source / rack slot / both), controls, proposed bank-law changes

- **Queue item:** B209 (row carried in PR #720; human 2026-09-22: "Filters lab — functionality, design, routing").
- **Why:** Where a filter sits was the undesigned question, and per-source and post-sum filtering are
  different instruments. So the lab lets the human HEAR three placements under one seeded pattern, and it
  designs the filter's controls. Any change to the swarm bank's law is shown as a PROPOSAL played beside
  the reference, never made to it.
- **What changed:** `docs/design/filter-lab.html` rewritten in place (the index link stays valid; no
  successor, so no `lab-superseded-by`). It is built to gui2's token standard (tokens copied from
  `src/gui/gui2.html:26-212`, the same copy `station-page-lab.html` carries), in both themes, and carries
  `<meta name="lab-review" content="B209 · 2026-09-22">` per the lead's addendum.
  - Placements: PER SOURCE is B81's per-voice SVF pair (a transcription of `src/svf_core.h`), with each
    of SWARM 1 / SWARM 2 / SUB assigned OFF/A/B/A+B plus serial/parallel. RACK SLOT is one filter inside a
    reduced ADR-088 matrix well (FILT = `coeff[src][slot]`, DRY = the B50 dry path). BOTH runs both.
    Hotkeys 1/2/3 switch placement.
  - Rack laws: SVF; SWARM · REF (reference/swarmfilter.html fetched and its `FilterLab` sliced by the
    extract_core banners, so its placement, forces and coefficients are CALLED; only the per-sample bank
    loop :362-374 is copied, because `render()` hard-wires its own exciter); SWARM · PROPOSED (P1 Q
    compensation, P2 LF keep, P3 rigid modulation). A live shadow of the reference is drawn as a dashed
    ghost while PROPOSED plays.
  - Controls: the response curve is the control (drag = cutoff × resonance, wheel, double-click). Violet
    shows live state: one curve per sounding voice, or the rack's single curve, plus the bank's bars.
    Cyan shows spectra out, drawn over the dim spectra in (an in-page FFT). Keytrack policy: per voice
    PLAYED KEY / SOURCE PITCH; rack LAST / LOWEST / HIGHEST, held across release. There is one filter
    envelope shape: per voice, each note runs its own copy; the rack has one copy, re-fired on every
    note-on.
- **Evidence consulted:** ROADMAP B209 (PR #720 diff), B81, B50, B23; `src/svf_core.h`; `src/fx_rack.h:86`
  (today's rack Filter is a one-pole stub); `src/filter_core.h:50-88`; `src/gui/gui2.html` tokens and the
  matrix pane (:385-480, :7139-7345); `docs/design/station-page-lab.html` (the model);
  `reference/swarmfilter.html` (read and called, not modified); `tools/golden/extract_core.mjs`,
  `gen_filter_goldens.mjs`; `tools/labharness/lab_load_check.mjs`.
- **Measured** (the lab's DSP loaded headless through the `design` banner set plus the reference's
  `FilterLab`; one 4.286 s DEMO loop at 48 kHz; the scratch script was not committed):
  - Must-read-zero controls: the same patch rendered twice gives max|diff| = **0**. "No filter" reached
    two ways (pre, all OFF, vs post, all DRY) gives max|diff| = **0**.
  - Placements differ: pre vs post **−13.0 dB** rel, pre vs both **−9.8 dB**, post vs both **−10.4 dB**.
    Filter-envelope re-fires reaching the held bass per loop: **3** per voice vs **16** on the rack.
  - Q3 linearity (instancing the state per source equals filtering the sum): max error **5.55e-16**, with
    the cutoff varying over time.
  - The drawn curves are the audio: SVF analytic vs simulated **0.000 dB** worst; bank (reference
    coefficients through the copied loop) **0.000 dB** worst.
  - P1: peak at qbase .1/.5/.9 is ref 5.49 / −1.50 / −7.07 dB and proposed 0.28 / −1.50 / −1.86 dB.
    P2: 40 Hz sits 22.8 dB below the peak for REF and 1.4 dB for PROPOSED. P3: 1.36 s to 90 % of a
    one-octave centre step for REF vs one tick (0.33 ms) for PROPOSED.
    Rack SWARM·REF vs SWARM·PROPOSED differ by 9.4 dB rel (RMS 0.060 vs 0.176).
  - Reference quirk: writing `center` every tick re-runs `rebuild()`, which re-seeds the RNG (:210). With
    the centre held, the drift's per-tick noise has sd **1.61e-3**; re-set every tick, it has sd
    **1.05e-16**, i.e. the random walk becomes a constant push.
  - Gain staging: the monitoring tanh was driven to a 2.2 peak (it squashed the placement differences),
    so its gain went from 1.6 to 0.6.
  - Cost: 34× real time (SWARM·REF) and 41× (BOTH, SVF) in node.
