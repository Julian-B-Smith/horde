# b497-cleanroom-tree — the clean-room tree for the new engine, its input data, and the sparse-checkout recipe

- **Queue item:** ROADMAP B497 part 1 (acceptance: "the tree builds an empty engine library and runs an empty suite; the recipe's tree passes its no-old-code check"), under DECISIONS ADR-223 to ADR-229 and `specs/SPEC-ENGINE.md` BD-10. Brief: the horde lead, 2026-10-16. Note: the B497 row itself was not in `ROADMAP.md` on `origin/main` (62132f2) when this ran; the brief quoted it, and this was built on the brief's text.
- **Why:** BD-10 makes the build a clean room: the builder sees the spec and the acceptance tests, in a tree with no earlier engine. A tree and a recipe are what turn that sentence into something a check can fail.
- **What changed:**
  1. `engine2/` (new): `CMakeLists.txt` (standalone project: static library `horde_engine2`, the suite's runner, the runner's own must-fail control under ctest `WILL_FAIL`, C++20, `-G "Unix Makefiles"`, Release by default, no `-ffp-contract` requirement per ADR-225 item 9), `build.sh` (absolute build dir; configure, build, ctest, print the suite line), `core/` (the spec's section 3 layout as empty headers with a purpose line each, and one empty translation unit), `tests/` (`runner.cpp`, `suite.h` with self-registering items, empty `items/`, `controls/`, `harness/` note), `wasm/` (a stub that refuses to configure, README: awaits the human's approval of an exact toolchain version), `data/` (the bank, the 12 envelope presets, READMEs for the phrases, the version-0 states and the reference renders, a `.gitignore` for audio), `tools/click_detector.mjs` (byte copy), `README.md`, `CLEANROOM.md`.
  2. `tools/engine2_cleanroom.sh` (new): the recipe. A detached git worktree, `--no-checkout`, non-cone sparse patterns `/engine2/`, `!/engine2/data/reference-renders/`, `!/engine2/data/version0-states/`, `/specs/SPEC-ENGINE.md`. `--snapshot` takes engine2 and the spec from the working tree through a throwaway index (the check must see uncommitted edits); `--also` exists for the must-fail controls only.
  3. `tools/engine2_cleanroom_check.py` (new, `WIRED: ./verify fast`): detector copy byte-identical to `tools/click_detector.mjs`; envelope data equal to Appendix A (with hand-read anchors and an independent pair count, so the parser is not its own witness); bank holds 83 presets in the bank format; the recipe's fresh tree: allow-list (engine2/ and the spec only), named deny list, test-author-only data absent, no file named like the twin or prototypes, no symlink, no old-engine identifier (the spec's BD-10 line exempt). Ten must-fail controls every run. `--build` also builds and tests the recipe's tree.
  4. `./verify`: one block added at the end of `fast()` (the check; `engine2/build.sh` in a scratch dir). Nothing removed, skipped or relaxed.
- **Evidence consulted:** `specs/SPEC-ENGINE.md` (sections 3, 7.1, 10.1, 10.3, 10.5, Appendices A and B, BD-1 to BD-10); `docs/port/spec-engine-provenance.md` line 108 (the version-0 example states are supplied by the lead with the reference renders); `reference/scalpel/data/presets.json` (copied unchanged: 83 presets, all 99 keys in B.1's base list); `tools/click_detector.mjs` (imports only `node:fs` and `node:url`); `tools/h2_rules_check.py`, `tools/build_flags_check.py`, `tools/test_table_check.py`, `tools/tolerance_registry_check.py`, `tools/sanitize_oracles.sh` (what each scans, so the added files and the verify block trip none of them); root `README.md` lines 402-403, 489-492.
- **Alternatives rejected:** cone-mode sparse checkout (always materialises every root file); including the root `README.md` as the brief listed (528 lines, including the old engine's file map and its "statement-level ports of browser prototypes"; there is no top-level license file); including `libs/clap` (the API is plain data in the spec's units; CLAP is the shell's); building the check's tree from `HEAD` (the Stop hook and `verify` run on uncommitted edits, so it would read the tree before the change); passing `-DCMAKE_BUILD_TYPE` from `verify` or a `tools/*.sh` (it would move `build_flags_pin.json`'s entry points; engine2's own CMake defaults to Release); inventing phrase events or version-0 states (the spec leaves the events to the test author, the states to the lead).
- **Verify:** `./verify fast` on the staged tree; the exit code, its closing lines and the `.harness/last-verify.json` tree check are in the hand-back and the PR body. `python3 tools/engine2_cleanroom_check.py --build` (about 2 s) also ran green: the recipe's own tree builds the empty library and runs the empty suite.
- **Open questions:** (1) Sparse checkout hides files, not history: `git show` in the builder's worktree still reads old code (CLEANROOM.md says so); a history-free export would close it. (2) The root `README.md` is left out of the recipe (see above); one line in `INCLUDE` adds it. (3) The phrase events are not in the tree: the spec states names and durations only, so `data/phrases/` holds a README and waits for the test author's `phrases.json`. (4) The version-0 example states and the reference renders are the lead's (B497 part 2) and sit outside the builder's recipe. (5) `build_flags_check.py` reads only the root `CMakeLists.txt`, `verify`, `tools/*.sh|py` and the workflows, so `engine2/CMakeLists.txt`'s flags are not pinned: a gate change for the build's own PR (the brief). (6) The recipe script sets `extensions.worktreeConfig` in the shared repository config (git's own mechanism for per-worktree sparse patterns). (7) `engine2/tools/click_detector.mjs` is byte-identical to the original, so its header comments still name the old tools and a research note that are not in the tree (names in comments, no imports). (8) An empty static library makes the macOS `ranlib` print "table of contents is empty" until the first symbol lands.
