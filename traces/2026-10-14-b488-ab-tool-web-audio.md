# b488-ab-tool-web-audio — the A/B page plays on Web Audio, loops, and has a blind mode (corrects traces/2026-10-14-b488-ab-tool.md decision 1 and traces/2026-10-14-b488-ab-tool-switch-fix.md)

- **Queue item:** B488 (0), ADR-220 item 2; PR 1091.
- **Why:** the human's feedback on the page: "The switch button is finnicky, sometimes restarting the sample. And the audio should loop." Two media elements kept in step by seeks cannot be made sample-tight, so the page stops using them for playback. The first trace's decision 1 (plain `<audio>` elements because `file://` blocks `fetch`) is reversed for the served case and kept for `file://` as a fallback.
- **What changed:**
  - `tools/h2_ab_page.mjs` (new): the page's behaviour as a real function `pageMain(document, env)` (shipped as its source), its CSS, and the probes. `tools/h2_ab.mjs` imports it and writes the page around it.
  - Playback: both WAVs of a row are fetched and decoded on that row's first Play; two looping `AudioBufferSourceNode`s start at one `when` of one `AudioContext` into their own `GainNode`s; Switch, the level toggle and Stop are 10 ms gain ramps from the current value (`cancelScheduledValues`, `setValueAtTime`, `linearRampToValueAtTime`), never a seek, start or new node. Starting another row stops the current one. The level match is a gain on B and may exceed 1.
  - A playhead per row (the context clock modulo the loop length) and the audible side as a large highlighted block. One column, cards, light and dark.
  - Keys: Space plays or stops the outlined row, S or X switches, the up and down arrows move between rows (Tab is left alone). Shown on the page.
  - Blind mode: per-row X and Y in a random order drawn from `crypto.getRandomValues` when it is turned on; every row opens on X; prefer X / prefer Y per row; Reveal shows what each was and a tally; the direction of the difference (which side is louder, the gain B needs) is hidden until reveal. Nothing is stored.
  - Fallback: when the `fetch` fails (opened from `file://`) the page plays through `<audio>` elements as the previous commit did (volume-only Switch, the silent element lined up with the audible one) and shows a note.
- **Decisions that were mine:** (1) The note names `python3 -m http.server` and not `tools/serve_labs.py`: `serve_labs.py` serves only `docs/design`, `reference` and a few named files, never a build directory, so naming it would send the human to a 404. (2) Looping makes the pair loop the whole render, release tail included, as asked. (3) The `<audio>` elements stay in the page with `preload="none"` so the fallback has its sources; in Web Audio mode they load nothing. (4) The fallback's Play handler is kept unchanged in effect and `loop` is set on its elements.
- **Controls (`--self-test`, control (d)), run in stub objects with no browser:** Play starts two sources at one `when`, both looping, after two fetches and two decodes, with gains 1 and 0; the playhead reads 2.4 s at 9.4 s into a 7 s loop; Switch issues two gain ramps, complementary (A to 0, B to its level), ending together 10 ms from now, and nothing else; a level toggle is one ramp; starting another row and Stop stop the sources; the keys; blind mode relabels to X and Y, opens on X, reveals the mapping and tallies. Must-fails, each read red every run: a source started on Switch, sources started 10 ms apart, a source whose loop stays false. The fallback keeps its own pair of controls (a seek on Switch; a seek to 0).
- **What no stub can see:** that a real browser plays the two sources in step and that the 10 ms ramp is click-free; the lead's browser run is the proof that remains. The probes also do not run `decodeAudioData` on a real WAV.
- **Evidence consulted:** the coordinator's message of 2026-10-14 (the human's feedback and the brief); `tools/h2_ab.mjs` before the change; `tools/labharness/sandbox_check.mjs` (the evaluator scan: the page stays a real function).
- **Alternatives rejected:** `setTargetAtTime` for the ramps (never reaches exactly 0, so the old side keeps a tail; the linear ramp ends exactly); `localStorage` for the tally (not needed); seeking by clicking the track (a seek restarts the sources; not asked for).
- **Verify:** `./verify fast` and `./verify full` on the staged final tree; the result and commit are in the report. Result recorded in `.harness/last-verify.json`.
- **Open questions:** the lead should replay in a browser over http: Space, S, the arrows, blind mode and reveal; and once from `file://` to see the note and the fallback. Whether B raised above 1 can clip on a loud pair (a pair at 0 dBFS peak with a +1 dB match) is not measured here.
