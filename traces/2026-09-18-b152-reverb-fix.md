# b152-reverb-fix — the reverb lab's five pre-port fixes, and its fidelity suite

- **Queue item:** B152 layer 2 (the lead's dispatch brief of 2026-09-18, off the
  layer-1 audit `docs/audits/2026-09-18-reverb-lab-audit.md`). Human direction
  2026-09-18: audit the reverb lab before it is integrated. `docs/design/
  reverb-lab.html` is a DESIGN lab, not a protected reference path, so the fixes
  needed no spec gate.
- **Why:** a lab edit is cheap and a port-then-re-port is not. The audit ranked
  five fixes as "do these in the lab before the port", every one of them
  bit-identical at 44.1 kHz — which is only true *before* a golden exists. R1
  (the unguarded index) is the one that produces silence and is invisible at
  44.1 kHz; R2 decides ADR-175 loop membership; R3/R4 cost nothing now and cost
  every golden later. The sixth candidate — hoisting the 53 loop-invariant
  transcendentals — was deliberately NOT done: the audit found a re-association
  that passed the 1e-6 parity bar while being non-bit-identical, so that
  optimisation waits for goldens and the port.
- **Evidence consulted:** the audit in full (R1 §1.1, R2 §1.2, R3 §1.3, R4 §1.4,
  R7 §1.6, R11 §1.12, R16, §3's suite table V1–V14, §5.2's parity strategy,
  §5.4's fix order); `src/time_core.h:167` (the two-sided guard idiom) and
  `:179` (the +1 all-ones Householder); ADR-030(a), ADR-009, ADR-175;
  `tools/golden/extract_core.mjs`, `tools/golden/gen_goldens.mjs`,
  `tools/labharness/lab_load_check.mjs`, `tools/feedback_scan.mjs` (the
  extract-don't-reimplement idiom); the audit's own scratch probes.
- **Alternatives rejected:**
  - *Changing the Householder sign to match its comment* — rejected: it changes
    the shipped sound (≤ 1.2 % T30, but a decision either way), so the comment
    was corrected instead and the divergence from `time_core.h` recorded. The
    human's call, not an implementer tidy-up.
  - *Renaming the lab's `DSP`/`UI` banners to fit `extract_core.mjs`* —
    rejected: nine of the ten `docs/design` labs use that pair, so the tool was
    given a banner table instead. Editing the artefact to suit its instrument is
    the wrong direction.
  - *Fixing the RT60 calibration (R5)* — out of scope by the brief and correctly
    so: the error is non-monotone in the setting, so it is a design question,
    not a scale factor. The suite PINS today's numbers instead.
  - *A single CMake target for the suite* — not possible for a JS lab; hence a
    hand-run Node script in the `lab_load_check.mjs` idiom.

## What changed

**`docs/design/reverb-lab.html`** — five fixes, one commit each:

1. **R1** — two-sided index guard on all three fractional reads (pre-delay, ER,
   FDN), plus a `d ≤ len − 4` clamp on the ER read. The `src/time_core.h:167`
   idiom; four lines of code and the comment that says why the watchdog below
   them cannot be relied on in C++.
2. **R2** — the 16-sample control tick moved from `smp & (TICK-1)` (the index
   *within the block*) to `this.tickCtr` in instance state. Deliberately not
   cleared in `reset()`: it is a clock, not state.
3. **R3/R4** — `baseLen0`, `apLen` and `modSamp` multiplied by `sr / 44100` at
   construction. The FDN and allpass buffers are now *derived* from the scaled
   lengths rather than written down, or the rescale would walk straight back
   into the read clamp at 96 kHz.
4. **R11** — the per-sample `new Array(NLINE)` hoisted to instance state.
5. **R7** — the Householder comment corrected to state the eigenvalue the code
   actually produces (−1, plain `I−(2/N)J`), with ADR-030(a) and the ≤ 1.2 %
   T30 measurement cited. **Code unchanged.**

**`tools/golden/extract_core.mjs`** — an exported `BANNERS` table (`reference`:
`DSP:`/`Audio graph`; `design`: `DSP`/`UI`) and an optional third argument to
`extractCore`, defaulting to `reference` so both existing callers are untouched.
Without this the lab could not be loaded by the golden machinery at all (R16).

**`tools/labharness/reverb_check.mjs`** (new) — eight checks, every threshold a
number measured on this lab plus a stated margin, every check with a must-fail
control. For R1 and R2 the control is the pre-fix defect planted back by
anchored source substitution; the anchor mechanism is itself verified by a bogus
anchor that must throw (L0032). Both planted controls reproduce the audit's
pre-fix numbers exactly.

- **Open questions:**
  1. **R5 (RT60 calibration) is pinned, not fixed** — +31.0 % at 0.5 s, −13.6 %
     at 2.2 s, and the 44.1 k→96 k drift of the 1 kHz band is now −0.3 / −3.6 /
     −5.3 % (was −17.3 / −5.3 / −17.4 %; R3's rescale improved it but did not
     close it, and `samplerate_check`'s bar is 0.3 %). The error is non-monotone
     in the setting, so no single scale factor fixes it. Lead/human call.
  2. **The Householder sign is still −1 while `time_core.h` is +1.** The comment
     now says so; ADR-030(a) requires the statement, and the audit recommends an
     ADR amendment recording the divergence. Not written here — DECISIONS.md is
     out of scope for this dispatch.
  3. **Audit §5.4 items 5 (its R9 half), 6, 7 and 8 remain open:** R9 (192 KiB
     of dead state — `erBufR`, `apR`, `dcx`, `dcy`), R12 (the ER tap set's
     missing provenance), R10 (43 % of the mixing-time slider is inert while the
     readout prints the request), R8 (flush-to-zero — V7 reports the state
     reaching 1.976e-323 at 60 s and gates only on finiteness, because whether
     to flush is a C++-side decision).
  4. **R6 (the transcendental hoist) was explicitly not done**, per the brief:
     the audit's first hoist was arithmetically identical but not bit-identical
     (6.939e-18, ~1e-14 relative — it would have *passed* the ε=1e-6 parity
     bar). It waits for goldens and the port, where multiply order must be
     preserved deliberately.
  5. **The suite is not wired into `./verify`** and is not proposed to be: it
     takes 46 s, 38 of them in V6's slider sweep, and `verify` is a human gate
     to edit. If the lead wants it gated, that is a separate decision.
