# b149-seed-trng — the ensemble-timing RNG is seeded from the patch seed and rides the state chunk

- **Queue item:** B149 (ROADMAP, `origin/main` @ 6e33fd7). Source finding:
  `docs/audits/2026-09-18-saw-engine-audit.md` §1.3 (A3), HIGH.
- **Why:** `src/swarm_core.h` carried the ADR-077/078 ensemble-timing stream as
  `uint32_t tRng = 12345` — a literal `p.seed` never reached and no saved state
  ever carried. The audit measured both halves on the patch `voiceEnv 1,
  attackScatter 1, relScatter 1, onsetScatter 8`: seed 1234 vs 999999 differed
  by **exactly 0.0** (the seed knob was inert for the feature), and the same
  note after five earlier notes vs none differed by **0.137 RMS** — the same
  magnitude as the audit's different-seed control (0.119), i.e. a completely
  different render. `specs/ACCEPTANCE.md` L0-13 ("same seed + note sequence →
  bit-identical") was therefore FALSE for every patch with onset scatter or
  per-voice envelopes on, and a bounce was not reproducible across a session
  restart. ACCEPTANCE is **restored, not edited** — the lead records it.

## What changed

**`src/swarm_core.h`**
- `ensembleSeed(seed)` — the stream's starting state, `s * 2654435761 +
  0x9E3779B8` under the existing `toInt32` / uint32-wrap idiom. mulberry32 stays
  the one RNG (SPEC §5.7); `rngNext()` is reused unchanged, so a "separate
  stream" is a separate starting state and not a separate algorithm.
  **Distinctness, proved for the geometry stream and bounded for the phase
  stream:** grng is `s + 1`; a coincidence needs `s*(C-1) ≡ 1-K (mod 2^32)`, and
  `C-1` is even while `1-K` is odd, so no seed solves it — *entailed*, exactly.
  The per-voice phase stream is `s + age*7919 + 1` and is re-seeded every note
  while this one free-runs across notes (that persistence is the whole of
  ADR-077), so the two cannot draw in lockstep even from an equal state; that
  half is an argument, not a proof, and the file says so.
- Re-derived in `rebuild()` beside `grng`, but **on a seed change only**
  (`ensSeeded` / `ensSeed`). `grng` is re-consumed from the top by `rebuild()`
  itself, whereas `tOff` is memory the swarm accumulates across notes and
  `rebuild()` also fires on width/topo/pan/law automation — re-rolling there
  would make a pan sweep silently reset the timing history. A seed change is the
  one edit that means "re-roll this swarm".
- `EnsembleTiming` / `ensembleTiming()` / `setEnsembleTiming()` /
  `ensembleIsInitial()`. The struct carries the seed it was derived under, which
  is what makes the restore order-independent (below).

**`src/hypersaw_clap.cpp`**
- A new append-only `ens=` state key, per oscillator (`ens=` / `o1.ens=`),
  payload `<seed>;<tRng>;<tOff[0..31]>` at `%.17g`. Read inside the existing
  `o<k>.` prefix split rather than beside `morph`/`routing`, so there is one
  copy of that parse.
- **Emitted only when the stream has left its seeded initial state.** A patch
  that uses neither onset scatter nor per-voice envelopes writes no key at all,
  so every chunk that existed before this change still serialises to the bytes
  it did — which is why `state_check`, `statefix_check` and `bank_check` stayed
  the regression proof instead of three things to regenerate.
- Emitted **last**, and carrying its own seed: `state_load` applies parameters
  directly when idle (seed first, then this key) but **queues** them to the
  audio thread while processing (this key first, then seed). Matching seeds mean
  "already derived", so `rebuild()` does not re-roll a stream that was just
  restored, in either order. `tseed_check` E2/E3 assert both orders.
- `plug_activate` carries the state across the core replacement, for the same
  reason it already carries `p`. **This is outside the brief's sub-file scope
  note ("ONLY the state chunk writer/reader") and is flagged as such.** It is
  not optional: `activate()` destroys and reconstructs the core, the host's
  order is `setState()` then `activate()`, so a restored history that is not
  carried here never reaches the first render. Measured — without it,
  `tseed_check`'s restore assertion passed and the audio control read
  `0.000e+00`: a false green, the detector-shares-the-assumption trap. It is not
  a routing site, so it does not collide with the `b23-osc-sources-2` stream.

**`tools/tseed_check.cpp`** (new, standalone, **not** wired into `./verify` —
that is the human's call, per the charter). Seven sections, each with its
control: A the seed reaches the stream; B **attribution** — the same two seeds
with the stream shut must move *exactly* 0.0, which is what makes A attributable
to the stream and nothing else; C **calibration** — the same rig with retrig off
must read non-zero, because a zero is also what a broken render produces; D the
stream is off-path when the features are off (FNV-1a equal to `origin/main`'s);
E the chunk round-trips the state exactly in both load orders, with the
key-stripped restore as the must-fail control; F the restored core draws the
same next-note onset delays bit for bit; G append-only / byte-neutral.

**`CMakeLists.txt`** — one target, the `polarity_check` pattern.

**What DOES sound different** — the two factory patches above, measured
core-direct by compiling one measurement program against `origin/main`'s header
and against this branch's (`scratchpad/b149/measure.cpp`), 2 s of a C4 strike at
44.1 kHz, seed 1234:

| patch | widest onset delay | whole-render RMS Δ | 1/3-octave band deviation, 1–2 s |
|---|---|---|---|
| `MISC - Onset Scatter Ensemble` | 182.5 → **228.2 ms** | 0.0875 (base rms 0.0640) | median 0.37 dB, max **+4.87 dB @ 39 Hz**; every band above 500 Hz within 1.2 dB, above 1 kHz within 0.4 dB |
| `PD - Breath Field` | 125.4 → **156.9 ms** | 0.0724 (base rms 0.0517) | median 0.31 dB, max **−4.28 dB @ 198 Hz**; every band above 500 Hz within 1.1 dB, above 1 kHz within 0.5 dB |

Character, stated plainly: **the same gesture, a different take of it.** The
16 voices enter in a different ragged order, so the whole note's beating pattern
is re-drawn — the difference envelope is not confined to the attack, it persists
for the full 2 s (>5 % of its own peak out to 1980 ms) because the voices stay
permanently offset from one another. But it is re-drawn *within the same
distribution*: the spectral deviation is confined to the fundamental and
sub-fundamental region where a 16-voice detuned cluster beats (≤ 500 Hz),
median 0.3 dB across the band set, and nothing above 1 kHz moves. The patches'
onset spread got wider by 25 % on this seed, which is a draw of the same
distribution, not a change in it.

## Alternatives rejected

- **Reset `tRng` on every `rebuild()`, as `grng` is** — rejected: `rebuild()`
  fires on width/topo/pan/law/oversample, so any automation of those would
  rewind the ensemble's accumulated `tOff`, which is the one thing ADR-077
  exists to accumulate.
- **Also zero `tOff` on every rebuild** — same reason.
- **Write `ens=` unconditionally** — rejected: it would change the bytes of every
  saved patch and force a regeneration of the three state fixtures and a re-save
  of the factory bank, destroying the regression proof that this change is
  byte-neutral where the feature is off.
- **Assert whole-render bit-identity of a mid-phrase restore** — rejected as
  false, and `tseed_check`'s header says so rather than quietly weakening the
  claim. Three other quantities cross a note boundary and none is in the chunk:
  the voice-slot allocator's ages (a released slot is reused in a different
  order after a restore), the per-voice phase stream's `age * 7919` term, and
  `lastPhase`/`lastNoteF`. The assertion that IS made is the one this change is
  responsible for: the next note's per-voice onset delays, bit for bit.

## Calibration transcript (the must-fail control)

`ensembleSeed()` planted back to `return 12345` (the pre-B149 literal), same
build, `build-release/tseed_check`:

```
A  seed 1234 vs 999999, ensemble ON : RMS diff = 0.000e+00 (audit A, before the fix: 0.000e+00)
FAIL A1 the seed reaches the ensemble-timing stream (must DIFFER)
...
FAIL tseed_check: 1 failure(s)          exit 1
```

That reproduces the audit's A to the digit. The header restored, the same binary
reads `9.087e-02` and exits 0. Full transcripts:
`scratchpad/b149/planted.out`, `scratchpad/b149/fixed.out`.

Two bugs in the check itself are recorded because both produced a GREEN that
meant nothing: (1) `std::vector<float> L{kBlock}` is *one* element of value 256,
not 256 elements — every assertion printed OK and the process then aborted
(SIGABRT) after the last line; (2) an earlier section A set `retrig 0`, which
hands the seed to the phase stream, so the planted-literal control PASSED at
1.373e-01. Section B (attribution, must read exactly 0.0) is what now makes the
section-A number mean what it says.

## Open questions

1. **Wiring `tseed_check` into `./verify` is the human's call** (charter). It
   runs in ~3 s and is self-contained; the lead's recommendation is the
   deliverable, not mine.
2. **Bit-identity of a mid-phrase restore is still false**, now for three named
   reasons and not for this one (voice-slot ages, the phase stream's `age` term,
   `lastPhase`/`lastNoteF`). If ACCEPTANCE L0-13 is meant to cover a mid-phrase
   restore rather than a fresh-instance replay, that is a separate queue item and
   a much larger state capture. This change does not close it and does not claim
   to.
3. **`plug_reset()` does not clear the ensemble history.** A transport reset
   arguably should re-roll it; the argument for leaving it is that ADR-077's
   memory is patch behaviour, not transport state. Unqueued, unresolved.
4. The `ens=` payload is a fixed 32 offsets regardless of `n`, ~450 bytes on the
   patches that write it. Sized for a round trip that survives an `n` change; if
   chunk size ever matters, trimming to `voiceCount()` is a lossy choice that
   should be a ruling, not a tidy-up.
