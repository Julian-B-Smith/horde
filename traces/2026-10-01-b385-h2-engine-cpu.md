# b385-h2-engine-cpu — the composed engine's CPU against the golden and the blade port (checkpoint 4)

- **Queue item:** ROADMAP B385, checkpoint 4 (Layer-E, ADR-187 item 8: measured by hand, never a gate).
- **Why:** the brief asks for the engine's CPU through `tools/auhost --horde`, pointed at the new engine, against
  the JS and against `razor_core.h` alone.
- **What changed:**
  - `tools/measure_h2_engine.cpp` (new, unwired): the `measure_h2_scalpel` pattern on the engine's bench
    stream (`node tools/h2_engine_render.mjs --bench --emit`).
  - Its CMake target (additive), at `-O3 -ffp-contract=off`; `h2_rules_check` counts it among the h2 targets.
  - `docs/port/h2-engine.md`: the CPU section with the tables.
- **Result (Apple M3, loaded; release build, per voice, % of real time):**
  - **Golden JS → engine C++:**
    - Crushed bells 18.01 → 5.90 (3.1×);
    - Glass horde pad 25.81 → 8.69 (3.0×);
    - Quarter sync 3.39 → 0.68 (5.0×).
  - **The engine costs 13–25% more than the blade port alone** (Crushed bells 5.90 against 5.22; Quarter
    sync 0.68 against 0.545).
  - **Through auhost's loop:** the engine is 1.13–1.23× `razor_core.h` across 1, 8 and 16 voices and four
    patches, bit-identical across repeats. 16 voices of Crushed bells read 92% of real time per block on
    one core; Glass horde pad reads 142%.

  `23bc4fe`), not on main.
  - A scratch copy of `auhost.cpp` adds an `--engine` mode: the same `cmdHorde` loop with the engine type and
    double block buffers.
  - It is not committed, because the edit belongs to #886's file. It is a small follow-up once #886 merges.
