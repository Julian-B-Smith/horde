# b156-apz-snap — snap the ADR-074 mode-D allpass pole to zero, and let the oracle see it

- **Queue item:** B156 (ROADMAP row on `lead-records-48`, PR #645).
- **Why:** `denormal_check` (PR #635) counted 334 subnormal OUTPUT samples per
  30 s silent tail on the `super-width + allpass` patch, unchanged at every
  revision back past PR #634 — nothing regressed, and the count was the
  *smaller* half of the defect. `apZ` (`src/swarm_core.h`, the mode-D block)
  has no floor: once every voice is culled the stage's input is exactly 0, the
  recursion degenerates to `apZ *= (1 - apc)`, and the state decays through the
  float32 subnormal band and then **stalls at -2.470e-323 — 5 ULP of double —
  and never moves again**, because `apc * apZ` underflows to zero while `apZ`
  does not. A denormal operand in the allpass multiply on every sample for the
  life of the instance on the ACCEPTANCE L0-6 min-spec x86 (no FTZ) is a worse
  cost than 167 transient samples, and no oracle could see it: `apZ` was
  private with no accessor, which the check's own NOT COVERED note said.

## What changed

1. **`src/swarm_core.h`, the mode-D stage.** After the pole update,
   `if (std::fabs(apZ) < apSnap) apZ = 0;` with
   `apSnap = FLT_MIN / (2 * sideGain)`, hoisted out of the loop.
   **The bound is derived, not tuned, and the derivation is in the file:** with
   `mid == 0` and the input `side == 0` the stage's two stores are exactly
   `+/- 2*apZ*sideGain`, so requiring that magnitude to fall below the smallest
   *normal* float32 gives `|apZ| < FLT_MIN / (2*sideGain)`. At width 1.3
   (`sideGain` 1.36) that is 4.322e-39, matching the verifier's ~4.3e-39; it is
   computed from `sideGain`, so it rescales with width instead of being a
   pasted constant. Nothing is expressed per tick (ADR-009 does not apply — this
   is amplitude, not a time constant). `#include <limits>` added with it.
2. **`src/swarm_core.h`, three accessors** beside `voiceAt`: `allpassZ()`,
   `halfbandTapAt(int)`, `halfbandTapCount()`. Read-only, parity-neutral, same
   contract as the accessors they sit with.
3. **`tools/denormal_check.cpp`.** Reads both states directly; folds `apZ` into
   the existing STATE count; adds four assertions and a sample-accurate section
   (below); rewrites the NOT COVERED note because it is now covered, and
   corrects a factual error in it (below).

## The `hb[]` finding — the brief's premise was wrong, and the check now proves it

`hb[]` is **not** "the ADR-075 halfband history". It is the 63-tap
windowed-sinc **coefficient kernel**, written once in the constructor
(`swarm_core.h`, the ADR-075 block: `hb[i] = sinc * win` then `hb[i] /= g`) and
never written again; the only other site reads it (`aL += hb[t] * s.osZL[k]`).
The decimator's actual history is the per-voice `osZL[]`/`osZR[]`, which
`denormal_check` has covered through `voiceAt()` since day one.

Measured rather than asserted: the taps are snapshotted before the first render
and compared bit-for-bit after the 30 s tail on all three patches. **Floor
`|hb[i]| = 1.391e-19`** (the Blackman edge taps, where `0.42 - 0.5 + 0.08`
leaves ~1.4e-17 of double residue rather than an exact zero), **0 subnormal
taps, 0 rewrites.** A constant kernel cannot stall, so **no snap is applied to
`hb[]`** — there is nothing to snap. This is a recorded coverage boundary
(L0033): the `hb[]` assertion correctly does NOT fire under the plant below.

## The must-fire control (L0032)

`denormal_check` built against a scratch copy of `swarm_core.h` with the snap
line, and only that line, removed:

```
super-width + allpass (width 1.3, superMode 3)  out 334/2646000  state 1 in apZ  smallest out 1.401e-45  apZ -2.470e-323
FAIL   30 s of silent tail contains no subnormal OUTPUT sample  (334 ...)
FAIL   no smoother or integrator STATE holds a subnormal  (1 ...)
FAIL   the mode-D allpass pole ARRIVES at zero, it does not stall  (1 ...)
FAIL   apZ reaches exactly 0 within the decay-derived N samples  (reached 0 after -1 samples; derived bound N = 736)
FAIL   it arrives by the SNAP, not by a double underflowing (smallest non-zero |apZ| 2.506e-262 vs threshold 4.322e-39)
denormal_check: RED (5 failures)
```

Every added assertion fires on the pre-B156 engine; the two CONTROL assertions
(the pole was live during the note; the tail starts with a culled voice and a
non-zero pole) pass on both, which is what keeps the RED from being vacuous.
The `-2.470e-323` is the stall the ROADMAP row predicted, measured.

Post-fix, the same file:

```
baseline (width 0.8, superMode 0)     out 0/2646000  state 0  smallest out 7.975e-10  apZ 0.000e+00
super-width, ITD only (width 1.3, m1) out 0/2646000  state 0  smallest out 8.315e-10  apZ 0.000e+00
super-width + allpass (width 1.3, m3) out 0/2646000  state 0  smallest out 1.275e-38  apZ 0.000e+00
held-note peak |apZ| 9.729e-02   cull at +64989 samples after note-off, |apZ| there 2.686e-07
snap threshold FLT_MIN/(2*1.36) = 4.322e-39   derived bound N = 736 samples (16.7 ms)
reached exactly 0 after 735 samples of silence; smallest non-zero |apZ| on the way 4.335e-39
denormal_check: GREEN (0 failures)
```

`N` is closed-form from the decay, not chosen:
`N = ceil( ln(T / |apZ_cull|) / ln(1 - apc) ) + 1` with `T` the engine's own
threshold and `apc` the stage's own coefficient (spelled `hypersaw::kTau`, not
`M_PI` — L0003). Change the 700 Hz corner and `N` follows it.

## Alternatives rejected

- **Raising `denormal_check`'s threshold / counting only "enough" subnormals.**
  That is weakening a gate to hide a real engine defect, and it would have left
  the stall — the expensive half — entirely unmeasured.
- **Snapping only when the stage's input `side` is exactly 0** (the textbook
  silence guard). Rejected: it needs a second condition to express the same
  bound, and it still would not bound the *output* effect, which is the
  property acceptance (a) states. The magnitude bound is one comparison and is
  derivable from the two stores beside it.
- **A fixed literal 4.3e-39.** Rejected: it is only correct at width 1.3.
  `FLT_MIN / (2*sideGain)` is the same number at that width and stays correct
  as width moves.
- **Snapping `hb[]` too.** Rejected on evidence: it is a constant kernel with a
  1.391e-19 floor and zero writes after construction (measured above). Snapping
  a constant would be a change with no defect behind it.
- **Flushing `apZ` in the voice cull instead.** Rejected: the cull is per-voice
  and `apZ` is a post-mix core-level state; the mode-D stage runs whenever the
  guard holds, regardless of which voices exist, so the guard is the right
  place and the cull is not.

## Residue, stated rather than argued away

With `mid != 0` the snap perturbs the double sum by at most `FLT_MIN` before
the float32 store, which could in principle flip a result sitting on an exact
rounding tie. That case is not excluded by construction; it is excluded by
measurement — 12.7 M samples across every mode/width/release row, 0 normal
values changed — and by the fact that reaching `|apZ| < 4.3e-39` at all
requires the geometric decay into silence, which only happens when `mid` is
already 0. The comment in `swarm_core.h` says exactly this rather than claiming
a proof it does not have.

## Open questions

1. **`denormal_check` is still not wired into `./verify`.** Out of this brief's
   scope by instruction — the lead wires it once this is green. Until then the
   snap is pinned by a binary nobody runs.
2. **The ~4.3e-39 bound is FLT_MIN-based, not FLT_TRUE_MIN-based.** It
   guarantees "no *normal* float32 output sample changes". A stricter bound
   (`FLT_TRUE_MIN / (2*sideGain)`) would guarantee "no output sample changes at
   all" but would leave ~150 samples per tail still subnormal, i.e. it would not
   fix the defect. The looser bound is the deliberate choice and the 12.7 M
   sample comparison is what licenses it.
3. **This is still evidence about the METRIC on an M3, not about x86.** The
   check's own caveat stands: this machine cannot show the stall's *cost*, only
   its *existence*. The existence is now measured (`-2.470e-323`, permanent);
   the cost on the L0-6 min-spec remains unmeasured here.
4. **Three FX cores and the shell have the same class of state** and no
   equivalent oracle — `denormal_check` measures `SwarmCore` only. Named, not
   fixed.
