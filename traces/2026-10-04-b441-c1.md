# b441-c1 — member overrides once per sample, not once per oversampled step

- **Queue item:** ROADMAP B441 phase 2, candidate C1 (the phase-1(B) optimisation audit's top output-neutral candidate). Lead brief of 2026-10-04 ("start C1", the human).
- **Why:** In `Engine::renderCall` (`h2/engine/engine.h`), each member's overrides of the shared parameters were recomputed at every oversampled step, but none of their inputs changes within a sample. They are now computed at `j == 0` into `memberOv[voice][member]` and replayed at `j >= 1`. The overrides are `s.w`, `s.depth`, `s.I`, the cut phase `c`, the cut rate `kq` with its `kCap`, `s.mEff`, and blade 2's `bx.c`, `bx.k`, `fillG2` view, `bx.mr` and `bx.mn`. The same expressions run in the same order, once. Blade 2's view lives in the member, so at `j >= 1` it is skipped outright. ROADMAP B441 phase 2 requires each experiment to "leave every parity digest unchanged (output-neutral; ADR-187 §5) ... plus a measured speedup under the frozen protocol, with the ledger updated".
- **The proof that the hoist is bit-identical:** every input is written only per sample or slower, never inside the `j` loop.
  - The per-sample voice pass writes `v.gr`, `v.kE`, `v.kE2`, `v.wE`, `v.wE2`, `v.rot`, `v.rot2`, `mm.rot`, `mm.rot2`, `gRot` and `gRot2`.
  - The smoothers write `s.*`, and `w0`, `d0` and `I0` are snapshots taken before the loop. `d.*` is fixed for the whole call.
  - `couple()` and `spread()` write `mm.inc`, `lead`, `cOff*`, `kAdd*`, `kMul*`, `wMul*`, `dAdd*`, `iMul*`, `mr*` and `mn*`, every 32 samples, before the loop.
  - Inside the loop, `stepMember`'s swarm work writes only `v.sw`, `v.tick0`, `v.gf0`/`gfb`, `v.env` and the members' entry and envelope state: `tickSwarm`, `syncSwarm` (which writes `field.p` and `gCoefS`), `unLookAhead` and `memberStep`.
  - The DC estimates write only the scratch states `sc`, `sc2` and `bxs`, and they restore `gmr`/`gmn`.
  - `fillG2` reads none of the four fields the block overrides.
  - `mm.bx.c/k/mr/mn` and `m.g2` are written by this block alone (grep of `engine.h`).
  - `v.active` changes only per sample (the release envelope) or between calls (`renderCalls`, `noteOn`).
- **Evidence (verified, by oracle):**
  - `h2_engine_selfdigest_check` and `h2_engine_selfdigest_product`: GREEN, 543 of 543 bit-identical against the committed references. TOTAL is `4d1ad7f1ed674d88` and equals the reference. **No re-pin.**
  - `h2_engine_parity_check`: GREEN, 540/543, with 3 chaotic rows excluded and 0 red.
  - **Must-fail control** (planted locally, never committed): the first step of each sample replays the PREVIOUS sample's cache. The self-digest went RED with 530 of 543 rows differing (exit 1). So the digest sees a stale cache.
  - **libm census** (`tools/h2_libm_count.py`): "matches h2/engine/libm-calls.darwin-arm64.appleclang-16.txt". Product TOTAL is 272 and parity TOTAL is 239; no function's count moved. The counts file is unchanged.
- **Measured (Layer-E):** see `docs/port/cpu-ledger.md` §2b. The run was two interleaved rounds of before/after whole-ledger passes, at 44.1 and 48 kHz, with calibration at 185.7–187.0 ms and load 1.78–3.41.
  - **8 voices:** 2.4–5.6 % faster on six presets (Glass horde pad 5.4–5.5 % at 44.1 kHz) and 0–1 % on Quarter sync. The audit's estimate was 8–15 %.
  - **1 voice:** the six presets move −1.2 % to +4.2 %. Quarter sync (N 1) is 9–12 % slower in every round and at both rates.
  - **Slice verdict at 44.1 kHz:** Fold over sync crosses under the 34 % slice (34.7 → 33.8 %, with the ×1.5 factor ASSUMED).
- **Tool:** `measure_h2_engine --sr`. This is protocol B441-2: 44.1 kHz is the reference and the default (the lead's E-6 ruling), and 48 kHz is the secondary. The rows now carry `"protocol":"B441-2"`.

- **Alternatives rejected:**
  - **Putting the cache in `Member`.** That would mean editing `blade.h`, which was outside the brief's named file.
  - **A stack-local cache in `renderCall`.** An Engine member is preallocated and zero-initialised, so an impossible read-before-write still reads defined values.
  - **Restoring the whole block per step and caching only the divisions.** It would not be bit-different, but it saves less.
- **Verify:** `./verify fast` exit 0 at `96f211e` (the engine commit). `./verify fast` and `./verify full` on the head that adds this trace are recorded in the PR body, each with `.harness/last-verify.json`.
- **Open questions:**
  1. **Why is C1 well under its estimate, and why does Quarter sync regress at 1 voice?** This is a hypothesis: a fixed per-sample cost that the cache-replay path adds, which N = 1 cannot amortise, or a code-layout or inlining change around `stepMember`. It is not profiled. E0's profile would settle it.
  2. **The tool's default rate is now 44.1 kHz.** This also applies to `--hold`, `--sweep` and `--stages`, so a bare B441-1 command line no longer reproduces its 48 kHz cell without `--sr 48000`. Is that the intended reading of the E-6 ruling?
