# b23-osc-sources-2 — the routing id renumbering, then the second oscillator source

- **Queue item:** B146 / B23 increment 3 (the re-dispatch after PR #636 stopped
  on a measured id collision).

- **Why:** PR #636 proved that widening the matrix by a SOURCE moved every
  slot's crosspoint id, because `from` packed sources and slots into one
  contiguous coordinate. The human ruled option (A) on 2026-09-18 — "Let's
  renumber now, I haven't built any new presets or saved any files that would
  lean on them" (ADR-088 amendment) — so the id's `from` reserves eight SOURCE
  rows and the slots begin at row 8. After that the second source is an
  append, not a shift, and no future source or slot ever moves an id again.

Six ids move (the six slot→slot crosspoints); four Src-1 ids, all four out
amounts, all four slot inits and `22000` do not. **No migration shim, and that
is a fact about the tree rather than a decision:** the `routing` chunk is
sparse and is written only for cells that differ from the series default, so no
tracked file contains a routing chunk at all (`bank_check` re-saves all 40
factory patches byte-for-byte, and none names `routing=`; `routing_check`
assertion 12 asserts the silence). Nothing exists to migrate.

## What changed

**`decodeRoutingId` speaks ROWS, the matrix speaks INDICES, and there is one
translation.** `routingRowOfIndex` / `routingIndexOfRow` in
`src/hypersaw_clap.cpp`; every site that holds one and needs the other calls
them — `makeRoutingTable` (which now loops ROWS, so the reserved source rows
simply decode false), `set`/`getRoutingParam`, and the debug exports
`hypersaw_debug_routing` / `_on`, which take rows because `routing_check` reads
`from` off the id list and hands it straight back. `routingIndexOfRow` returns
-1 for a reserved-but-unfilled row, so a caller that forgets to check indexes
out of bounds rather than landing on cell 0. The coreKEYS of every pre-existing
cell are unchanged (`rt.c.m0.1` still names Slot 1 → Slot 2); only the numeric
ids moved.

**The second source.** `RoutingMatrixT = RoutingMatrix<2, kRackSlots>`, and the
Plugin's matrix member is now that alias rather than a second spelling of the
template arguments. `renderSpan` KEEPS oscillator k's chunk in source k's
buffer instead of summing it into oscillator 0's. Source 0 is still the output
buffer; sources 1.. are fixed-size members (`kSrcBufFrames` = 32768 frames,
~0.74 s at 44.1 kHz), zeroed for the whole block before the span loop — which
is what makes "a disabled oscillator's source is silent" true for every path at
once (a switched-off oscillator, the SPECTRA branch, a span the bend grid never
reaches) instead of at three skip sites.

**Preallocation, and the refusal that goes with it.** The buffers are NOT sized
at `activate()`: a buffer whose existence depends on activate having run is the
trap `renderSpan`'s own comment records (a heap scratch sized there once made
audible output conditional on it, and a restored instance silently lost
oscillator 1). The two places that could exceed the fixed size REFUSE rather
than truncate — `plug_activate` returns false above `kSrcBufFrames` (its
`maxFrames` argument was unused until now), and `process` returns
`CLAP_PROCESS_ERROR`. A partial split would be silently-wrong routing and an
unchecked write would be memory corruption; neither is an acceptable
alternative to a loud refusal. `rtsafety_probe` (block sizes 33..2048) is GREEN.

**Bass-mono `pre` is one stage PER SOURCE**, each with its own integrator pair
(`bmIc1[kRoutingNSrc]`), because `pre` means "before the matrix" and a single
stage over source 0 would leave the others unfiltered. Both reset sites go
through one `clearBassMonoState()`. This is inert on every shipped patch:
`bassMono` defaults to 0.

**The morph layout marker steps 4 → 5** — the renumbered ids are new slot
positions in the field (the routing block is appended last and shares one lead
index, B142) — at the three shell writers, in `gen_factory_bank` and in
`bank_check`'s expectation. The 40 factory patches and 4 corner presets are
regenerated: corner arrays 243 → 248 slots, marker 5, new build stamp, nothing
else. `morphlayout_check` T1b ("everything after the prefix is ≥ 10000") still
holds — PASS.

**The GUI pane** (`#mxPane` only). `mxShape` gains `srcRows`, DISCOVERED as the
lowest coeff row that is not a source row, so neither the source count nor the
slot-row base is a literal and a third source needs no edit here. `mxRowOf` is
the single display-row → id-row translation, used by the well's grid and by the
rail's terminal test, reachability walk and slot→slot ribbons. `mxDefault` now
knows that EVERY source feeds slot 1 at unity, not just the first.

## The parity measurement

**No parity moved, and the default is bit-identical by CONSTRUCTION rather than
by a measurement agreeing afterwards.** The acyclic gather accumulates in float:
`slot[i] = 0.0f; slot[i] += (float)(1.0*src0[i]); slot[i] += (float)(1.0*src1[i])`
is the same two roundings, in the same order, that `outL[i] += tL[i]` performed
before. `setSerialChain` gives every source coeff exactly 1.0 into slot 0, so
the terms and their order are the old summed bus.

- `parity_check: 156/156 scenarios within eps=1e-06 (worst 4.262e-09 @
  dyn-ring.seed42)` — **the same worst delta as PR #636's run.** No
  re-baseline was needed and none was taken. (Stated precisely: parity_check
  measures the CORE against the JS reference and does not span the shell's
  source split at all — L0031. The shell-level claim is the one below.)
- `routing_check` assertion 24 is the shell-level oracle for it: for every
  sample of a 1024-sample render, `both[i] == (float)(only1[i] + only2[i])`
  EXACTLY — 0 of 1024 differ. Equality, no tolerance, because a tolerance here
  would hide the very re-ordering the acceptance criterion is about.
- `state_check`, `bank_check` (40 × "re-save is bit-identical"), `preset_check`
  and the seven golden chains are all green with no golden regenerated.

## The aliasing decision, restated

`traces/2026-09-17-b50-dry-path.md` recorded that `processBlock`'s dry term
INITIALISES the output because `outL/outR` may alias a source buffer. **That is
still load-bearing and nothing was changed.** Separate buffers removed the alias
for sources 1.., not for source 0 — oscillator 0 still renders straight into the
output buffer, which the rack also writes. Giving source 0 its own buffer would
cost a per-block copy and change nothing an oracle can see, so it was not done;
the constraint is now recorded at the buffers' declaration as well as in
routing_core.h, because that is where the next person will add source 3.

## Oracles added, and their calibration

`routing_check` gains two assertions (24 cells, 24 assertions, GREEN):

- **23, two sources feeding different slots keep their signals separate.**
  osc 1 → slot 1 only, osc 2 → slot 3 only, slot 1 is Drive at 0.9. The
  nonlinearity IS the measurement: a linear slot would pass whether the sources
  were split or summed. Four renders, not two, so a shaper's `f(0)` cancels:
  `both - only1 - only2 + neither`. Result 2.98e-08 (must be ~0); the must-fail
  control — osc 2 ALSO into the drive — reads 0.161.
- **24, the two-source default renders the old summed bus**, above.
  **A control that did not fire, on the first draft:** moving osc 2's crosspoint
  to 0.5 in ALL THREE renders left the identity exactly true, because `both` and
  `only2` scale together — it measured the crosspoint's linearity (assertion
  8's job), not the summation order. Recorded rather than quietly re-rolled
  (L0033). The control now moves the gain in the COMBINED render only and reads
  1024 of 1024 samples differing.

`paramclass_check`, the two edits the brief names: T1a's pin 243 → 244 (B146
appended `bassMonoPos`; the pin is meant to be moved by the change that adds the
row), and T4 now excludes ids ≥ 10000 — routing ids are not per-osc twins, the
crosspoint block being a positional namespace of its own (`decodeRoutingId`), so
`id - 1000` named no parameter and 14 comparisons reported an artefact of the
subtraction. Red since B50 phase 1; **PASSED (0 failures)** now.

**The GUI evidence is a headless DOM/canvas dump, with a plant** (scratch —
see Open questions). The well builds six rows — `Src 1`, `Src 2`, `Slot 1`…
`Slot 4` — with `Src 2 > Slot 1 [cell 10064]` where the brief asks for it, and
`mxDefault` agrees with `setSerialChain` cell for cell (1 at 10000, 10064,
10513, 10578, 10643, 20003; 0 everywhere else). The rail paints `SRC1 SRC2 S1

## Alternatives rejected

- **Keep `decodeRoutingId` returning the matrix index** and convert only inside
  `routingCoeffId`. Fewer edits, and rejected: the debug export, the GUI and the
  oracle would then each hold a different idea of what `from` means, which is
  the two-coordinate-spaces hazard the amendment exists to end. Rows outward,
  indices inward, one translation.
- **Size the source buffers at `activate()`** from the host's declared maximum.
  Rejected on the recorded scar: a buffer whose existence depends on activate
  is how a restored instance silently lost an oscillator.
- **Give source 0 its own buffer too**, to delete the alias. Rejected: a
  per-block copy for no observable difference; the alias is safe under
  `processBlock`'s stated ordering and is now documented at both ends.
- **A migration shim for layout-4 corner arrays.** Rejected as unnecessary,
  not as out of scope: no tracked file carries a routing chunk, and the bank
  regenerates. Said out loud because "no shim" should never be silent.
- **Restructuring `process()` into segments** so the source buffers could be
  one chunk long. Rejected: it would move the rack's and the viz feed's block
  boundaries, which is exactly the kind of change that costs a golden.

## Open questions

1. **`kSrcBufFrames` is a ceiling the plugin now refuses above.** 32768 frames
   is past any host block size I know of, but the refusal is a behaviour change
   at the CLAP surface (`activate` can now return false) and deserves the
   human's eye. The alternative shapes are all worse; the number is the part
   that is a judgement.
2. **The GUI probes live in the session scratchpad**, not in `tools/`. The
   brief scoped no new harness file, and landing them as gates needs a
   `tools/labharness/` file plus a `./verify` line.
3. **No screenshots.** The pane and rail evidence is a headless DOM/canvas dump
   with a calibration plant, not a render.
4. **ADR candidates** (not filed — `DECISIONS.md` is out of scope):
   *(a)* the id's ROW vs the matrix's INDEX as two coordinate spaces with one
   named translation, and the rule that everything outside `routing_core.h`
   speaks rows; *(b)* a fixed-size audio-thread buffer whose ceiling is refused
   at `activate` and again in `process`, rather than sized at activate — the
   general form of the ADR-099 scar; *(c)* `pre`-placed output-stage filters
   are per-SOURCE once sources multiply, which the sub-osc and every future
   source inherits.
5. **The sub-osc is source 3 and takes row 2.** Nothing in this change reserves
   it beyond `kRoutingMaxSrc`; B155's stream will add it by bumping
   `kRoutingNSrc`, and no id will move.
