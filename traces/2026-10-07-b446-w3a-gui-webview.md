# b446-w3a-gui-webview — the GUI loads only its embedded page; a content security policy is applied; dropdown text is set as text; page script has no clipboard read

- **Queue item:** ROADMAP B446 (security overhaul), P1 Wave 3, item W3a (P1 plan item B6). Lead brief of 2026-10-07 (horde lead session; the human: "start Wave 3", after ADR-194). Under B446's disclosure rule the P1 plan and its acceptance text are held privately, so the brief carried the acceptance criteria rather than quoting ROADMAP.
- **Why:** the plugin GUI is a web page with a native bridge. The page should be the only document the view ever shows, run only the scripts it was built with, treat names from disk as text, and have no clipboard read of its own.
- **What changed:**
  - `src/gui/hypersaw_gui.mm` (macOS): `lockToEmbeddedPage`, installed from choc's ready callback before `setHTML`. A navigation delegate admits exactly one load (the embedded page, `about:blank`) and cancels every later navigation in every frame; the bridge's message handler is re-registered behind a main-frame check and forwards to choc's handler; choc's `javaScriptCanAccessClipboard` and `DOMPasteAllowed` are turned off. The guard is a runtime class with a unique name (choc's `createDelegateClass`), so two plugin builds in one host cannot collide. New binding `hzPasteState`: reads the pasteboard natively and applies it as a patch, returning only a status.
  - `tools/embed_file.py`: an `.html` embed gets a Content-Security-Policy meta: `default-src 'none'; script-src 'sha256-…'` (one hash per inline script, computed from the embedded bytes); `style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`. The build refuses a page with an inline handler attribute, an external script, a `javascript:` URL or its own policy.
  - `src/gui/gui2.html`: the preset, corner-preset and scale dropdowns are built with `new Option(text, value)`; the scheme/mode chips and the corner labels with DOM nodes. The unused `esc` helper is deleted. `presetStore.list` takes the typed listing. PASTE uses `hzPasteState` where it is bound (the macOS plugin) and the page's own path elsewhere.
  - `src/gui/hypersaw_gui_common.h`: `hzPresetList` returns typed arrays (`{presets, corners, factory}`) built from `bridgeStr` values, replacing hand-concatenated JSON.
  - New checks, wired (ADR-180 §1): `tools/gui_sink_check.py` (`./verify fast`; HTML sinks in `src/gui/*.html` take literals only, one named exception with its reason; the embedded policy's shape and hashes; 20 in-memory controls) and `tools/gui_webview_check.mm` (`./verify full` on macOS; the shipped plugin GUI on a real WKWebView, 16 rows, plus 8 CONTROL rows on a plain choc view). `CMakeLists.txt` gains the probe's target (APPLE only).
- **Not changed, on purpose:** `libs/choc` (ADR-194 D-S5: wrapper first); the Windows backend (`hypersaw_gui_win.cpp`): choc keeps the WebView2 objects private, so the navigation and sender rules need a choc change there; the lead holds that note. The policy, the dropdown fix and the typed listing apply on both platforms. `gui.html` needed nothing beyond the policy (its one sink is a literal).
- **Evidence consulted:** the brief; the private P0 lane-2 report (W2-02, -03, -04, -10) and P1 plan item B6; ADR-194; `libs/choc/choc/gui/choc_WebView.h` (Apple `Pimpl::initialise`, the delegate class, `bind`, `invokeBinding`) and `choc/platform/choc_ObjectiveCHelpers.h`; WebKit SDK headers (`WKNavigationDelegate.h`, `WKScriptMessage.h`, `WKFrameInfo.h`); `src/gui/*` sources; `tools/labharness/lab_load_check.mjs` and `gui_history_check.mjs` (stub DOMs); `tools/test_table_check.py` (wiring rule); the W1a trace.
- **Controls, before and after.** "Before" = `gui_webview_check` built against an export of `origin/main` 0bfb255 (submodules linked from this worktree); "after" = this branch.
  - `gui_webview_check` before: exit 1, `FAIL (24 rows, 12 failed)` — both NAMES rows (typed listing absent; the dropdowns lost the names), both CSP rows (`__pwnScript=1`, `__pwnImg=1`), FRAME (`'FRAMEPOST'` delivered), all three CLIPBOARD rows (`{"ret":true,"fired":true}`, preferences `1/1`, no `hzPasteState`), four NAV rows (`replaced:about:blank bridge=function`). The 8 CONTROL rows passed. After: `OK (24 rows, 0 failed)`, with BOOT reporting zero policy violations and `hzGetBuild` resolving under the policy.
  - `gui_sink_check` on `origin/main`'s `gui2.html`: exit 1, 7 non-literal sinks (2122, 2183, 2726, 2946, 2970, 5525 — the last one is the excepted readout, flagged here because exceptions are keyed by file name — and 7037). On a copy of this branch's `gui2.html` with a planted `document.body.innerHTML = name;`: exit 1, the planted line named. On this tree: `OK (2 pages, 5 sinks, 1 excepted, 20 controls)`.
  - A file name containing `"` or markup lists and renders as text (NAMES rows above). WebKit's select parser dropped the markup element even before the fix (`imgs: 0`), but the name text was lost and the quote made the listing unparseable.
- **Alternatives rejected:** patching `libs/choc` for a navigation option (human gate; not needed on macOS); `class_addMethod` on choc's own delegate class (the audit's brittle option; a separate delegate object is cleaner); leaving `DOMPasteAllowed` on because PASTE needs it (a native read keeps PASTE working and gives the page nothing); `queryCommandSupported('paste')` as the clipboard detector (reads `true` both ways, measured; the probe uses a gesture-free `execCommand('paste')` whose handler never calls `getData`, so it reads no clipboard content); an old-tree rebuild by overwriting this worktree's sources (refused by the permission layer; an exported copy was used instead).

No load-flaky gate failed, so no standalone re-run was needed. (The first fast run was red on `include_check`, `<string>` missing in `hypersaw_gui.mm`; fixed in scope.) No browser was used; the probe runs WebKit in-process.
- **Open questions:** PASTE's native path is bound and tested for presence only; applying a pasted patch was not exercised, because that needs the user's clipboard (human check: copy a patch, press PASTE in a host). `test_table_check`'s census reads `tools/*_check.{cpp,py,mjs}`, so the `.mm` probe's `WIRED:` header is truthful but uncounted (the lead decides whether to widen the glob). The visible note under COPY/PASTE in `gui2.html` (~1410) still describes an older PASTE.
