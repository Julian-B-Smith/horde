The five most consequential gaps

These are elements that are ruled but not in the shell, ranked by how central they are to playing the instrument. The ranking is the auditor's judgment; the states are evidence.
1
Main's performance surface
ADR-176 decision 5, ADR-150, ADR-151, ADR-192, ADR-180 §3–4 · state vendored / ruled · port tab: main-rest, macros
The pad as Main's centre (the bundle's XYPad is vendored but mounted only as the morph pad), the fixed macros Tone, Space, Time and Motion with named macros 5 to 8 (no master component at all), the bend and mod wheels. Main is the page a player lives on, and the shell's Main has only Voice and ENV 1.
2
The oscillator's Kuramoto ring with its blades
ADR-156, ADR-333 · state vendored · port tab: osc-visualizers
The bundle already holds RingXY (the Coupling × Detune gesture), the blade rim arcs and the cross-mod arrows; the shell calls Viz.kuramoto with a SAMPLE point and never mounts RingXY. It is each oscillator's main direct control, and the human asked for it to be copied precisely from the Scalpel bench.
3
The mod matrix page
ADR-266 rulings 1, 3, 4, 6, 7; ADR-136 · state vendored · port tab: modulators
Grid, routes, trace lanes, compact wires, hosted-macro rows, the S&H shape and the retrigger switch are all vendored and unmounted. Map mode writes routes into the device's matrix, but there is no page to see or edit them, and every modulator card is mounted with no retrigger switch.
4
The Specimen and the Specimen XY
ADR-139, ADR-140, ADR-144, ADR-147, ADR-151, ADR-262 ruling 1, ADR-333 · state in-master · port tab: specimen-xy
MAIN's visualizer is fully described in the master's Specimen README but has no bundle export, so by ADR-316 it cannot reach the shell until it is vendored. The README also contradicts ADR-144 (shipped on, not off) and ADR-139 (tension rises with R).
5
Gain staging and the FX rack's module cards
ADR-230, ADR-272 A1, ADR-273 and A1, ADR-259 rulings 4–5 · state vendored · port tab: gain-staging, fx-modules
GainStaging, ChainLine, FxRack and FxCables are vendored and unused: the Mix page shows MOCK meters with no stage view and no home for the make-up gain, and the FX page draws placeholder screens instead of the cream cards with their own screens. The FX device inherits both pages (ADR-254).

What the GUI session should do first

  1. Mount what is already vendored. 35 live rows are in the bundle and not in the shell: no master change, no ruling needed. Start with RingXY and the bladed ring, the matrix page (ModMatrixGrid, RouteRow), GainStaging and ChainLine on Mix, FxRack and FxCables on FX, the census ring, ModCardHeader's retrigger, and XYPad as Main's pad.
  2. Fix the shell defects the audit found. The spectrum's peak hold is passed seconds where the bundle expects milliseconds (gui3.html lines 539 and 668: frame / 60 against a 1500 ms hold, so caps hold about 25 minutes). The Mods | Macros pills ADR-323 ruling 2 rejected are still shown. The keyboard lamp reads KEYS where the master says KEYS OFF. The window is fixed at 980 × 720, not resizable (ADR-259 ruling 2).
  3. Harvest into the bundle what the master only documents. 25 live rows stop at the master: the Specimen, ModuleCard (the hosted-module face), ScreenFrame (the chassis carrying corner colours), KeyboardLamp, the Bend law's drag modes, the parameter menu. ADR-316: harvest first, never draw locally.
  4. Bring the master up to the rulings it contradicts. MapControl still says map keys work only in keyboard mode and draws a 28 px button half (ADR-335 rulings 1 and 3). TempoDivisions predates ADR-326 X37 and ADR-327 X41. The census draws plain dots where ADR-262 ruling 5 wants glyph shapes. EventLanes calls hosted triggers open, which ADR-267 ruling 2 settled. bundle.css loads the fonts from Google Fonts, against ADR-259 ruling 1's bundled faces.
  5. Put the untracked gaps on the port ledger. 47 live rows below the shell have no port-tab row, so the shell's own tab under-reports what is missing. Adding rows is the GUI session's call; removing one stays the human's.
