MAW (ADR-170) is horde's FX-C: the three-stage saturator every source hands off to (ADR-092 amendment, "Maw eats it"). Here it sits in rack slot 1 of horde's FX page. Its face is four role macros (ADR-169; the A2 distillation) over its full panel: three stages, five topologies, fourteen curves. What you hear and see is MAW's own core (reference/maw/core.js, loaded) rendering a horde voice: the composed engine's saw swarm, a SCALPEL patch, noise or a drum. The transfer curves, spectra and drive meter are read from that render. The self-checks below prove each picture against the rendered signal.

HOW TO READ THE WINDOW

  • Rack strip. Voice sum → MAW (slot 1, FX-C) → today's rack types as context (Filter, Delay, Room: src/fx_rack.h FxType). Only MAW renders here. The slot's bypass is the MAW IN / BYPASS button.
  • Face (left, top). The four roles in fixed order (SPEC-MODULE-MACROS §9). Each knob's home reproduces the preset exactly: 0.5 for Amount, Tone and Regen, 0 for Motion. Each has a tier toggle. GLOBAL = on horde's face and in the DAW's list as FX1 <Role> (ids 300 + 8·host + role, ADR-169 A1). CORNER = a per-corner base the morph owns, not DAW-exposed. The readout under each knob shows what it moves.
  • Transfer (right, top). Each stage's static curve, stage input to stage output, with auto-gain, drive-ref, floor and mix. It is read from the rendering instance at the playhead, so modulation, inertia, ecology and flux move it as you listen. The shaded band is where the signal sits: ±the stage's own input follower (SPEC-MAW §2.5). The tone filter is not part of a static curve and is named under it.
  • Spectra. Rack input (ghost) and MAW's output (meter ink), Hann 8192 from the analysis point. The scope beside them shows the same two signals.
  • Drive meter. Per stage over the 2 s loop: the gain into the curve (dB, value ink), the measured auto-gain makeup (physics ink) and the stage's output level (meter area). MAW has no gain-reduction stage. Its dynamics are drive-ref, ecology and the env/LFO drive routes, and all three show here.
  • Inside the module (right, scrolling). Every internal parameter (ADR-169 A2: the face summarises and never hides). None of them is a DAW parameter (ADR-172). A knob's violet arc runs from the authored value to the value after the macros.

OPEN QUESTIONS — MAW IN HORDE (for the human)

  1. Placement. Is FX-C a fixed post-stage (every source → MAW → the rack), or MAW in a matrix slot (B50) that a patch can move? The lab draws slot 1, which reads as both. Recommend: a matrix slot whose default patch puts it first. ADR-172's one-instance rule already makes it singular.
  2. MAW hears notes. The feedback route's pitch tracking reads the last note (SPEC-MAW §6). On a bus-level MAW (D2) that makes it horde's second note-hearing FX, which is B92's registered trigger for the transport ruling. Which note of a chord should it get? The core takes the last; the lab feeds the last note played.
  3. Who authors the macro distillation? MAW's presets carry no macros. The lab's bindings are one proposal: relative, home = the preset (Sluice's G-70 rule), Amount ±18 dB on all stages, Tone shape ±0.5 with cutoff ±2 oct, Motion adding inertia and flux, Regen ±fb. Should MAW's project own per-preset labels and bindings in its preset format, with horde only presenting them?
  4. Regen outside the feedback route. Regen is IDLE on four of five topologies (fx-design-lab's rule, drawn in caution). Should it rebind per route instead, for example to ecology (which is pending its A/B, ADR-170 A1)?
  5. Input level. Static auto-gain and drive are calibrated at 0.5 peak, and the lab normalises every source to it. In horde the voice sum's level is the mix's. Should FX-C get an input trim calibrated to the voice bus, or should drive-ref be on by default?
  6. This is the intake core. reference/maw/core.js still has what MAW's project fixed (ADR-170 A3): the ±1 output clamp (the lab counts clamp hits), NaN poisoning (a self-check control shows it), the mid/side drive-ref follower, and the point-slope feedback normaliser. Should the lab switch to MAW's current core when their module ABI lands?
  7. Oversampling. The lab plays the prototype's per-stage 2× FIR (incidental, SPEC-MAW §10). Horde's global 2× will replace it, so aliasing will be close to what you hear here but not identical, and the ~10-sample per-stage latency will go.
  8. The deep panel on horde. The panel shows everything (A2). Should MAW's internals be mod-matrix destinations, or only its four slots? Host exposure is ADR-172's test and stays off here.
  9. Chrome. The colour-shifting logo is not ported. It is not cheap (td::Warp is ~200 lines), and a later round unifies chrome. Knobs are drag-only, so there is no alt-wheel yet.
