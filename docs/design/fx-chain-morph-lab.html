Two FX chains, L and R, and a morph x between them, done nine ways on the same endpoint pairs. B265's four: A rank keys, B edit path, C an approved-order graph, D naive slot splicing (the control), all but D on one shared router. B266's five, which avoid order collisions by construction: E a fixed order per patch with a per-module mix, F series↔parallel, G a forward-only send matrix, H continuous positions on a spine, and GC the send matrix walking C's approved orders — all on one wiring planner that searches for a legal sequence instead of repairing one. Seven invariants are checked at 601 x positions, each with a planted fault that must fail; the newest is I7, "no node without any inputs should have outputs", read two ways. A fuzzer (tools/labharness/fxmorph_fuzz.mjs) runs the same model on thousands of seeded random pairs and shrinks every failure to a minimal case — the gallery below. It sounds: POWER plays Body and Sub through the chain you LISTEN to.

Feedback — none against one bounded return

Placement rules. F1 a return lands only on a Delay or Reverb input (a module with a delay line, so the loop is never zero-delay). F2 it runs backward: its target sits before its source in the order (the order gate enforces it at every x). F3 gain ≤ , and the return passes through tanh, so the loop is amplitude-bounded whatever the modules do. F4 at most one at any x: two different returns hand over break-before-make (the only place the router breaks first — a return adds no forward path, so I6 is untouched).

The approved set (C, and I4 for everyone)

Every ordered SUBSET of an approved order is approved too (take a module out of a tested chain and it is still a tested chain). The nine are linked by single adjacent swaps into one connected graph; C walks a shortest path through it.
