Open design questions — each with the lab's recommendation

  1. Blade core above the swarm (ACCOUNTING Q I1). The face here is: Coupling × Detune (since round 3, the phase ring itself), Members, Base wave and Volume (the swarm's identity), then both blades. Everything else of the swarm is one level down. Recommend: as built. Coupling × Detune stays on the face because it IS the swarm. Stereo, the amp envelope, Coherence → Tone, Onset, Dissolve, Drift and Pitch drop a level, and a summary strip names any of them that is off its default.
  2. Stacked or tabbed blades (Q I2). The OSC page stacks both blades. MAIN has room for one, so it uses a 1 | 2 selector. Recommend: stacked on OSC, tabbed on MAIN. The cycle view always draws both windows, so a tab never hides the other blade's effect.
  3. The brief puts mirror, FM and spreads on the face; the accounting's §2 puts mirror and the spreads at T2. The lab follows the brief and shows each promotion in the tier table. Recommend: keep mirror on the face. It is four pills, and twin − alone removes the even harmonics. Recommend: keep only Position and Cut spread on the face. The accounting counts every other spread in three or fewer presets. Leave the spread law one level down.
  4. How blade 2's "same as blade 1" reads. Each following control shows blade 1's value with a dashed cap and an =1 mark. Touching it copies blade 1's group into blade 2 and takes ownership (copy-on-write). The =1 pill re-links without erasing blade 2's own values. Recommend: as built. It is stored in the rows that already exist (the −1 sentinels and the b2fm / b2sp / b2env / rot2Follow switches). It adds no parameter.
  5. Two controls named "Width". The blade's Width (id 303) and the swarm's stereo Width (id 14, a SCALPEL merge) would sit on the same page. Recommend: rename the swarm's to "Stereo" in the presentation table and the host name. That is a B224-style label change, and it moves no id. The lab already calls it Stereo.
  6. Knobs, sliders or direct manipulation. Recommend: knobs (A) as the face, with CYCLE EDITS on. Knobs carry gui2's modulation halo and morph stripe. Direct edits on the cycle view give the "intuitive" feel the human asked for. They write the same addresses through the same path, so that is a view and not a second parameter (B212 decision 6). Skin C (no knobs) loses the halo, and the modulation view with it. Skin B belongs in the depths, where it already is.
  7. How a window is drawn. Recommend: II GATE. A plain band hides Edges and Depth. The gate shape draws the real taper g(e)·depth (SPEC §4.1), so both read at a glance, and it still uses only standard tokens.
  8. Blade 2's identity. The standard gives blade 2 the same authored colour, hatched. The HUE alternative adds a token, and every named colour in the set is a status. Recommend: the hatch. Adopt a hue only if the human wants one, as an ADR-116 amendment.
  9. Position is a circle. The Position knob here has no end stops. The MAIN morph blends it on the shortest arc (toggle CIRCULAR off to see today's linear blend run 0.95 → 0.05 through 0.5). Recommend: an endless dial plus a circular morph rule in the shell (ACCOUNTING finding 5). The matrix clamp needs the same rule.
  10. The Coupling axis voices the oracle's law. Superseded in round 7: the lab plays horde's law now (question 45). The accounting recommends horde's law (§1.6), which couples 1–9× softer at the same K. The ring's feel will change when that lands. Recommend: settle the law in the B252 discussion first, then re-label the ring's y axis from the measured lock boundary, not from K.
  11. What the cycle view cannot show. Cross-mod and feedback act sample to sample. Round 3: cross-mod is now drawn (question 23). Feedback still is not: the cycle shows the blades without it. Recommend: accept feedback as undrawn for v1. Add it through the same three-pass estimate only if the human asks.
  12. Visualizers on MAIN. Recommend: the cycle view and the ring on MAIN, and the spectrum on OSC only. The formant band is a sound-design read, not a performance read.

Round 2 (B293) — open questions

  1. What does a drag on the waveform target? Width, cut rate and position exist once per blade. As built, a drag moves the blade whose window is under the pointer when you grab it. Grabbing empty space moves every blade that is on, each by the same amount along its own taper, so their relation holds. The target is outlined in the attention ink while you hover and while you drag. Recommend: as built. The alternatives are "always blade 1" or following the MAIN page's 1 | 2 selector. Both hide which blade moves until you hear it.
  2. Relative, not absolute. The bench's pad is absolute: the puck is the value, so a grab jumps the sound to the pointer. The waveform has no puck, because its x axis is phase. So every drag here is a delta from the value at grab, and a grab alone moves nothing. Recommend: keep it relative. The MAIN page's XY pad stays absolute because it does have a puck.
  3. CYCLE EDITS and the XY share one surface. With CYCLE EDITS on (or skin C), round 1's grips take the waveform back: drag a window to move it, drag an edge for width. With it off, the waveform is the XY. Recommend: the XY by default, and CYCLE EDITS as the advanced alternative. The two cannot both own a plain horizontal drag.
  4. Should the mapping be per patch? The bench's pad assignments are bench state, not preset state. Here the mapping is a lab setting and resets on reload. Recommend: a global UI preference, not a patch parameter. A patch parameter would need ids, and ACCOUNTING's J2 already settles that pads become intents (ADR-176).
  5. The presets are the bench's voicings. Superseded in round 7: the lab plays horde's coupling law, so they lock less than on the bench (question 49). They play exactly as the oracle defines them, so their Coupling is SCALPEL's law (ACCOUNTING §1.6), not horde's. The browser and the patch name say so. Re-voicing is Q B3. The lab has no undo history, so loading a preset is not a history step.

Round 3 (B294) — the ring is the Coupling × Detune XY

  1. How the ring shows the pad's position. The ring's canvas is the pad's plane: x = Detune, y = Coupling, both across the whole canvas along their own taper. A faint magenta crosshair and a hollow puck mark the value. They are drawn under the members, the arcs and the R needle, so they never cover the phase picture. Short magenta rails on the left and bottom edges repeat the value where nothing else is drawn. The corner labels are the pad's: lock, splay, detune →. Coherence moves to the top-right corner. Recommend: as built.
  2. How the ring shows modulation. Violet is the knob halo's ink. A hollow violet diamond marks where the morph and the macros carry the value, joined to the puck by a dashed line. It is hollow and diamond-shaped because the members are filled violet dots, and a filled violet dot would read as one more member. The edge rails grow a violet segment from the value to the carried value: the knob halo's arc, one per axis. A dashed violet reach box shows how far the bound macros can carry it (0 to 1 on every macro), which is B227's recommended reach box. No trail: nothing in this lab moves Coupling over time (there is no LFO), and a trail would need a wall-clock history. Recommend: as built. Add a trail only when the port has time-based sources.
  3. Relative, like the waveform, but the marker tracks the hand. Superseded in round 4 (question 25): the ring is now absolute. A grab moves nothing. A drag adds a delta, and alt makes it ¼. On the ring, a whole canvas width (or height) is the whole taper, so the crosshair moves exactly with the pointer. On the waveform, the whole taper is 420 px, because its x axis is phase and there is no marker to track. The ring is as sensitive as the pad it replaces (150 px for the whole Coupling range before, about 256 px now).
  4. What the ⇧ slot drives on the ring. The default is Cross-mod, the lab's proposal: the ring draws cross-mod (its arrows), so the gesture shows its own effect. The ring's mapping row has the waveform's selectors and roles. A blade role on the ring moves the blade whose arc is under the pointer (outside the circle). Inside the circle it moves every blade that is on. Recommend: ask the human. Stereo is the other candidate.
  5. MAIN was folded too. MAIN had its own Coupling × Detune pad in Osc Controls, and a second, mini ring in its left Visualizers cell. The pad's slot in Osc Controls is now the ring: it is still the K × Detune XY the human's MAIN wireframe asks for there, and it is now also the mini visualizer the wireframe puts beside it. The left Visualizers cell loses the duplicate ring, and the cycle view takes its whole width. Both pages share one ring mapping. Recommend: as built. The alternative, folding into the left Visualizers ring, would take the swarm's XY out of Osc Controls.
  6. Cross-mod, made visible (the human: "can we visualize the cross-mod?"). What the oracle does: each member's blade carrier phase is pushed by ½·xm times the next member's previous output sample (razor-core.js render; SPEC §6). This acts only on Sync, FM and Ring carriers, and only inside a blade window. So the lab computes what the push adds, using the bench's own three-pass static estimate (SPEC §10 calls it a display approximation; audio stays exact). It shows the result in two places, both in the meter ink, because each is a measure: (1) the ring's arrows run from member i+1 to member i, each weighted by the RMS of what that push adds to member i. A push with no effect is a dotted hairline, so "on, but doing nothing here" reads differently from "off". Each arrow bows toward the centre, so it still shows as a small loop when a locked swarm stacks two members on one point. (2) a dash-dot CONTRIBUTIONS lane on the cycle view shows what cross-mod adds to the heard wave. The heard trace now includes it. At xm 0 nothing is drawn, and the ring's legend line reads "Cross-mod off". The arrows were magenta in round 1. They move to the meter ink because they are now a measurement, not an authored value. Recommend: as built.
  7. The waveform XY's defaults are swapped (the human: "Maybe we should swap the width and position dragging after all; it's less inuitive this way"). Horizontal is now Position (it wraps), shift + horizontal is Width, and vertical is still Cut rate. The mapping stays settable, and "default" restores this order. The ring's defaults (Detune, Coupling) are independent of it.

Round 4 (B295) — the ring snaps to the click; the carpet and the voice map return

  1. The ring is absolute (the human: "please make the XY point on the phase circle snap to where the mouse clicks instead of staying put and dragging"). A click puts ↔ and ↕ (Detune and Coupling by default) at the clicked point, and the drag follows the pointer. A remapped or second parameter lands through its own taper, and an inverted second lands mirrored. This reverses round 2's "a grab moves nothing" for the ring only. The waveform XY stays relative, because its x axis is phase, not a value. Recommend: as built.
  2. Alt and ⇧ on an absolute plane. Alt is fine: from the point where alt goes down, the value moves a quarter as far as the hand. Letting go of alt does not jump the value back under the pointer. The drag goes on 1:1 from where the fine drag left it, so the marker then sits a little off the hand until the next click. ⇧ drives a third parameter (Cross-mod by default), and a 2-D plane has no place for a third axis, so the ⇧ slot stays relative: a ⇧-click lands nothing, ⇧ + horizontal moves Cross-mod by the step, and Detune holds while ⇧ is down. Recommend: as built. The other choice for alt, snapping back under the pointer on release, would undo the fine adjustment.
  3. A blade role on the absolute ring. The targeting is round 3's: the arc under the pointer, or every blade from inside the circle. The click lands the value on each target. When both blades are targeted they land on the SAME position of their taper, so their relation is not kept (the relative drag kept it). Recommend: accept it. A blade role on the ring is a remap, and the swarm roles are the default.
  4. The phase carpet (gui2's, from reference/swarmdynamics.html drawCarpet). One row per member, phase across the strip, and a trail of the monitor's last 16 frames at 0.75 per frame (gui2's fade). Each frame is a whole number of note periods of rendered audio, so a member at the note's pitch stands still, as on the ring. It never reads the clock. Each row carries that member's own blade windows as faint bands, and a dot is magenta while it is inside one, as on the ring. It reads each member's phase m.phi, the field the oracle's viz post publishes as mem.phi. The windows come from mem.c / mem.w / mem.c2 / mem.w2 via the cycle view. What changed from gui2: rows instead of columns, so phase gets the long axis of a short strip; the trail is counted in frames, not in paints; and the members are violet. In this lab magenta is the authored value (the ring's puck), and gui2 draws members in the value ink. Recommend: as built.
  5. The voice map (gui2's, from the detune lab). x = pan, y = pitch against the note, ○ target, ● actual, ★ root (the member nearest pan centre), and gui2's stepped zoom (±50 ¢ … ±10 oct). The viz post carries no pan per member, so the pan is read off the instance: the gains gl[i] / gr[i] it applies, which include Stereo. No field holds the target pitch either, so it is couple()'s law, detune·(2i/(N−1) − 1), recomputed from s.detune and d.N. The actual pitch is the heard increment m.inc·v.gr, pull included, so the gap from ○ to ● is the coupling's pull. At the default Coupling the swarm is locked: every ● sits on 0 ¢ while the ○ fan out.
  6. Where they sit. On OSC they sit side by side under the spectrum (about 130 × 78 px each). The spectrum gives up 40 px (132 → 92) and the cell's empty foot gives the rest. The ring keeps its 250 px. On MAIN they sit under the cycle view in the left Visualizers cell, whose empty foot they fill. The cycle view keeps its 150 px, and its caption is one line shorter. Recommend: always shown, not a toggle. They show what the ring's drag does: Coupling moves the carpet between lock and splay, and Detune spreads the voice map. A toggle with the spectrum would hide one of them while your hand is on the ring. The alternative is a SPECTRUM / CARPET / VOICE MAP toggle in the spectrum's slot, which gives the spectrum back its 132 px. While the ring's mapping row is open, the strip is folded away, as the spectrum shrank for it in round 3.

Round 5 (B297) — members at their phase, the beam, Cut spread under a rule

  1. AT PHASE, and "would that get too messy?" SUM draws every member over its own phase, so it shows the swarm as if it were locked. AT PHASE shifts each member's heard cycle by where it actually is against the mean field ψ (the ring's needle): δi = φi − ψ, from the viz feed's mem.phi, the same instant as the windows. Its blade windows move with it. The heard trace becomes the sum of the shifted members, the swarm as it lines up now. To stay legible at N = 9, the members are 1 px violet at low alpha. A comb of ticks on the top edge marks where each member's own cycle starts. Hovering a line lifts that member (2 px, full ink, its windows brighter, its offset named) and a drag keeps it lifted. At lock every δ is 0, so AT PHASE is SUM. Answer: not too messy at 3 or 5, busy but readable at 9 (screenshots in the trace). The comb carries the spread when the lines do not. Recommend: as built, and make AT PHASE the default view (measured 2026-09-27, the box below: it is nearer the heard wave than SUM on 62 of the 63 presets with more than one member, and the median error falls from 0.55 to 0.11. The default stays SUM here, because changing a default is the human's call).
  2. ψ at deep splay. ψ is the phase of the sum's fundamental. At R → 0 that fundamental cancels, so ψ is weakly defined and the whole picture can slide sideways. The offsets between members stay exact. Recommend: accept. The alternative reference, the root member (the voice map's ★), holds still but is not physical: it favours one member.
  3. The beam (gui2's scope, ADR-119 A2). It reads the monitor's rendered samples (left channel as the beam, right dotted), triggered on the fundamental with gui2's low-pass trigger, one period across. Its hue is gui2's mapping, mixHex(--scr-value, --scr-marker, R̃): pink while the swarm drifts, amber as it locks. R̃ is smoothed at 0.35 per stroboscope frame, as gui2 smooths it per viz frame. Placement: directly under the cycle view on OSC, the same width, so one period of what you hear sits under one cycle of what is drawn. It costs the Controls column 60 px, so the column now scrolls a little and the ADVANCED bar sits under the fold. The left column (rounds 3–4) is untouched. MAIN has no room without shrinking round 3's 150 px cycle view, so MAIN has no beam. MAIN's cycle view also keeps SUM, because it has no view pills. Recommend: as built on OSC, and ask whether MAIN wants a beam. If AT PHASE becomes the default, MAIN's cycle should follow it.
  4. What the cycle view gets wrong, measured (the box below: MEASURE, or ?misread=1). For every preset, the drawn wave is compared with the rendered output as a normalised RMS error at the best alignment, and each cause is named by removing it and re-measuring. Measured 2026-09-27: SUM's error is 0.5 or more on 41 of the 76 presets, and AT PHASE's on 6. On 62 presets the largest cause is SUM's as-if-locked drawing, even near lock: at R ≈ 0.97, offsets of ±0.03 cycle smear a sync edge or a high formant. What AT PHASE still misses is the sample-to-sample part: undrawn feedback (Feedback screech 0.78, Feedback snarl 0.76), the noise and S&H shapes (Jitter swarm 0.69), non-periodic FM (FM bell 0.59, where consecutive periods already differ by 0.89), and the cross-mod estimate (Cross-mod roar 0.49). Recommend: AT PHASE as the default; keep the beam under it. Feedback and the noise shapes stay undrawn by design. The beam is where they show.
  5. Cut spread under a rule (the human: "When the cut rule is switched to something else (like harmonic), the cut rate spread knob stops working"). The oracle's law: RazorCore.kSpread reads Cut spread only while the rule is "even". Any other rule sets each member's cut-rate ratio, and Rule depth sets how far. The lab now draws Cut spread inert under a rule: dimmed, label struck through, a dotted cap, and the reason in its tooltip. It adds Rule depth beside it on the face, and the group's caption names the rule. The mirror holds too: Rule depth is drawn inert under "even". The law is unchanged. Open for the human: should spread MEAN something under a rule? One concrete proposal: stack them. kSpread already returns two numbers, an offset (the even spread) and a multiplier (the rule's ratio), and render applies (k + offset)·ratio. Computing the offset under a rule too makes each member's cut rate (k + spread·slot)·ratiodepth: the rule's chord, with each member detuned by the spread law. No new parameter, and both knobs live. It is a change to the protected oracle, so it needs an ADR.
  6. Rule depth on the face only while a rule is on. That makes the tier audit's promotion conditional: kRuleAmt (T2) and kRuleAmt2 (T3) count as promoted to the face while their blade has a rule. Recommend: as built. A knob that appears with its reason beats one the hand has to go one level down for.

Round 6 (B299) — Rotate keeps turning; the waveform gestures on MAIN

  1. Why Rotate jumped (the human: "rotate currently isn't continuous; it jumps back to its beginning position at a rate I can't seem to control anywhere"). Measured, not guessed (trace b299, 10 s at Rotate 0.3 and 0.5 Hz). The oracle's rotation is continuous under a held note in both Rotation modes: the heard blade never jumped. The drawing did. Every 2 s of its own time the monitor built a new oracle instance and struck the note again, and a new instance starts every rotation clock at 0, so even "free-running" went back to Position. Its time was one stroboscope frame per animation frame, so the jump came every 3.67 s on a 60 Hz display and every 1.83 s on a 120 Hz one: the display's rate, which no control reaches. The drawn blade also turned at 0.55× (60 Hz) or 1.09× (120 Hz) of the heard one. At exactly 0.5 Hz the jump hid: 2 s is one whole turn. Fixed in the lab: the note is held (RE-STRIKE, under the keys, brings the 2 s re-trigger back, and then it re-triggers the audio too); a strike carries the rotation the audio would still have; with the audio on, the monitor renders exactly as much as the audio has, so the drawn window stays within one viz post (33 ms) of the heard one; and any strike names itself on the cycle view (↻). Rotation now sits beside Rotate on the face, on both blades, with blade 2's clock switch ("with ①" / "its own") beside its own Rotate. Recommend: keep "restart per note" as the default, in the lab and in horde. The jump was the monitor's, not the patch's. Restart per note makes a note's attack start where Position says, every time; 8 of the 76 bench presets rotate and all 8 rely on it (none sets free-running), so changing the default would re-voice them. Free-running is now one click on the face.
  2. What MAIN's XY pad should hold (the human's message ends at "to leave the XY pad clear for different"). MAIN's cycle views now take OSC's waveform gestures: ↔ Position (wraps), ⇧↔ Width, ↕ Cut rate, alt = fine, the window under the pointer or every blade from empty space, the same readout and outline, and the one mapping (the XY pill on MAIN opens the same row as on OSC). So the pad no longer has to hold blade control. It keeps today's Width × Cut rate for now, marked FREE TO REASSIGN. The ring (Coupling × Detune) is unchanged. Open for the human: what goes on the pad? Candidates the lab can already drive: two macros (e.g. Sweep × Motion), Cross-mod × Feedback (the swarm's sample-to-sample pair), or a second waveform-style mapping for blade 2.
  3. With the audio off, the drawing runs at the display's pace. Nothing is heard, so there is nothing to disagree with, and B271's rule stands: no wall clock reaches what is drawn. But Rotate at 0.5 Hz then turns the drawn blade at 0.27 Hz on a 60 Hz display. Recommend: accept. The alternative, pacing by the wall clock when silent, breaks the lab's reproducible stills.
  4. The audio's clock is a clock. While the audio runs, the monitor reads AudioContext.currentTime, which is the audio's own count of rendered samples, not the wall's. A stalled or glitching audio stalls the drawing with it, which is the point. A hidden tab pauses the paints but not the audio, so on return the monitor catches up at most 32 strobes a paint. Recommend: as built; say so if the "no clock" rule should be read more strictly.
  5. MAIN draws SUM. MAIN's cycle views have no view pills, so they draw SUM, and their hit-test reads SUM's windows even while OSC shows AT PHASE (a check proves they differ). If AT PHASE becomes the default (question 31), MAIN's views, their hit-test and their outline follow it by one line (cycleView).
  6. The packet's parameter list. parameters.json lists rotSync's options as [restart per note, free-running] with default 1. That is display order: 1 = restart per note, as the bench's own seg() defines it (scalpel-bench.html:1238) and as ACCOUNTING §1.8.1 already records. It is not a data bug. The same holds for rot2Follow ([with blade 1, its own], default 1 = with blade 1), which §1.8.1's list of affected rows omits.
