A filter's placement is not a layout choice — per-source and post-sum filtering are audibly different instruments. PER SOURCE gives every voice of every source its own filter (B81's SVF pair, src/svf_core.h): each note carries its own cutoff, keytrack and envelope. RACK SLOT puts one filter after the sum, inside the FX routing matrix (ADR-088): one cutoff for everything, so a new note re-sweeps the whole mix and keytracking has to pick a note. BOTH stacks them. POWER, then hold a chord (A..L, Z/X octave) or press DEMO (space), and flip placements with 1 / 2 / 3 while it plays. Drag any response curve: across = cutoff, up = resonance. Violet is what the filter is doing on its own right now; magenta is what you set; cyan is the spectrum out, over the dimmed spectrum in.

Signal path

Magenta edges are the routing you set (width = gain); cyan dots are live level; the violet count under each pre-mix box is how many per-voice instances are running right now. Parts not in the current placement are drawn dashed and faint rather than removed.

Pre-mix · per source

Settings are shared, state is per source. A source assigned to A runs its OWN instance of A, with A's settings — so the matrix downstream still receives three separate sources. For a linear filter that is exactly equal to filtering the sum (see the questions card, Q3). The sub defaults to OFF: a sub's job is to stay clean.

Rack · matrix

The FX page's well, reduced to the one slot under test. FILT feeds the rack filter (coeff[src][slot]); DRY goes around the whole rack (the B50 dry path). Drag or scroll a cell; double-click toggles 0 / 1. With the rack filter out of the placement, every source reaches OUT directly.

Sources

The lab's own stand-ins — polyBLEP saw stacks and a sine — not the engines. They exist so the three sources play different pitches (SWARM 2 an octave up, the SUB an octave down), which is what makes "keytrack from which note?" a real question.

Filter envelope

One envelope shape (B81: a DEDICATED filter env). Per voice, every note runs its own copy (violet dots). The rack has ONE copy (violet ring), re-triggered by every note-on and released only when all keys are up — the classic mono-filter behaviour, and the audible heart of the placement difference.

What the placements answer — and what is left for the human

Q1 · WHERE DOES THE FILTER SIT?Hear DEMO in each placement. Per source: each stab plucks on its own envelope while the held bass keeps its own, untouched; chords voice evenly because every note's cutoff follows that note. Rack: one envelope, re-fired by every stab, so the held bass wahs along with the melody — a pumping, glued, mono-synth character. Both: the per-voice SVF does the tone, the rack slot does the motion (the plan of record — B81 per voice, B50 folds the E1 bank into the rack). The lab's lean is BOTH, but the choice of default placement for a new patch is yours.
Q2 · DOES THE SUB GET ITS OWN FILTER?The lab says no third filter. The pair already lets SWARM 1 and SWARM 2 be shaped independently (A and B), and the sub defaults to OFF before the mix and can take the DRY cell around the rack — the "sub stays clean" patch is two clicks (SUB AROUND). If a sub needs shaping it can share A or B. A dedicated third per-voice filter would be a new parameter block to earn with a named patch the pair cannot express.
Q3 · SHARED FILTER vs PER-SOURCE MATRIXB81's pair (sources share A) collides with B23 increment 3 (the matrix wants each source separately): if A filters SWARM 1 + SWARM 2 summed, no per-source signal is left for the matrix. The lab's resolution: share the settings, instance the state per source — exact for a linear filter (Σ filtered = filtered Σ), and 2→6 SVFs per voice against B81's measured 0.21 % of a core for 2. It stops being exact the day a drive stage enters the filter. Ruling owed.
Q4 · KEYTRACK — FROM WHICH NOTE?Per voice the answer is local: each voice tracks its own note, and the only choice is PLAYED KEY (a transposed source shares its key's cutoff) or SOURCE PITCH (the sub's cutoff sits an octave below, so brightness is constant per source). On the rack there is one cutoff, so the note is a policy: LAST (mono-synth convention), LOWEST (follows the bass, steady under chords) or HIGHEST (follows the melody). All three hold their value when keys lift, so the cutoff never jumps on release.
Q5 · SERIAL / PARALLELThe lab applies it per source, to sources assigned A+B only: SERIAL = B(A(x)), PARALLEL = ½(A(x) + B(x)). Serum's global serial also runs A-only sources through B; that is a different instrument (B stops being independently reachable). Which does horde want?
Q6 · WHAT THE CONTROLS LOOK LIKEThe curve is the control: drag = cutoff × resonance, wheel = resonance, double-click = reset; the magenta handle rides the resonance peak. The filter's state is visible as violet — a fan of curves, one per sounding voice, per voice; a single curve on the rack; the swarm bank's resonators as violet bars whose height is their energy. The spectrum in (dim) and out (cyan) sit under the curve so what it does to THIS sound is read, not inferred.
