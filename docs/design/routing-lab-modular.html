Layout findings (edit as they accrue)

1. The upper-triangular shape reads instantly once the blank cells are actually blank — filling below-diagonal cells with a hatch or a zero would make the eye hunt for the boundary; a flat dark blank cell makes the staircase self-evident in about one glance.
2. The matrix answers "what", the graph answers "so what" — nine non-zero cells in a table is a diffing exercise; the same nine cells as cables make the split-band-vs-serial shape obvious without reading a single number. Neither view alone is enough at this pool size (10 rows × 8 columns after adding OSC1/OSC2).
3. Normalling wants to be near-invisible until it matters — a dashed MST cell plus a dashed cable is enough; anything louder (a warning icon, a colour swap) would make the common "nothing wired yet" case look like an error state, when it is actually the safe default.
4. Open question: does per-cell colour-by-sender help or just add noise? — this lab colours cables by sender rank so parallel paths from the same source stay visually grouped; at 10 senders the palette runs out of easily-distinguished hues around the 7th–8th row (VRB, DRV2 sit close in hue to CHO, DLY). A future pass may want colour reserved for corner-ownership instead (fx-page-lab's corner strip) and something else — dash pattern, curve height — for sender identity.
5. The OSC1/OSC2 preview rows are legible ONLY because they're visually quarantined — same table, amber accent, a dashed row background and the note block above it. Without that separation a reader has no way to know two of the ten rows describe a feature that doesn't exist in the audio path yet; QM-3 itself never mentions OSC1/OSC2, so nothing in the matrix shape signals "preview" on its own.
6. slotInit earned its space but not its prominence — a per-column constant that can drive a module with nothing connected is a real, if rare, case (routing_core.h's `in_i` term); showing it as a thin editable strip above the header row rather than a fifth matrix dimension kept it from competing with the sends, which are what QM-3 actually authors.
