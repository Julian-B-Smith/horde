Sluice's title: hue walk, no icon

Every mark here runs the mark's own engine from sluice-mark-dark.html, untouched. The pixel versions render the tubes at eight times the grid, read each frame back and decide every pixel from what falls inside it, so all twelve tiles move in step with their density's one render.

Crossing gap in the pixel marks

The smooth mark cuts a thin gap where one tube passes over another. On the pixel grid that gap is thinner than a pixel, so it flips pixels on and off as the tubes move. Both versions below draw the same frame of the same route, in the hue walk at 4 px stems. Every other pixel mark on this page now draws without the gap, and the button brings it back for comparison. The smooth marks keep it.

Shifting colour

The parked word is always one colour, and each slide carries it to a new one. Every point of a tube turns from the old colour to the new as it runs its route: still on its letter it is the old colour, out on the route an in-between one, back home the new. So mid-slide each tube carries the gradient along its length, and the word parks in one colour again. In-betweens are interpolated in OKLCH, so they pass through the neighbouring hues instead of greying out.

Colour options in the slot

Today's slot, 4 px coverage, cropped from the same real frame. Click one to put it on the three screens above. The two depth options colour each pixel by how near the tube is: the tube is a 3D path seen head-on, so the S twists, the U dips behind its arms and the E coils, and a slide carries each tube out to a far plane and back through a near one. Each pixel takes the mean depth of the tube inside it, in four steps, which stays inside the GBC four-colour rule.

Pixel distribution

Densities are chosen so the tube's stem is a whole number of pixels: 3, 4 and 6. The exported file samples one point per pixel at 16 rows, which gives 4.48 px stems that alternate between 4 and 5, plus stray pixels on every curve. That's most of the mess in the letterforms.
