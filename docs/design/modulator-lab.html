horde modulator lab

Bench for the modulator editor (ROADMAP B16) — the weakest surface in the instrument, because the LFOs have three parameters and the envelope is a plain ADSR while everything else here has had a lab. Three claims, each measurable on this page. Reverse-saw is not a sixth shape: it is skew = 0 on the ramp axis, and the same warp that turns triangle into saw-up and saw-down turns square into a pulse — so shape is a continuous axis and can itself be a modulation destination, which a dropdown can never be. S&H is a sampler, not a shape, and the thing the two kinds differ in is the CLOCK: global is one clock and one value broadcast to every attached mod (measured: value correlation 1.000, timing lock 1.00), kuro samples on each mod's bound rotor voice wrapping — measured value correlation −0.23 with timing lock riding |K| from 0.04 to 0.83, because coupling locks when they sample and never what. Polarity belongs to the route, not the source: every route carries its own, and the lab measures the fraction a rectified destination throws away, so "half-inert" is a number instead of a surprise. Envelopes show the distribution across voices that scatter produces, not one curve. Double-click any control to reset it. Keys A..;, Z/X octave, space drone.

Modulator scope · 3 s window · ticks below each trace are S&H sample instants

value corr(A,B) over 3 s: —  ·  timing lock(A,B): —  ·  rotor R: —  ·  A rate: —  ·  B rate: —
Two meters, because the two S&H kinds differ on two axes and one number cannot show it. value corr is Pearson over the mods' outputs; timing lock is the order parameter of the A→B sampling offset measured in units of A's own period — 1 = a constant offset, 0 = an offset that walks. Measured offline on this core (seed 1234, rotor 6 Hz, 60 000 control ticks, A bound to K1, B to K2):

Read it as: global hands every attached mod the same number, so both axes pin to 1 and nothing independent is left. kuro leaves the values uncorrelated at every setting and puts the whole effect of the coupling on the timing. Splay locks too — K = −1 reads 0.75, because a repelled configuration holds a constant offset just as a synchronised one does; what separates them is the rotor's R, not this meter. And with both mods off there are no sample instants and the meter reads nothing at all: a lock number with the samplers switched off would be the meter measuring itself.

Rotor · the LFOs' clock source

K1..K4 are rotor voices, not independent LFOs — that is the HYPERSAW-specific thing a conventional editor has no way to say. Positive K pulls them together (lock), 0 lets detune drift them apart, negative K pushes them apart (splay). Watch the S&H tick raster on the scope, not the dots: coupling is legible there as the ticks aligning or fanning.

Compact rotor, deliberately. Mean-field only — no ring/two-cluster topology, no link, and negative K is plain repulsion rather than the rank-lattice splay law. The reference rotor is mod-lab.html's KuroSwarm; this one exists to give the S&H clocks real coupled timing, and any fold takes the reference, not this.

LFO A

skew 0 = reverse saw (down-ramp), 0.5 = triangle, 1 = saw-up; on the pulse family the same knob is pulse width. That is the whole reverse-saw request, and it arrives as an axis rather than a sixth enum entry — which is what makes it modulatable (route something to LFO B shape and hear it).

LFO B

LFO B's shape is a routable destination, so a slow modulator can walk it from sine through triangle into pulse. Only a continuous shape axis makes that expressible.

Global S&H clock · the shared one

last sampled value: —  ·  attached mods: 0
One clock, one draw, broadcast. Every mod in global mode outputs the identical value — that is the request as stated ("one sampled value across every attached mod"), and the cost is that N mods in this kind carry exactly one independent stream between them however many are attached. kuro is the opposite trade: N independent streams, timing coupled by the swarm. Neither subsumes the other — that is the argument for shipping both rather than one with a "spread" knob, and the two meters above are the evidence, since a single correlation number cannot tell them apart.

Envelope · DAHDSR with per-segment curve

The fan is the point: the VST already scatters envelopes per voice, so the honest display of an envelope here is the distribution it produces across voices, not one curve. Seven seeded draws from the same scatter law, redrawn when the seed changes — the picture and the sound come from the same law, but not from the same draw (the notes currently sounding drew earlier).

Two time grammars, unreconciled — a question for the fold. This envelope is staged seconds (a gate has no total duration). shape-lab-mod.html's editor is normalised t with a separate duration. Both are right for their own object and this lab does not pretend they unify; it reuses that lab's segCurve exponent unchanged so at least the curve grammar cannot fork. Which one a preset stores is unruled.

Target · something to hear it on

Three polyBLEP saws per voice into two one-poles and a tanh drive — deliberately the dullest target that can still show every destination. drive is RECTIFIED (it takes the positive half only, the way Kboost does), which is what makes the per-route polarity claim measurable rather than rhetorical.

preset: B26 patch builds the two pieces B16 owes the depth-of-depth item — a tempo-synced down-ramp saw on the cutoff. The second-order half of that request (a high R fading the routing's grip in and out) is B26's own scope and is not built here.

Determinism

not run
Two runs at the same seed must hash identically, and a run at seed+1 must NOT — the second half is the control, without which a hash checker that always returned a constant would pass. Changing the seed rebuilds every stream from scratch (the S&H streams, the envelope's per-voice scatter draws), which is what makes the claim testable at all; a stream that survived a reseed would make the seed decorative.

Ownership tier · the question, made concrete

The request was "which mods have a baked-in tier vs a modifiable one", and the human flagged uncertainty about the framing itself — so this panel makes the question concrete rather than answering it. Click a chip and watch what actually changes. Three readings, and the phrase does not pick one:
(i) tier = editability. A baked mod's identity is fixed: K1's rate is the rotor's detune spread, so "make K1 modifiable" is not a permission to grant — there is no knob to unlock. Try it; the lab refuses and says why. That refusal is the finding: editability is not a per-mod flag, it is a property of where the mod's identity comes from.
(ii) tier = preset ownership. Does the mod's state serialize? Toggle LFO A to baked and watch it leave the JSON below. This reading is implementable today and costs one field.
(iii) tier = precedence. "Tier" also reads as priority when two things write one destination — a system-wide route outranking a corner-owned one. That is the morph scope vocabulary, already ruled and already built elsewhere; if this is what was meant, B16 owes nothing and the request is already served. NOT implemented here, deliberately: building it would answer a question nobody has asked yet.
