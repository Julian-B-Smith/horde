VIEW
Every FX module horde hosts, drawn in gui2's token set and held to one rule — ADR-169's module macro tiers as the human put it: "distill its essential controls to four knobs, even while the rest of the parameters are accessible". Each card is a FACE: four role slots (Amount · Tone · Motion · Regen), each one knob that may drive several internals. EXPAND opens every control beside it, and every row a face knob drives wears that knob's mark. The reverb is the ruled worked example (ADR-177 §4); MAW and Sluice are hosted — horde designs how it presents them, not how they work; comb, echo, drive, filter are the rack's own modules, expanded with proposed controls. Sluice's face is drawn both ways for the open ruling ADR-169 A1. Pictures are computed from the parameters, not heard: this lab answers what a module shows. The face

Four slots keyed by the fixed role enum Amount · Tone · Motion · Regen (SPEC-MODULE-MACROS §1). The module PRESET supplies each slot's label and bindings — one knob → N internals, lo…hi spans (ADR-169 A2) — never values. A role the preset does not implement is drawn inert and labelled unbound, never hidden. Global-tier slots are host parameters at ids 300 + 8·host + role (ADR-169 A1 ruling 4).

The expanded view

Every control the module has. The face never hides, it summarises: a row the face drives carries the slot's mark. Ghost rows are present but not in force in the current mode (gui2:764) — dimmed, never removed. Dashed rows are proposed: controls the rack does not have today.

What the lab surfaced — for the human

  1. The role enum fits five modules; Drive and Sluice strain it from opposite sides. Reverb, MAW, comb, echo and filter each fill all four roles honestly. Drive cannot: a one-stage drive has no loop, so Regen is drawn unbound, and the knob a player would want there (Output, or Bias) has no role. Sluice will not: it declines to author roles at all (D-052). Both are a label the vocabulary cannot hold.
  2. ADR-169 A1, made concrete (not ruled). Keyed by role, Sluice's shipped presets put nothing on the face (they author no roles); with a horde-authored role table two slots bind and shifted glass's defining macro — shift — is not on the face at all. Keyed by order, all four bind under Sluice's own labels, but an automation lane on slot 1 means shift in shifted glass and allpass unison in the next preset. L0028 (canonical here) asks for both halves: address a ROLE, and LABEL what it resolved to — each rule keeps one half.
  3. A face knob can be bound to a parameter the current topology ignores. MAW's Feedback (Regen) only acts in the feedback route. The card keeps it turnable and marks it IDLE rather than letting it turn silently — worth a line in SPEC-MODULE-MACROS if the human agrees.
  4. Drive's expanded view is a one-stage subset of a MAW stage (curve, drive, bias, tone, mix; its curves are drawn by MAW's own core). If Drive and MAW should converge, the reduction is Drive = a MAW preset with stages 2–3 off — one module fewer at 1.0 (ADR-172: one instance per type).
  5. Filter's face inverts today's knob. The rack's Filter amount turns UP to CLOSE (fx_rack.h:671); a Cutoff knob that closes as it turns up is a trap, so the face turns up to open. A saved patch would migrate a → 1 − a. Proposed, not assumed.
