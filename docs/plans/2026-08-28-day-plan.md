## 2 · B73/B68 increment A — the standard Delay module (design final)

**Why this shape.** The human's complaint — *"Echo and room need feedback,
and the feedback from their lab didn't really work very well"* — is DIAGNOSED
(read `src/time_core.h:120-190` before touching anything):

1. **The `/N` feedback norm crushes loop gain.** `fbSig = wetRaw / n` is the
   worst-case-correlation law; with N≈8 decorrelated taps the audible loop
   gain at regen 0.9 is ≈0.32. Repeats die in 2–3 generations and the
   edge-of-oscillation zone — the musical heart of a delay — is unreachable.
2. **Mean-collapse smears.** All taps average into ONE write head, so every
   generation re-smears through the whole tap swarm: wash, not repeats.
3. **`tanh` at unity in-loop + always-in-loop damping** duck and dull every
   pass.

Room's FDN (negated Householder) is structurally correct; its problem is only
that `regen` maps to decay time perceptually cramped (the human's own tail
measurements: −102 dB at 0.3 vs −34.8 dB at 0.97 — the action all lives above
0.9). So: the fix is NOT re-plumbing the lab law (B73's roadmap entry is an
explicit license to diverge). Build the **standard delay the human described
for B68** with textbook feedback — it is the A/B baseline they asked for and
almost certainly the keeper — then fix Echo/Room against it (increments B/C).

**Module: `Delay` (slot type 9) in a new `src/delay_core.h`** — framework-free
per doctrine, spec-in-comments since no lab exists for it (record THAT in the
ADR: this is the first engine-side module without an HTML reference; its
oracle IS the spec — impulse-response numbers below are the acceptance
contract, specs/ACCEPTANCE.md gains a section).

State: two delay lines L/R (`kDBuf = 1<<17` doubles, preallocated like ebuf),
one write head each, damped one-pole LP + DC-block per channel in the loop.
No RNG anywhere (no unseeded-RNG blocker by construction).

Per-sample (channel pair, stereo in/out — note the rack is currently mono
per-slot; if `FxRack` slots process mono, v1 collapses to mono in / equal-
power stereo out like Echo does, and ping-pong becomes cross-feed of two
internal lines; check `fx_rack.h` FIRST and follow its seam):

```
readL = lerp(bufL, wL - dL);  readR = lerp(bufR, wR - dR)
fbL   = readL*(1-x) + readR*x          // x = crossfeed 0..1 (ping-pong at 1)
fbR   = readR*(1-x) + readL*x
loopL = dc(lp(fbL));  loopR = dc(lp(fbR))       // damping INSIDE the loop
bufL[wL] = in + loopL*fb;  bufR[wR] = inR + loopR*fb
out   = read (pre-feedback tap), mixed by the rack's existing dry/wet
```

- `fb` range **0..1.08**, soft-limited: `if (|loop*fb| > 1.2) soft = tanh` —
  saturation engages ONLY above threshold, so clean repeats stay clean and
  >1.0 self-oscillates into a controlled ceiling instead of exploding. This
  is the audible fix for lab-cause #3.
- Delay times: `timeL` in ms (log control 1..2000) **or synced** — reuse the
  ADR-103/ id-23 grid-step machinery (`snapGridStep`) for note fractions;
  param `sync` stepped 0/1, `timeSyncL` in beats. Host tempo already reaches
  the shell (the time engines use it — follow their transport read).
  `offsetR` as a ratio (0.5..2.0, default 1.0) per the human's "L/R offsets".
- Time changes SLEW like tSm does (`+= (target-t)*0.0015` per sample — tape
  chirp, no clicks); document that zipper-free retime is a feature, not
  smearing.
- Params (8-block at 232.. next free rack block; check ADR-131's arithmetic —
  four blocks of 8 end at 231, so Delay claims 232-239): time, sync,
  timeSync, offsetR, feedback, crossfeed, damp, (mix lives in the rack's
  existing per-slot mix 133-136). That is 7 — one spare for the in-line HP
  the human requested ("in-line filter"): `loopHp` 20..500 Hz one-pole.
- Mode enum (std / M-S): DEFER. The human listed "std/M-S/ping-pong";
  crossfeed=1 IS ping-pong; M-S needs a stereo rack seam — name it in the
  ADR as deferred-with-reason rather than silently dropping it.

**Oracle: `tools/delay_check.cpp`** (goes into ./verify — remember the
human gate on editing ./verify's gate list: ASK before wiring it in, land
the binary regardless). Impulse-response invariants, all deterministic:
- Repeat spacing: impulse at t=0, fb=0.5, time=100ms → peaks at 100/200/300ms
  ±1 sample after slew settle; peak ratio per generation = fb×(damp gain at
  the LP cutoff) within 1e-3.
- fb=0 → exactly one repeat then silence (< 1e-9 after 2×time).
- fb=1.05 → bounded forever (max |sample| < 1.3 over 30 s) — the soft-limit
  law.
- crossfeed=1 → impulse alternates channels per generation (ping-pong proof).
- Sync: at 120 BPM, timeSync=0.25 beat → 125 ms spacing exactly.
- NaN watchdog heal (copy time_core's pattern + its heal test).
- **Parity-safe superset:** slot type default remains 0/off; parity_check
  156/156 byte-identical with no Delay slot selected.

**GUI:** the rack page already generates per-slot controls from the

## 3 · B73 increments B/C — Echo/Room fixes (design done; build after A)

**B — Echo:** replace the mean-collapse feedback with **center-tap
regeneration**: `fbSig = (tap at swarm-center delay)` — the same centerIdx
concept the swarm engines already own — with **no /N** (single-tap loop gain
= regen×dampGain < 1, stable by the same argument as the standard delay),
keep DC-block + damp placement. The swarm taps then DECORATE each discrete
generation instead of dissolving it. One-line ADR framing: "the swarm is the
diffusion; the feedback is the meter." Oracle: extend time_check with an
impulse test — post-fix, an impulse at regen 0.7 must show a periodic peak
train at the center delay (was: monotone wash; capture the before numbers in
the trace as the measured justification).

**C — Room:** keep the FDN untouched; re-map the knob to **RT60 seconds**
(log 0.15..25 s): `g = pow(10, -3 * meanDelaySamples / (RT60 * sr))` computed
at control tick. The knob becomes perceptually linear-ish; the FDN math is
unchanged so time_check parity for regen-expressed scenarios must either pin
the OLD mapping via raw-g test entry points or re-measure — **do not weaken
the gate silently; if golden numbers change, that is a re-measurement with
the human informed (charter rule).**

## 4 · B72 — the morph-transition question (FRAME, do not build)

Put to the human, once, with this recommendation:

> B72 needs one ruling before routes can join the morph. When corners share a
> link (same source→dest), its DEPTH interpolates like any parameter — that
> part is settled by the canonical key. The open case is a link present in
> SOME corners only. Three options:
> **(a) depth-fades** — absent corners contribute depth 0; the link always
> exists, its strength follows the field (matches the weighted-ADOPT rule you
> ratified for silent-osc params; no clicks by construction).
> **(b) ARGMAX flip** — the link exists only when a corner that has it wins
> the Gumbel draw (ADR-125's topology law; treats a route as structure).
> **(c) exempt** — routes ignore the morph until both… all corners define
> them (safest, least musical).
> **Recommendation: (a)**, on the argument that a route's EXISTENCE is not
> audible — only its depth is — so it is intensity, not topology, and
> intensity interpolates. ARGMAX stays for the SOURCE: if two corners route
> the same dest from different sources, source flips at the boundary (a
> source IS topology). One composition rule: under B70, the depth being
> interpolated is the BASE depth; depth-modulation applies on top.

If ratified, the build is: per-corner depth vector keyed by (src,dest) in the
morph chunk (schema note), morphStep writes depths through `modSetDepth`
under a guard mirroring `morphFromField`, exempt flag per link. Not today
unless the ruling arrives early and item 2 is done.
